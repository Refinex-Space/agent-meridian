# meridian-control-plane

控制面应用（Spring MVC + 虚拟线程，schema `cp`）：T14a 起有租户、租户设置、项目、成员、角色绑定、API Key 的管理 API（`/admin/v1/`，只接受 OIDC 令牌），给 runtime 与 knowledge 的内部接口（API Key 校验、租户配额、控制台用户的项目权限），T14b 起签发服务 JWT（`/oauth2/token`、`/oauth2/jwks`），T15a 起有凭据库（信封加密）、供应商账号、模型目录与价格表（ADR-0045），T15b 起有智能体与版本、环境、技能、MCP 服务、租户与项目策略的管理、给 runtime 的配置分发与公开接口 `GET /v1/agents`（ADR-0047），T16 起有用量账本、审计日志、四级预算与对账、用量报表与公开接口 `GET /v1/usage`（ADR-0048），T17a 起有项目的 Webhook 配置与给 runtime 的订阅接口（ADR-0049），T19b 起有当前用户与权限、按邮箱邀请成员、项目预算消耗、用量明细与导出、供应商连通性测试、MCP 连接状态、Webhook 密钥轮换（ADR-0053）。不执行智能体，不读写 `rt`、`kb`。

## 不变量

- 用例自己绑定 `PlatformContext`（`PlatformContexts.call(Scopes.tenant(...), ...)`）与事务（`TransactionTemplate`）；处理器只做 `@RequiresPermission` 声明与 decode → call → map，`/admin/` 下漏掉注解的处理器由拦截器拒绝（ADR-0042）。
- 角色判断只经 `AccessContext`（同一套 `RoleMatrix`）：授予、撤销所有者与移除所有者成员另需 `OWNER_ROLE_MANAGE`，`RoleBindingRepository.lockOwners` 锁住所有者再计数，租户至少保留一位。
- 已删除的租户中没有任何角色（`DatabaseGrantSource` 先查租户是否存在），删除之后的管理操作都是 403。
- Webhook 签名密钥与 API Key 一样只出现在创建响应（与它的幂等重放）中，另外只在给 runtime 的内部接口中出现；审计与日志都没有。
- API Key 明文只出现在创建响应（与它的幂等重放）中；库、审计、日志只有 SHA-256 与 `mk_live_` 之后的前 8 位，幂等记录中是租户数据密钥加密的密文（ADR-0054）。作用域与限流创建后不能改。
- Pub/Sub（`key.revoked`、`config.invalidate`）在事务提交后发布，失败只记 WARN；只改保留天数不发布配额变更。
- 内部接口的处理器首行 `ServiceCredentialFilter.require(request, 调用方…)`：本服务的接口只接受 `runtime`、`knowledge`（凭据解析与模型目录只接受 `runtime`）。令牌端点与 JWKS 不在 `/internal/` 下，令牌端点自己认证客户端（未登记的服务名也比较一次摘要）。
- 凭据明文只在 `SecretResolution` 的返回值与 `secrets:resolve` 的响应（`no-store`）中出现：管理响应、审计、日志、幂等记录都没有（写入与轮换的幂等指纹只含 `value` 的租户密钥 HMAC，ADR-0054）；解析在审计事务提交之后才交出明文。数据密钥在独立事务（`REQUIRES_NEW`）中生成并提交后才进缓存，业务事务之前取得。
- `secrets.key-encryption` 没有默认值（`local` 或 `vault`），`dev` 与测试是 `local`；换了主密钥（文件或服务）后旧的数据密钥解不开（`secret.encryption_unavailable`）。
- 删除被引用的资源抛 `common.error.ReferencedException`（409，problem+json 带 `references`）；外键是并发删除的兜底。jsonb 中的引用（智能体规格）没有外键：发布时把引用写进 `agent_version_refs`，被引用的 MCP 服务、技能共享锁读取、模型排他锁读取，删除方锁行后再查引用。
- 已发布的智能体版本不可变：仓储的写操作都带 `status = 'draft'` 条件；发布把 MCP 服务配置与技能名写进规格快照，MCP 服务的修改在下一次发布时才生效。智能体、环境、技能是软删除，已发布版本、修订、技能版本仍可经内部接口解析（运行中的会话）。端点在写入时解析 DNS 校验：测试只用回环地址（`application-test.yml` 放行回环）。
- control-plane 调用其他服务（knowledge）的服务 JWT 由 `ServiceTokenIssuer.issueOwn` 在进程内签发（`sub` 为 control-plane，`config.ServiceTokenConfiguration` 的 `ServiceCredentialProvider`），不经令牌端点。
- 服务客户端在 `meridian.control-plane.service-tokens.clients` 登记（密钥至少 16 个字符，启动时只留 SHA-256），每个客户端只能换取列出的目标服务；签名密钥目录 `service-tokens.key-directory` 必填，多副本必须共用（生产改密钥管理系统，D58）。

- 账本与审计只追加：`usage_records`、`audit_logs` 的写入只有两个消费者，应用角色在表与分区上只有 `INSERT`、`SELECT`；分区只经 `cp.ensure_ledger_partitions`、`cp.drop_expired_ledger_partitions`（迁移角色拥有）。入账与预算汇总在同一事务，只有真正插入的记录才累加。
- 预算以 token 计；没有设置的级别硬阈值为 0（新租户默认零预算），每级可以有默认值（`scope_id` 为空）。改预算后 Redis 限额在提交后写入，失败由 5 分钟一次的全量重写兜底；Redis 键只经 `common.budget.BudgetKeys`。

## 易错点

- `TenantScopedRepository` 的子类不能手动设置名为 `tenant_id`、`project_id` 的参数（`ScopedStatement.param` 拒绝）：租户级仓储里要按项目过滤时换个参数名（`:project_filter`、`:binding_project_id`）。
- JSON 消息用 record 序列化（字段顺序固定），不要用 `Map.of`：顺序不定，订阅方或测试按原文比较会失败。
- 测试身份（`support.ControlPlaneTestBase`）：控制台用户是 Keycloak 中按名字动态创建的用户（`token(名字)`，`platform` 在平台管理员组），`application-test.yml` 把用户标识设为 `preferred_username`；要换声明配置的测试类用自己的 `@DynamicPropertySource` 覆盖（`OidcSubjectClaimIT`），基类不能注册这些属性，否则子类覆盖不了。内部接口用 `serviceToken()`（经本应用的令牌端点换取）；签名密钥目录在同一 JVM 的全部上下文间共用。
- 测试跑在 Testcontainers 的共享库上，用 `TenantFixture.create` 新建租户隔离；Redis 订阅在监听容器中异步生效，断言前先等约 200 毫秒。
- `@Bean` 之外的组件用 `@Service`/`@Repository` 注解扫描；`application-test.yml` 在 `src/test/resources`（不放 `src/main`，D54 Q-L6）。
- 管理 API 规范里 `format: uri` 加 `maxLength` 会在生成的 `URI` 字段上放 `@Size`，校验时 500：端点字段写成普通字符串（T15a 修了租户设置的 `base_url`）。
- 契约覆盖（R2）：`AdminClient` 每次校验都记进 `ContractCoverage`，最后运行的 `ContractCoverageIT` 核对管理 API 107 个、公开 3 个、内部 15 个操作；新增操作要有测试经 `AdminClient` 调用，角色矩阵表另要有一行。`withAgentConfig` 另有项目级的 `mcp_project_secret`（项目开发者登记 MCP 用它）。
- `TenantFixture` 另建凭据、供应商账号、价格表与模型（`secret`、`provider`、`model` 有引用方，`spare_*` 没有），角色矩阵的写操作每行都新建一份；`withAgentConfig` 再建 MCP 服务（探测基类的进程内 `MCP`，令牌 `MCP_TOKEN`）、环境、技能与已发布一版、草稿一版的智能体，角色矩阵只在路径或请求体引用它们时才建。知识库由基类的 `StubKnowledge`（`KNOWLEDGE.register(租户, 项目)`）模拟 knowledge 的内部接口，`down(true)` 模拟不可用。
- `TenantFixture` 另建一条不限的租户级预算 `{budget}`（角色矩阵的预算行）；要验证零预算的测试直接经平台管理员建租户。用量、审计的测试共用库，按自己的租户过滤；对账会处理全部租户的计数。
- 报表的 `group_by` 是逗号分隔的字符串（规范只约束格式，取值由 `UsageReports` 校验）：契约校验库不支持 3.1 的数组查询参数。
- control-plane 需要对象存储（技能文件）：测试基类注册 MinIO，`dev` profile 用 compose 的 MinIO。

## 对外接口

- 管理 API（控制台，T21 起）：`meridian-admin-v1.yaml`，只接受 OIDC 令牌（`security.oidc.OidcTokenVerifier`）。
- 配置分发（T15b，只接受 runtime）：`POST /internal/v1/agent-versions/{id}:resolve`、`POST /internal/v1/agents/{id}:resolve`（快照与技能内容）、`GET /internal/v1/environments/{id}[?revision=]`、`GET /internal/v1/skills/{id}/versions/{v}`、`GET|POST /internal/v1/projects/{id}/permission-rules`、`GET /internal/v1/tenants/{id}/settings`；解析不按租户过滤，runtime 校验归属。公开 `GET /v1/agents`（`sessions:read`）。
- 内部接口：`POST /internal/v1/api-keys:verify`（按哈希，404 表示无效）、`GET /internal/v1/tenants/{tenant_id}/quotas`（含 `event_retention_days`，runtime 的事件保留清理读它）、`GET /internal/v1/projects/{project_id}/webhooks`、`POST /internal/v1/project-access:resolve`（`{subject, project_id}` → 租户与作用域，项目不存在 404）、`POST /internal/v1/secrets:resolve` 与 `GET /internal/v1/models/{model_id}`（只接受 runtime，ADR-0045）；调用方经 `security.servicejwt.ServiceRestClients`。服务 JWT：`POST /oauth2/token`（HTTP Basic，`grant_type=client_credentials&audience=…`）、`GET /oauth2/jwks`。
- Pub/Sub：`key.revoked`（Key ID）、`config.invalidate`（`{"type":"tenant_quota","tenant_id":…}`；T15a 起另有 `secret`、`provider_account`、`model`、`price_book`，T15b 起另有 `agent`、`environment`、`skill`、`mcp_server`、`permission_policy`、`tenant_settings`，带 `id`）。审计另有 `secret.*`（`secret.resolved` 的操作者是 `service`）、`provider_account.*`、`model.*`、`price_book.*`。审计：outbox `audit`，标准字段 `{action, occurred_at, tenant_id, project_id, actor, resource_type, resource_id, session_id, details}`（`actor` 是 `common.audit.AuditActor`），其余顶层字段并入 `details`。用量与审计的消息格式以 `meridian-test-support` 的 `outbox` 样本为准，runtime 的契约测试与本模块的消费者测试共用。
- 管理接口（T16）：预算 `/budgets`（增删改查）、告警 `/budget-alerts`、租户与项目用量报表 `/usage`、审计 `/audit-logs`；公开 `GET /v1/usage`（`sessions:read`）。给 T17b：`session.usage` 与账本一致应读同一口径（输入加输出，按 `kind` 区分）。knowledge 的存储量是 `knowledge_storage_gb_days`（属性带 `knowledge_base_id`、`day`、`file_bytes`、`index_bytes`，没有单价，ADR-0051）。给 T25b：报表的维度与默认时间范围见 `UsageReports`。
- 资源引用凭据时用 `SecretService.requireUsable(租户, 项目, 凭据, 字段)`（项目级资源可以引用租户级与本项目的凭据；MCP 请求头引用租户级凭据另需 `SECRET_WRITE`，ADR-0054），新的引用方加进 `SecretReferenceRepository`。knowledge 的地址是 `meridian.control-plane.knowledge.url`，客户端 `knowledge` 在 `service-tokens.clients` 登记（目标 control-plane、runtime）；T19 起客户端 `runtime` 的目标另有 `knowledge`（知识检索）。给 T22、T23：控制台按 `agent-spec.schema.json` 校验表单，服务端字段错误是 `spec.` 加点号路径。
