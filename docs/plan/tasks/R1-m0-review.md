## 执行要求

开工前完整阅读 `docs/plan/protocol.md` 并严格遵守，开工检查、范围与决策分级、质量门禁、验收记录、收尾与报告格式都以它为准。最重要的几条：

- 先读后写；AgentScope 只以 2.0.4 为准（读法见 `docs/plan/references.md`）。
- 只做本任务范围内的事；补充型决策自己定（影响多个模块或难以回退的才写 ADR），变更型决策写 ADR 提议后停止受影响部分。
- 不删改测试和验收项；只有亲自验证通过的验收项才能标 `passing`。
- 每完成一个检查项就更新 `PLAN.md` 检查点并提交；上下文会被自动压缩，不要提前停下。
- 不推送，不打印凭据。

## 背景与目标

M0 的目的，是在投入 M1 的大量开发之前，证明架构中依赖运行时行为的假设成立。本任务是 M0 的阶段门：补完剩下的两项测量（P7 容量、P11 内存），用独立视角评审 M0 的全部代码与架构的一致性，修正确认的问题，并给出"是否进入 M1"的结论。

评审由你主持，但要借助独立的审查子代理获得不受你自己思路影响的意见。这是本计划中少数适合并行使用子代理的场景：几个审查维度相互独立，各自需要读大量代码。

## 范围

### 要做

- P7 容量测量、P11 内存测量。
- 四个维度的独立代码审查，修正确认的问题。
- 汇总 M0 结论，写入 `docs/poc/M0-总结.md`。
- 把实测的容量数据写回架构设计「非功能需求」。
- `CLAUDE.md` 体系的检查。

### 不做

- 新功能。审查发现的缺失功能，登记为后续任务或 ADR，不在本任务中实现。

## 交付物

### 1. P7 容量

- 用 Gatling 或等效工具，在单个 runtime 实例（记录 CPU 与内存配置）上测量：并发运行的轮次上限（`ScriptedModel` 模拟 2 至 5 秒的模型延迟与流式输出），SSE 连接上限（每连接持续接收事件）。
- 记录到达上限时的瓶颈（CPU、数据库连接、内存、Redis）。
- 报告 `docs/poc/P07-容量.md`。

### 2. P11 内存

- 10 万个线程轮转执行（每个线程一轮短对话）后，堆内存稳定；记录 `clearStateCache` 前后 AgentScope 内部缓存的大小。
- 不稳定时，按待决问题 Q6 实现"定期重建引擎实例"的缓解措施，并重新测量。
- 报告 `docs/poc/P11-内存.md`。

### 3. 独立审查

并行启动四个只读的审查子代理（有 `read-only-reviewer` 就用它），每个只负责一个维度，给它们的提示中写明：审查范围、对照的架构设计章节、要求报告全部发现（不只报告高严重度）、每条给出文件与行号和具体的失败场景。

| 维度 | 审查重点 |
|---|---|
| 并发与一致性 | 认领、续租、回收、fencing、事件序号、恢复判定、空闲回收与轮次的竞争 |
| 安全与租户隔离 | 跨租户访问、凭据泄露（代码、日志、事件）、SSRF、受保护路径、出网控制、权限合成与改写 |
| AgentScope 集成 | 引擎装配表逐项落实、事件映射穷举、2.0.4 行为差异的处理、`builder(parent)` 等禁止用法 |
| 工程质量 | 编码规范、通用能力复用（有没有重复实现）、注释、测试质量（有没有削弱断言、硬编码）、`CLAUDE.md` 是否与代码一致 |

拿到结果后，你逐条核实（读代码确认），只修正确认的问题；不同意的发现写明理由。修复中涉及架构变更的，按决策分级处理。

### 4. M0 总结 `docs/poc/M0-总结.md`

- P1 至 P15 每项的结论（通过、有条件通过、不通过）与报告链接。
- 不通过或有条件通过的项，对应的 ADR 与后续处理。
- 实测数据与架构设计目标的对比。
- 结论：是否进入 M1；如果有前提条件，逐条列出。

### 5. 文档与 CLAUDE.md

- 把 P7 实测的容量写回架构设计「非功能需求」表（只更新数值与测试条件）。
- 如果 `init` 技能可用，调用它检查根 `CLAUDE.md`；运行 `/doctor prompt-audit`（如可用），处理过期、冲突的指令；逐个模块核对 `CLAUDE.md` 与代码是否一致。

## 验收标准

- [R1-A01] P7 报告给出并发轮次与 SSE 连接的上限、瓶颈与测试条件。验证：报告路径与数值。
- [R1-A02] P11 报告证明 10 万线程轮转后堆内存稳定，或已实现缓解措施并重新证明。验证：报告路径与数值。
- [R1-A03] 四个维度的审查都已完成；每条发现都有处理结论（已修复并有测试、不同意及理由、登记为后续项）。验证：报告中的发现清单。
- [R1-A04] `docs/poc/M0-总结.md` 覆盖 P1 至 P15，并给出是否进入 M1 的结论。验证：文件路径。
- [R1-A05] 架构设计「非功能需求」已更新为实测值。验证：diff。
- [R1-A06] 各模块 `CLAUDE.md` 与代码一致，根 `CLAUDE.md` 在 200 行以内。验证：检查清单。
- [R1-A07] `scripts/dev/verify.sh` 与 `-Plive`、`-Pkind` 的测试全部通过。验证：命令输出。
