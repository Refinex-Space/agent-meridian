## 背景与目标

runtime 已经在产生用量记录（模型 token、沙箱 vCPU 秒）与审计事件，并写入 outbox；预算检查目前读取开发期配置。本任务在 control-plane 中把这些数据落成正式的账本与审计日志，建立四级预算的管理与对账，并提供用量查询接口。

账本是计费的依据，数字必须准确、可追溯、幂等。

## 必读

1. 架构设计「计量与预算」「数据架构」（跨服务数据流、`usage_records` 与 `audit_logs` 的分区与主键、数据保留）、「安全架构」中的审计范围。
2. runtime 中 `ModelGateway` 的预算预扣与结算实现，以及 outbox `usage`、`audit` 主题的消息格式。
3. 已有模块 `CLAUDE.md`。

## 范围

### 要做

- `cp.usage_records`（按月分区，主键 `(id, occurred_at)`）与消费者：从 Redis Stream `usage` 消费，按价格表版本计算成本，幂等入库。
- `cp.audit_logs`（按月分区，只追加）与消费者：消费 `audit` 主题；查询接口（按时间、操作者、资源、动作过滤）。
- `cp.budgets`：租户、项目、API Key、会话四级，软阈值与硬阈值；管理接口；预算变更同步到 Redis 中的限额。
- 对账任务：每小时比较 Redis 预算计数与账本，以账本为准修正，记录差异指标。
- 软阈值告警：产生审计事件与一条可供控制台读取的告警记录。
- 公开接口 `GET /v1/usage`（项目维度）；管理接口中的用量报表（按天、模型、智能体、API Key 聚合）。
- 搜索次数、Embedding token 的计量（这些在 runtime 中产生的位置补齐 outbox 写入）。

### 不做

- 账单导出、支付（不在架构范围内）。
- 控制台的用量页面（T25b）。

## 交付物

- 消费者支持多实例并发运行，消息至少一次投递、按 `(id, occurred_at)` 幂等；消费者与对账任务的仓储继承 `SystemRepository`，放在 `infra.system`。
- 新租户的四级预算硬阈值默认为 0（架构原则第 5 条"新租户默认零预算"），管理员显式设置后才能使用模型。
- 分区按月自动创建（提前创建下个月的分区），旧分区的保留按架构设计（3 年）。
- 成本计算使用记录产生时生效的价格表版本；调价不影响历史记录。
- runtime 的预算限额来源从开发配置切换为 control-plane 同步到 Redis 的值。

## 实现要点

- 金额用整数的最小货币单位或 `BigDecimal` 加固定精度，不用浮点数。
- 对账以账本为准，修正 Redis 时记录修正量；修正量持续偏大说明预扣逻辑有问题，告警。
- 审计日志的写入路径只有消费者一个入口；数据库角色上对 `audit_logs` 只授予 `INSERT` 与 `SELECT`。

## 验收标准

- [T16-A01] 一轮真实或模拟的对话后，`usage_records` 中有对应记录，成本按价格表正确计算；重复投递不产生重复记录。验证：集成测试。
- [T16-A02] 调整价格表后，新记录用新价格，历史记录不变。验证：集成测试。
- [T16-A03] 四级预算：任一级达到硬阈值时 runtime 拒绝新的模型调用并以 `budget_exceeded` 结束；达到软阈值时产生告警。验证：集成测试。
- [T16-A04] 对账：人为制造 Redis 与账本不一致后，对账任务按账本修正并记录差异。验证：集成测试。
- [T16-A05] 审计：管理操作、权限判定、待处理动作回应、凭据访问、沙箱命令都能在审计查询中检索到；`meridian_app` 角色无法更新或删除审计记录。验证：集成测试。
- [T16-A06] `GET /v1/usage` 与管理报表的聚合结果与账本明细一致。验证：集成测试。
- [T16-A07] 分区自动创建：时钟推进到月底时下个月分区已存在。验证：测试。
- [T16-A08] 新租户在未设置预算前，模型调用以 `budget_exceeded` 被拒绝；设置后可用。验证：集成测试。
- [T16-A09] `scripts/dev/verify.sh` 通过。验证：命令输出。
