## 背景与目标

有些场景，现成的智能体比我们自己搭的更合适，例如编码任务用 Claude Agent SDK，复杂图编排用 LangGraph。架构设计为此在内核适配层预留了接口：`AgentEngine` 只有 AgentScope 一个实现，将来可以新增实现（架构原则第 2 条）。本任务把外部智能体作为"外部 Agent Worker"接入：它们运行在会话沙箱中，平台负责会话、事件、权限、计量、审计，外部智能体只负责执行一轮。

## 必读

1. 架构设计「内核适配层」「端口」「工作区与沙箱」、架构原则第 1、2 条；技术选型调研中「非 Java 组件」。
2. Claude Agent SDK（Python 或 TypeScript）与 LangGraph 的当前版本文档（联网查阅官方资料）；各自的许可证与服务条款。

## 第一步：设计增补

`docs/architecture/addenda/M3-外部AgentWorker.md`：

- 新的 `AgentEngine` 实现如何与沙箱中的外部进程通信（协议、流式事件、取消与中断）。
- 外部智能体的事件到平台事件的映射；无法映射的能力（例如权限审批）如何处理。
- 模型调用：外部智能体直接调用模型时，如何保证限流、预算、计量（例如经平台的 OpenAI 兼容端点转发，并用会话级的临时凭据）。
- 工具与权限：外部智能体自带的工具如何受平台权限约束；做不到的要明确列出风险。
- 首期支持哪一种外部智能体（建议选一个做深），另一种作为扩展说明。
- 与基线的关系：新增 `AgentEngine` 实现是架构预留的扩展点，属于补充；需要改动端口时写 ADR 提议并停止。
