## 背景与目标

平台的目标之一，是业务系统拿到 BaseUrl 与 API Key 后，按手册就能完成接入。本任务提供 Java SDK（业务系统大多是 Java），以及一套面向业务开发者的接入文档：快速开始、概念、事件参考、常见场景、错误码。

## 必读

1. 架构设计「API 设计」全节。
2. `meridian-v1.yaml`（公开 API）。
3. 调用 `doc-craft` 技能撰写文档（教程与参考两类，按技能的文档类型骨架）。

## 范围

### 要做

- `meridian-sdk-java`：由 `meridian-v1.yaml` 生成客户端，再加一层手写的易用封装：会话创建与发送消息、SSE 事件流（类型化事件、自动用 `Last-Event-ID` 续传、去重；会话流按连续 `seq` 检测缺失，线程流与 `?threads=main` 的 `seq` 不连续，不按跳号判定缺失，见架构设计「SSE 协议」）、待处理动作的回应、自定义工具的回调接口、Webhook 签名校验工具、重试与幂等键。SDK 只依赖 JDK 的 HTTP 客户端与 Jackson，不依赖 Spring。
- SDK 示例：`examples/` 下三个可运行的示例（知识库问答、带审批的工具调用、自定义工具），运行前提写清楚。
- 接入文档 `docs/api/`：
  - 快速开始：从拿到 Key 到第一次对话，10 分钟内完成。
  - 概念：会话、线程、轮次、事件、待处理动作、环境、终端用户与权限标签。
  - 事件参考：每个事件类型的含义、何时出现、数据字段。
  - 场景：知识库问答、文档生成与下载产物、审批、自定义工具、运行中插入指令与中断、预算与用量查询、Webhook 接入。
  - 错误码参考：从规范生成，加上处理建议。
- 规范渲染：用 Redoc 或同类工具把 OpenAPI 生成静态页面，构建脚本放在 `scripts/docs/`。

### 不做

- Python、TypeScript SDK（不在 M1 范围；文档中写明可用 OpenAPI 自行生成）。
- 控制台的 SDK（控制台用 openapi-typescript）。

## 验收标准

- [T26-A01] SDK 由规范生成并通过编译；封装层的单元测试覆盖 SSE 续传与去重（会话流与线程流两种 `seq` 语义）、Webhook 签名校验、幂等键。验证：测试报告。
- [T26-A02] 三个示例对本地运行的平台执行成功（知识库问答用 `-Plive` 的真实模型）。验证：运行输出。
- [T26-A03] 一个只读过快速开始文档的子代理（不给它其他上下文），能按文档完成第一次对话。验证：子代理的执行记录与结果。
- [T26-A04] 事件参考覆盖规范中的全部事件类型；错误码参考覆盖全部错误码。验证：生成脚本的对照检查。
- [T26-A05] 文档通过 `doc-craft` 的体检脚本，无明显问题。验证：脚本输出。
- [T26-A06] `scripts/dev/verify.sh` 通过。验证：命令输出。
