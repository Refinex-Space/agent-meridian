## 背景与目标

会话详情页是控制台最有辨识度、也最常用的页面：开发者在这里看清智能体每一步做了什么、为什么停下、花了多少。Playground 让开发者直接和智能体对话调试。两者共用同一个时间轴工作台。

这个页面承载了设计系统中唯一的编排动效（子午线时间轴），它的完成度决定了控制台给人的第一印象。

## 范围

### 要做

- 会话列表：筛选（状态、智能体、终端用户、时间）、实时变化提示（"有 N 条更新"）、批量归档。
- 会话详情（工作台模板）：
  - 左栏：线程树、待处理动作（带黄铜色标记）。
  - 中栏：`SessionTimeline`，展示全部事件类型的渲染器（消息、思考、工具调用与结果、MCP 调用、自定义工具、压缩、状态变化、错误、用量）；运行中实时追加；子线程分叉展开；键盘上下移动选中。
  - 右栏：检查器，显示选中事件的完整内容、原始 JSON、权限结论、耗时、token 与成本；大结果按需加载。
  - 顶部：会话状态、`StreamIndicator`、操作（中断、归档、删除）。
- 运行中的交互：发送消息时选择投递方式（排队或插入当前轮），中断；处理待处理动作（批准、拒绝、记住此决定，回传自定义工具结果，恢复确认）。
- 工作区：浏览工作区文件与产物（`outputs/`），下载。
- Playground：选择智能体版本与环境，开启新会话并对话；与会话详情共用工作台，额外提供"以终端用户身份"的设置（`end_user_id` 与 `acl_tags`），便于调试权限过滤。
- 上下文构成：如果后端提供了每次模型请求的上下文构成（压缩后看到了什么），在检查器中展示。

### 不做

- Web 终端（M2）、会话分叉与回退（M2）。

## 实现要点

- 每种事件的渲染器放在一个注册表中，新增事件类型只需注册渲染器；未知事件类型有兜底渲染（显示类型与 JSON）。
- 1 万条事件的会话：时间轴虚拟滚动、检查器懒加载；性能标准为 Playwright 在固定的 1 万条事件数据上连续滚动 5 秒，帧时间 p95 不超过 16.7 ms，没有超过 50 ms 的长任务。
- 实时追加时，如果用户正在查看历史位置，不要把视图拉到底部；提供"回到最新"。
- 智能体消息用 react-markdown 加 rehype-sanitize 渲染，代码用 Shiki 高亮。

## 验收标准

- [T24-A01] Playground 中与一个真实模型（`qwen-plus`）的智能体对话，时间轴实时显示消息、工具调用与结果、状态变化，结束后显示用量与成本。验证：Playwright 用例（`live` 标签）与录屏或截图。
- [T24-A02] 待处理动作：触发一个需要审批的工具调用，在控制台批准后智能体继续；拒绝后智能体收到拒绝结果。验证：Playwright 用例。
- [T24-A03] 运行中插入一条补充指令（steer），它在当前轮被智能体使用；中断后本轮在检查点停止。验证：Playwright 用例。
- [T24-A04] 子智能体的线程在时间轴中分叉展示，线程树可切换到子线程查看其事件。验证：截图。
- [T24-A05] 断开网络后重连，事件完整且不重复，`StreamIndicator` 正确反映状态。验证：Playwright 用例（模拟断网）。
- [T24-A06] 1 万条事件的会话：Playwright 在固定数据上连续滚动 5 秒，帧时间 p95 不超过 16.7 ms，没有超过 50 ms 的长任务；选中事件时检查器在 200ms 内显示内容。验证：Playwright 输出的帧时间统计与计时。
- [T24-A07] 页面与 T20a、T20c 的原型一致，内容区以外与 T21 的截图基线（`toHaveScreenshot`）一致；禁用清单逐条无违反；亮暗主题、两种宽度截图完整。验证：截图（`tmp/evidence/T24/`）、`toHaveScreenshot` 结果与评审记录。
- [T24-A08] 用 `ego-browser` 以开发者身份完成一次"调试一个工具调用失败的会话"的走查，记录并修正问题。验证：走查记录。
- [T24-A09] 控制台全部检查与 `scripts/dev/verify.sh` 通过。验证：命令输出。
