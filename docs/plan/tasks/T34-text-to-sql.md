## 背景与目标

智能问数让业务人员用自然语言查询企业数据，智能体生成 SQL、执行、分析并给出结论与图表。架构设计中对应平台工具 `sql_query`（只读，规则内容为数据源 ID）。它直接接触企业的业务数据库，安全是第一位的：必须做到"无论模型生成什么 SQL，都不可能修改数据、不可能越权读取、不可能拖垮数据库"。

## 必读

2. `docs/engineering/frontend-design.md`（数据源管理页面）。

## 第一步：设计增补

`docs/architecture/addenda/M2-智能问数.md`：

- 数据源注册（control-plane）：连接信息与凭据（凭据库）、支持的数据库类型（首期 PostgreSQL 与 MySQL）、允许访问的 schema 与表、行级过滤（按终端用户属性）。
- 只读保证的多层防线：数据库层使用只读账号（必需）、SQL 解析白名单（只允许 `SELECT`，禁止多语句与危险函数）、语句超时、结果行数上限、并发上限。
- 语义层：表与列的业务描述、常用指标的定义，供模型生成 SQL 时参考；存储与维护方式。
- 结果处理：小结果直接返回；大结果写入工作区，由智能体在沙箱中用 Python 分析与绘图。
- 审计：每条执行的 SQL 都记录。
- 与基线的关系：只补充；需要改动基线时写 ADR 提议并停止。

**设计关口**：设计增补提交后，把看板中本任务的状态改为"阻塞（等待用户确认设计增补）"，在报告中列出需要用户判断的设计取舍，然后停止（`docs/plan/protocol.md`「设计增补关口」）。用户确认后，用同一个任务编号新开会话续做实现。

## 范围

### 要做

- 设计增补中的全部内容：数据源管理（API 与控制台）、`sql_query` 工具、语义层、审计。
- 测试数据库：用 Testcontainers 起一个带示例业务数据（自编的销售、订单、客户表）的 PostgreSQL 与 MySQL。
- 真实模型测试：10 个自然语言问题，生成的 SQL 执行成功且结果正确。

## 验收标准

- [T34-A01] 设计增补已写，用户已确认。验证：文件路径与确认日期。
- [T34-A02] 安全：`INSERT`、`UPDATE`、`DELETE`、DDL、多语句、`pg_sleep` 等危险函数、超出授权范围的表，全部被拦截；即使绕过解析层，只读账号也无法写入。验证：表驱动测试。
- [T34-A03] 语句超时、行数上限、并发上限生效。验证：测试。
- [T34-A04] 行级过滤按终端用户属性生效。验证：测试。
- [T34-A05] 10 个问题中至少 8 个生成正确结果（`-Plive`），失败的记录原因。验证：测试输出。
- [T34-A06] 大结果写入工作区后，智能体在沙箱中完成分析并生成图表产物。验证：场景测试（`-Pkind`）。
- [T34-A07] 每条执行的 SQL 都有审计记录。验证：测试。
- [T34-A08] 数据源管理页面通过截图评审。验证：截图与评审记录。
- [T34-A09] 全部质量门禁通过。验证：命令输出。
