## 执行要求

开工前完整阅读 `docs/plan/protocol.md` 并严格遵守，开工检查、范围与决策分级、质量门禁、验收记录、收尾与报告格式都以它为准。最重要的几条：

- 先读后写；AgentScope 只以 2.0.4 为准（读法见 `docs/plan/references.md`）。
- 只做本任务范围内的事；补充型决策自己定（影响多个模块或难以回退的才写 ADR），变更型决策写 ADR 提议后停止受影响部分。
- 不删改测试和验收项；只有亲自验证通过的验收项才能标 `passing`。
- 每完成一个检查项就更新 `PLAN.md` 检查点并提交；上下文会被自动压缩，不要提前停下。
- 不推送，不打印凭据。

## 背景与目标

控制台开发之前，后端必须完整、稳定：控制台的每个页面都依赖后端接口，后端的缺口到了前端阶段会变成大量返工。本任务对照架构设计，审查 M1 后端的完整性与质量，修正确认的问题，并确认 M1 验收场景在后端层面都能跑通。

## 必读

1. 架构设计全文，重点「API 设计」中的资源表、「能力清单」中的一期项、「里程碑与验收」中的 M1 验收场景。
2. `docs/plan/PLAN.md` 中 T14a 至 T19b 的会话日志与登记事项；`docs/plan/acceptance.json` 中这些任务的状态。

## 范围

### 要做

- **完整性核对**：逐行对照资源表与能力清单的一期项，列出每项的实现位置。缺失项登记到 `PLAN.md` 的"登记事项"；需要新接口或要改动多个类的，不在本任务实现，由用户决定插入补充任务。只改动少量代码就能修正的问题可以在本任务修正。
- **API 一致性**：`meridian-v1.yaml`、`meridian-admin-v1.yaml`、`meridian-internal-v1.yaml` 与实现一致（契约测试全覆盖），字段命名、错误码、分页、幂等的风格统一。核对 T19b 的"页面到接口"对照表（`docs/engineering/console-api-map.md`）与实现一致。
- **独立审查**：并行启动四个只读审查子代理（同 R1 的方式与提示要求），维度为：租户隔离与授权、凭据与审计、API 契约与错误处理、并发与数据一致性（会话删除、归档、Webhook、计量）。逐条核实结论，修正确认的问题。
- **后端验收预演**：用 HTTP 客户端脚本（放在 `e2e/backend/`）跑通 M1 验收场景 1、3、4、5、6、7、8 的后端部分（场景 2 使用 T12a 的内置 docx 技能与沙箱，也一并跑通）。默认连接脚本化模型服务，需要真实模型理解的步骤放在 `-Plive` 中。
- **CLAUDE.md 与文档**：同 R1 的检查。

### 不做

- 控制台、可观测性、部署（后续任务）。

## 验收标准

- [R2-A01] 资源表与一期能力清单逐项有实现位置，缺失项已补齐或登记。验证：报告中的对照表。
- [R2-A02] 三份 OpenAPI 规范与实现一致，契约测试覆盖全部端点。验证：测试报告。
- [R2-A03] T19b 的页面到接口对照表与实现一致；新发现的缺口已登记。验证：对照表与登记事项。
- [R2-A04] 四个维度的审查完成，每条发现都有处理结论。验证：发现清单。
- [R2-A05] `e2e/backend/` 中 M1 验收场景的后端部分全部跑通。验证：脚本输出。
- [R2-A06] `scripts/dev/verify.sh`、`-Plive`、`-Pkind` 全部通过。验证：命令输出。
