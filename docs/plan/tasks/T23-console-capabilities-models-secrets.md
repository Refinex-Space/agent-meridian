## 背景与目标

管理员在这些页面中管理智能体可用的能力（技能、MCP 服务）、模型（供应商账号、模型目录、价格表）与凭据。凭据页的设计重点是"只写不读"：用户要清楚地知道凭据已保存、被哪些资源使用、何时最后使用，但永远看不到明文。

## 必读

2. 架构设计「控制台」中能力、模型两行与设置中的凭据，「安全架构」中的「凭据」。
3. `console/CLAUDE.md`；管理 API 中技能、MCP 服务、供应商、模型、价格表、凭据的接口。

## 范围

### 要做

- 技能：列表、上传技能包（`SKILL.md` 及附件，上传前在浏览器端解析并预览 frontmatter 与正文）、版本、被哪些智能体引用。
- MCP 服务：注册（传输类型、地址、认证凭据引用）、探测结果与工具清单、为每个工具标注副作用等级、连接状态。
- 自定义工具：说明页（业务方如何在创建会话时声明自定义工具，示例请求）。
- 供应商账号与模型：供应商账号（类型、端点、凭据引用）、模型目录（上下文窗口、能力、默认参数）、连通性测试按钮（调用一次最小请求并展示延迟与结果）。
- 价格表：版本化，展示生效时间，新版本不影响历史。
- 凭据：创建（输入后立即提交，不回显）、轮换、删除（说明影响的资源）、列表（名称、创建时间、最后使用时间、引用方）。

### 不做

- 用量与预算、设置（T25b）。

## 实现要点

- 凭据输入框使用密码类型，提交后清空表单状态；任何地方都不缓存明文（包括 TanStack Query 的缓存与浏览器存储）。
- 副作用等级的说明用 info 提示解释三个等级的含义与对恢复的影响，不在页面上铺长段文字。
- 连通性测试会产生少量费用：按钮旁用提示说明，并在结果中显示用量。

## 验收标准

- [T23-A01] 上传一个技能包，预览正确，发布后能被智能体引用。验证：Playwright 用例。
- [T23-A02] 注册一个 MCP 服务（测试环境中的进程内服务或本地 MCP 服务），工具清单出现，副作用等级可标注并保存。验证：Playwright 用例。
- [T23-A03] 新建供应商账号与模型后，连通性测试成功（`DASHSCOPE_API_KEY`，作为凭据录入），显示延迟与用量。验证：Playwright 用例（`live` 标签）。
- [T23-A04] 凭据明文在提交后不出现在页面、网络响应、浏览器存储与查询缓存中。验证：Playwright 用例检查 DOM、网络响应与存储。
- [T23-A05] 价格表新版本生效后，历史用量的成本不变。验证：Playwright 用例加 API 断言。
- [T23-A06] 所有页面的状态完整，与设计规范一致，内容区以外与 T21 的截图基线（`toHaveScreenshot`）一致。验证：截图（`tmp/evidence/T23/`）与 `toHaveScreenshot` 结果，对照评审表与禁用清单。
