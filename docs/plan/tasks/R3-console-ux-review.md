## 背景与目标

四个页面任务分别完成了各自的页面。本任务从用户的角度把控制台当作一个整体来审视：一致性、完成度、细节、性能、无障碍，以及有没有 AI 模板的痕迹。发现的问题当场修正。

## 必读

1. `docs/engineering/frontend-design.md` 全文，尤其「禁用清单」与「设计流程与评审」中的评审表。
2. `tmp/evidence/` 下 T20a 至 T25b 已有的截图与各任务的评审记录。

## 范围

### 要做

- **全量走查**：用 `ego-browser` 按四类用户（平台管理员、智能体开发者、审批人、运营与财务）各走一遍他们的主要任务，记录每一处卡顿、困惑、不一致。
- **一致性审查**：所有页面的状态颜色、图标、术语、页头结构、表格行为、空态与错误态、确认对话框的写法，与规范逐项比对。
- **禁用清单**：逐页逐条检查，截图为证。
- **细节**：对齐、间距、截断与溢出、长文本、极端数据（0 条、1 条、1 万条）、中英文混排、数字格式。
- **无障碍**：键盘全程可用、焦点可见、屏幕阅读器名称（用浏览器的无障碍树检查）、对比度、减少动效。
- **性能**：首屏 JavaScript 体积、路由懒加载、长列表滚动、时间轴性能，与规范的预算比较。
- **修正**：确认的问题直接修正；涉及设计规范变更的，写 ADR 并更新 `frontend-design.md`。

## 验收标准

- [R3-A01] 四类用户的主要任务都能顺畅完成，走查记录中的问题全部修正或登记。验证：走查记录。
- [R3-A02] 一致性审查的差异全部消除。验证：审查清单。
- [R3-A03] 禁用清单在全部页面上逐条无违反。验证：截图与清单。
- [R3-A04] 键盘可完成全部主要任务；Storybook 与页面级 a11y 检查零违规。验证：检查报告。
- [R3-A05] 性能预算全部满足：首屏 JavaScript（gzip）不超过 300 KB；时间轴在真实页面中，Playwright 在固定的 1 万条事件数据上连续滚动 5 秒，帧时间 p95 不超过 16.7 ms，没有超过 50 ms 的长任务。验证：构建分析与 Playwright 输出的帧时间统计。
- [R3-A06] 全部页面亮暗主题、1280 与 1920 宽度的最终截图归档在 `tmp/evidence/R3/`，并在报告中给出总体评价。验证：截图与报告。
- [R3-A07] 控制台全部检查与 `scripts/dev/verify.sh` 通过。验证：命令输出。
