## 背景与目标

各任务已经注册了自己的指标、span 与日志。本任务把它们汇成可用的可观测体系：统一的追踪层级与属性、Langfuse 中的 LLM 调用明细、Grafana 看板与告警、日志脱敏。目标是线上出问题时，运维能在几分钟内定位到租户、会话、轮次、工具。

## 必读

1. 架构设计「可观测性」全节、「非功能需求」、「部署架构」中 `meridian-observability` 命名空间。
2. 各模块 `CLAUDE.md` 中登记的指标与 span。

## 范围

### 要做

- 追踪：核对 span 层级（`turn` → `invoke_agent` → `chat {model}`，以及 `execute_tool {name}`、`sandbox.exec`、`subagent {name}`）与公共属性；跨服务传播（runtime ↔ control-plane ↔ knowledge ↔ doc-parser）；补齐缺失的部分。
- Langfuse：自托管（Docker Compose 的 `observability` profile）；通过 OTLP 接收 LLM 调用的 span，包含提示词与输出（只在 Langfuse 中，不进普通追踪）；访问权限与控制台一致的方案写进部署文档。
- 指标：核对架构设计「可观测性」指标表中的每一个都已注册、命名与标签一致；补齐缺失的。
- Grafana 看板（JSON 提交到仓库）：平台总览、调度与轮次、模型与成本、工具与沙箱、SSE 与 API。
- 告警规则（Prometheus 规则文件）：可用性、错误率、调度队列积压、租约丢失、预算拒绝激增、沙箱认领变慢。阈值与非功能需求一致。
- 日志：JSON 格式，带 MDC 键；脱敏过滤器（API Key、凭据、代理变量、邮箱与手机号等个人信息）；脱敏的单元测试。
- 本地：`observability` profile 起 OTel Collector、Prometheus、Grafana、Loki、Langfuse；看板自动导入。

### 不做

- 生产环境的部署（T28）。

## 实现要点

- Langfuse 依赖 ClickHouse，内存占用较大：启动前检查 Docker 可用内存，不足时在报告开头提醒用户。
- GenAI 语义约定仍在变化：导出时加一层属性映射，映射表集中在一处。

## 验收标准

- [T27-A01] 一次包含工具调用、子智能体、沙箱命令、知识检索的会话，在追踪中呈现完整的跨服务调用树，公共属性齐全。验证：Tempo 或 Jaeger 中的追踪截图，或导出的追踪 JSON。
- [T27-A02] 该会话的 LLM 调用在 Langfuse 中可见（提示词、输出、token、成本）；普通追踪中不含提示词正文。验证：截图与追踪 JSON 检查。
- [T27-A03] 指标表中的每个指标都已注册且命名与标签一致。验证：一个测试或脚本对照架构设计的指标表。
- [T27-A04] 五个看板导入后都有数据。验证：截图。
- [T27-A05] 告警规则通过 `promtool` 校验；人为制造调度积压时触发告警。验证：命令输出。
- [T27-A06] 脱敏：日志中出现 API Key、凭据、个人信息时被遮盖。验证：单元测试。
- [T27-A07] `scripts/dev/verify.sh` 通过。验证：命令输出。
