## 背景与目标

架构设计把三项安全能力放在二期：PostgreSQL 行级安全（RLS）作为租户隔离的第二道防线；MCP 的 OAuth（外部 MCP 客户端访问平台、平台访问需要 OAuth 的 MCP 服务）；沙箱出网时由代理注入凭据（需要 TLS 终止，一期的 ADR-0017 暂缓了它）。

## 必读

1. 架构设计「安全架构」全节、「数据架构」、「工作区与沙箱」中的「沙箱出网」、ADR-0017。
2. MCP 规范最新版本中的授权部分（联网查阅官方规范）。

## 第一步：设计增补

`docs/architecture/addenda/M2-安全加固.md`：

- RLS：每张业务表的策略、会话变量的设置方式（与 `TenantScopedRepository` 和连接池配合）、调度类跨租户 SQL 的处理（使用单独的角色）、性能影响的评估方法。
- MCP OAuth：平台作为 MCP 服务端时的授权流程；平台作为客户端访问需要 OAuth 的 MCP 服务时，令牌的获取、存储（凭据库）、刷新，以及按终端用户授权的场景。
- 出网凭据注入：TLS 终止代理的选型、沙箱镜像信任平台 CA 的方式、凭据按目标域名注入的规则、证书管理；与 ADR-0017 的关系（写新 ADR 取代它，状态"提议"，需用户确认后才实施）。
- 与基线的关系：RLS 与 MCP OAuth 为补充；出网凭据注入改变 ADR-0017，属于变更型。

**设计关口**：设计增补提交后，把看板中本任务的状态改为"阻塞（等待用户确认设计增补）"，在报告中列出需要用户判断的设计取舍，然后停止（`docs/plan/protocol.md`「设计增补关口」）。用户确认后，用同一个任务编号新开会话续做实现。
