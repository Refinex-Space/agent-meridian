## 背景与目标

调试智能体时，开发者经常想"从某一步重新来"：回退到某个事件之前，换一种说法重试；或者从某个时刻分叉出一个新会话，对比两种走向。架构设计在 API 中预留了 `POST /v1/sessions/{id}:fork` 与 `:rewind`。

## 必读

1. 架构设计「API 设计」资源表中的分叉与回退、「数据架构」、「工作区与沙箱」（快照）、「崩溃恢复」（状态版本与 `content_epoch`）。
2. 参考：claude-code-analysis 的 fork 与 rewind 机制（只学机制）、pi 的会话树。

## 第一步：设计增补

`docs/architecture/addenda/M2-分叉与回退.md`：

- 分叉：新会话复制到指定事件为止的事件链、智能体状态（如何得到那一刻的状态）、工作区（`none` 档复制存储条目，沙箱档基于快照）；新会话与原会话的关系记录。
- 回退：回到指定事件之前，之后的事件如何处理（保留并标记为已回退，还是删除）、智能体状态与工作区如何恢复、有副作用的工具调用不会被撤销（必须在界面与 API 中明确告知）。
- 状态快照的来源：是否需要在每轮结束时保存可回退的状态版本；存储成本。
- 与基线的关系：只补充；需要改动基线时写 ADR 提议并停止。

## 验收标准

- [T33-A01] 设计增补已写。验证：文件路径。
- [T33-A02] 分叉：新会话从指定事件处继续对话，原会话不受影响；两种档位的工作区都正确复制。验证：集成测试。
- [T33-A03] 回退：回到指定事件之前后继续对话，智能体看不到被回退的内容；工作区恢复到对应时刻。验证：集成测试。
- [T33-A04] 有副作用的工具调用在回退时被明确告知不会撤销。验证：API 响应与控制台截图。
- [T33-A05] 控制台操作通过截图评审。验证：截图与评审记录。
- [T33-A06] 全部质量门禁通过。验证：命令输出。
