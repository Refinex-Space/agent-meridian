## 背景与目标

两个开放协议让平台融入更大的生态：A2A 让平台上的智能体与外部智能体互相调用（平台既是服务端也是客户端），AG-UI 让业务方的前端组件直接对接智能体事件流。架构设计把二者列为二期能力。

## 必读

1. 架构设计「API 设计」中的「接入协议」与「事件」、「子智能体」。
2. A2A 规范与 a2a-java SDK 的当前版本（联网查阅官方仓库，取最新稳定版）；AG-UI 协议与其 Java 社区 SDK。
3. 技术选型调研中关于 A2A 与 AG-UI 的部分。

## 第一步：设计增补

`docs/architecture/addenda/M2-A2A与AG-UI.md`：

- A2A 服务端：哪些智能体对外暴露（智能体版本上的开关）、Agent Card 的生成、认证（API Key）、任务与平台会话的映射、流式。
- A2A 客户端：外部智能体作为一种远程子智能体（经 `spawn_subagent` 或独立工具），凭据来自凭据库，结果与事件如何回到父线程。
- AG-UI：平台事件到 AG-UI 事件的映射表，端点形态，认证。
- 依赖：a2a-java SDK 是新依赖，写 ADR（补充型），确认与 AgentScope 的依赖不冲突。
- 与基线的关系：只补充；需要改动基线时写 ADR 提议并停止。
