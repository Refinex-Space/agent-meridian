## 背景与目标

T14a 至 T19 按领域建好了后端，但控制台的页面是按管理员的工作组织的：概览要聚合、待处理要跨会话、设置要处理 OIDC 下的成员。按页面倒推，后端还有一批接口没有任何任务负责。本任务先逐页列出"页面到接口"的对照表，再补齐缺口、写规范与契约测试。

完成后，控制台任务（T21 至 T25b）只消费已有接口，不在前端阶段临时发明后端。

## 必读

## 范围

### 要做

- 页面到接口的对照表：`docs/engineering/console-api-map.md`。按信息架构的十一个一级导航逐页列出：展示的数据、可执行的操作、实时性要求、对应的接口、接口是否已存在。
- 补齐对照表中缺失的接口，写入对应规范并有契约测试。已知的缺口至少包括：
  - 项目级待处理动作的列表与历史（按状态、类型、智能体筛选，游标分页）。
  - 概览的聚合：运行中的会话数、待处理动作数、按智能体的失败率（时间窗）、最近错误、本周期用量与预算消耗。
  - 会话列表的筛选与搜索（智能体、状态、终端用户、时间范围）。
  - OIDC 下的成员管理语义：以 IdP 中的用户标识或邮箱添加成员并授予角色；用户首次登录时按邮箱声明绑定。语义写进对照表与规范。
  - 供应商账号的连通性测试、MCP 服务的连接状态与重新探测。
  - 智能体的"使用中的会话"数、环境的修订历史查询。
- 每个新接口都有授权规则（角色矩阵中补行）与审计（写操作）。

### 不做

- 控制台页面（T21 起）。
- M2 的能力（预算报表的高级分析、跨项目的待处理收件箱等）。

## 实现要点

- 聚合查询不能拖慢主路径：概览的聚合优先使用已有的账本与计数，必要时建物化的日聚合表；写明每个聚合的数据来源与刷新频率。
- 接口风格与已有规范一致：字段命名、错误码、游标分页、幂等。
- 新的跨租户查询（例如按时间窗统计失败率的后台作业）继承 `SystemRepository`，放在 `infra.system`。
