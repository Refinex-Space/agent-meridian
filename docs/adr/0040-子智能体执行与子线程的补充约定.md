# ADR-0040 子智能体执行与子线程的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-09 |
| 决策人 | T13 执行会话 |
| 影响的架构设计章节 | 「端口」（`ThreadRegistryPort` 的语义细化与方法签名）、「平台中间件」的 `PolicyMiddleware` 行、「子智能体」、「崩溃恢复」（只补充，不改既有条款） |

## 背景

T13 按架构设计「子智能体」的六步实现 `spawn_subagent`，并验证 P12。落地时遇到以下没有写到的细节（AgentScope 2.0.4 已核实）：

- **执行放在哪里。** 子智能体要从实例缓存租用实例，而实例缓存经装配器依赖工具提供者，`spawn_subagent` 又是工具提供者创建的工具；工具直接持有实例缓存会形成循环。中断要求 `AgentEngine.interrupt` 先找到"本轮登记的全部子线程"。
- **阻塞与取消。** 平台工具的 `execute` 在有界弹性线程上同步执行；同步等待一个最长 600 秒的子智能体会占住线程，父线程的订阅被取消（失去租约）时取消也传不到子智能体。
- **`ThreadRegistryPort` 与事件。** 端口有"创建子线程""更新线程状态"两个方法，架构要求同时发出 `session.thread_created`、`session.thread_status_running`、`session.thread_status_idle`；而 runtime 的线程状态本来就随状态事件在同一事务中推进（ADR-0027）。`session.thread_status_idle` 必须带 `stop_reason`（OpenAPI），原端口的 `updateStatus(threadId, status)` 没有它。
- **子线程的终态。** 子智能体的事件流与主线程一样以 `session.status_*` 结束；把它写到子线程上会推进会话状态（`StatusChange` 对带线程的 `session.status_*` 同时更新会话）。超时没有对应的停止原因。
- **`RuntimeContext.builder(parent)` 复制什么。** 2.0.4 的 `Builder.from` 复制 `sessionId`、`userId`、`agentState`、`toolExecutionContext`、`toolRequestConfig` 与全部类型化属性；`HarnessAgent.ensureSessionDefaults` 只在上下文里没有 `AbstractFilesystem` 时放入本实例的文件系统，复制来的父线程文件系统会被沿用。
- **拉起上限怎样拒绝。** 2.0.4 不发布 `onActing` 中间件自己合成的事件（ADR-0034），`PolicyMiddleware` 不能直接给出被拒绝调用的结果。
- **副作用等级。** 架构规定 `spawn_subagent` 取子智能体工具中最高的等级，平台工具的等级写在各自的声明里，MCP 工具的等级在服务配置里。
- **崩溃恢复。** 子线程的工具调用记在父轮次下（账本带 `thread_id`、`turn_id` 是父轮次），父线程恢复时读取"本轮的全部账本记录"，会把子线程的调用当成父线程的调用：状态未知的 `non_idempotent` 子线程调用会产生恢复确认，确认重试时却在父线程的 Toolkit 里执行。
- **审计。** 架构要求每次权限判定都写审计；Worker 写主线程的工具结果时写 `permission.decided`，子线程的事件经 `EventSinkPort` 写入，原实现不写。
- **删除会话。** 任务要求删除会话时清理子线程的 `agent_states`；级联清理的总流程在 T17a。

## 候选方案

- **执行组件。** A：工具持有实例缓存（循环依赖，要延迟注入）。B：内核每轮在主线程的 `RuntimeContext` 放一个本轮入口，工具从调用上下文取出它，入口指向内核级的执行组件（与实例缓存同一个）。选 B：没有循环，中断登记天然属于本轮。
- **线程事件。** A：端口只管行，工具另经 `EventSinkPort` 写事件（两个事务，崩溃时可能留下没有事件的线程行）。B：端口的实现在同一事务里写行与事件，`updateStatus` 增加停止原因、就是写状态事件。选 B。
- **拉起上限。** A：工具自己计数（并行执行时被拒绝的是哪一个取决于调度）。B：`PolicyMiddleware` 在每批执行前按批内顺序分配名额，工具据此给出拒绝结果。选 B。

## 决策

1. **工具与执行组件。** `tools.SpawnSubagentTool`（继承 `PlatformTool`）只校验入参（`subagent` 是枚举，`task` 不能为空）并把结果写成给模型看的英文文本；`PlatformTool` 增加可覆盖的 `executeAsync`，`spawn_subagent` 以响应式执行，不占线程，取消会传到子智能体。`PlatformToolProvider` 不经登记，在其他工具（含 MCP 工具）创建之后为声明了子智能体的主智能体加入它，副作用等级取子智能体可用工具在本实例中同名工具的最高等级（没有注册的工具不计入）。内核（`AgentScopeEngine` 的第 7 个构造参数）配置了 `turn.SubagentRunner` 时，每轮把 `SubagentSlot`（本轮入口：父线程的上下文、子智能体执行的登记）与 `middleware.SubagentQuota`（拉起名额）放进主线程的 `RuntimeContext`；没有配置时工具返回"不可用"的错误结果。
2. **子线程与事件（`ThreadRegistryPort`）。** `createChildThread` 在一个事务里先以父轮次的租约为条件写 `session.thread_created`（锁轮次行、再锁会话行分配 seq），再插入 `rt.threads` 行，租约不满足时什么都不写、抛 `LeaseLostException`。`updateStatus(threadId, status, stopReason)` 写 `session.thread_status_running` 或 `session.thread_status_idle`（空闲必须带停止原因、运行中不能带），线程行的状态由事件写入方在同一事务中推进。这些事件与子线程的其他事件，信封中的 `thread_id` 都是子线程；`?threads=main` 按类型放行三种线程事件（T07 已实现）。
3. **子线程的上下文。** `RuntimeContext.builder()` 从空白构建，只放派生的 `PlatformContext`（线程 ID 改为子线程，租户、项目、会话、轮次、租约 epoch、终端用户、预算句柄与父线程相同）、会话沙箱的 `SandboxContext`（同一个沙箱，新建的上下文对象）与本次执行新建的 `PlatformStopRequest`。恢复说明、批次 checkpoint、中断检查点、拉起名额与本轮入口都不放：子智能体中间件集合中的对应中间件对子线程不起作用。子智能体的输入是平台上下文消息（当前时间）加任务文本。
4. **执行与权限。** 子智能体实例经 `AgentInstanceCache.acquireSubagent` 按父智能体版本加子智能体名装配与缓存，中间件集合不含 `SteerMiddleware`。开始前把子线程登记到父线程的租约下（`LeaseRegistry.attachChildThread`），`clearStateCache` 后在权限安装标记下安装 `TurnContext.subagentPolicies` 中该子智能体的策略并入实例的策略拒绝规则；本轮没有该子智能体的策略时失败关闭（`DONT_ASK`、没有放行规则）。结束时（含异常、取消）取消登记、清理缓存、解除租约登记、归还实例。
5. **子线程的事件与终态。** 每次执行一个新的 `TurnEventMapper`，事件按顺序经 `EventSinkPort` 写成子线程的事件。终态事件不写，而是换成 `session.thread_status_idle`：`status_idle` 取它的停止原因；`status_requires_action`（`PERMISSION_ASKING`、`TOOL_SUSPENDED`）为 `tools_denied`，工具结果是说明哪些调用需要审批而被拒绝的错误结果；节点下线的 `status_rescheduled` 为 `interrupted`，可重试错误为 `error`（子线程不重试）。子线程的 `session.error` 照写，`retry_status` 一律为 `terminal`。子线程创建之后、事件流之外的失败（例如子智能体的实例装配失败）按同样的映射写 `session.error` 与 `session.thread_status_idle(error)`，子线程不会停在只有 `thread_created` 的状态；租约丢失原样结束。只有 `end_turn` 的结果是成功的工具结果（内容是最终消息），其余是说明原因并附带已有输出的错误结果。
6. **超时。** 对 `streamEvents` 的订阅加 `takeUntilOther(子智能体超时)`：到时取消订阅（AgentScope 不保存状态、不发事件），已经映射出的事件按顺序写完后写 `session.thread_status_idle(interrupted)`，返回超时结果。停止原因复用 `interrupted`，不新增取值（对外的枚举不变）。
7. **中断。** `SubagentSlot` 登记本轮正在执行的子智能体；`AgentEngine.interrupt` 先经它以用户来源中断全部子线程，再中断父线程。父线程被中断之后开始的拉起直接拒绝、不创建线程；登记时父线程已被中断的执行立即中断。调用被受理之前收到的中断在受理后补发（从主线程的实现提取为 `InterruptRelay`，两处共用）。
8. **拉起上限。** `PolicyMiddleware` 在每批工具执行前按批内顺序为 `spawn_subagent` 调用在 `SubagentQuota` 中分配名额，上限由 runtime 配置 `meridian.runtime.worker.max-subagents-per-turn`（默认 8）经 `PlatformMiddlewareProvider` 传入；超出的调用照常进入工具，由工具返回错误结果，不创建子线程。恢复确认的重试不经过中间件，不占本轮名额。
9. **崩溃恢复。** 子线程不会被恢复：每次拉起都是新的子线程，状态留在 `agent_states` 中，只随会话删除清理。父线程恢复时的账本记录与结果摘要只取本线程（`thread_id` 等于轮次所在线程）的，父线程看到的是 `spawn_subagent` 本身；它的副作用等级（第 1 条）决定状态未知时是否需要恢复确认，选择重试时 `retryToolCall` 放入本轮入口，拉起一条新的子线程。
10. **审计、计量与删除。** runtime 的 `EventSinkPort` 实现经 `ApprovalAudit` 写入持久化事件，子线程的工具结果在同一事务中写 `permission.decided`。子智能体的模型调用带派生的 `PlatformContext` 经 `RoutedModel` 计量，用量记录的会话、轮次是父线程的，线程是子线程、模型是子智能体的模型。删除会话的事务（已取消执行中的轮次）删除会话全部线程（含子线程）的 `agent_states`，其余数据仍由 T17a 的级联清理负责。

## 影响

- 架构设计：「端口」表中 `ThreadRegistryPort` 的用途写明线程事件；「平台中间件」的 `PolicyMiddleware` 行写明拉起名额的落地方式；「子智能体」增加落地约定；「崩溃恢复」写明子线程不恢复、父线程只看本线程的调用；版本升至 v1.15。
- 代码：engine-spi 的 `ThreadRegistryPort`；engine-agentscope 的 `tools.SpawnSubagentTool`、`PlatformTool.executeAsync`、`PlatformToolProvider`、`turn.SubagentRunner`/`SubagentSlot`/`SubagentOutcome`/`InterruptRelay`/`ExecutionSlot`、`middleware.SubagentQuota`、`PolicyMiddleware`、`PlatformMiddlewareProvider`、`AgentScopeEngine`；runtime 的 `session.app.DatabaseThreadRegistry`、`DatabaseEventSink`、`TurnPreparer`、`SessionService.delete`、`ThreadRepository.deleteAgentStates`、`WorkerProperties.maxSubagentsPerTurn`、`EngineAutoConfiguration`。没有迁移。
- 验证：`SubagentScenarioTest`（内核）、`SubagentSessionIT`（经 HTTP 的完整路径）、`SubagentRecoveryIT`（恢复只看父线程的调用、旧 epoch 不能创建子线程）；P12 报告 `docs/poc/P12-子智能体.md`。
- 风险：子线程的事件逐条在各自的事务中写入，事件量大的子智能体会增加数据库写入；超时与父线程取消时，AgentScope 在取消后把内部的 `CancellationException` 交给 Reactor 的 `onErrorDropped`，日志中会有一条 ERROR（不影响结果）。
