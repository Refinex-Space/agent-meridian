## 背景

T21 搭建控制台的工程基座：登录、路由、API 客户端、SSE、权限、主题、端到端测试与 CI。架构设计规定了"授权码加 PKCE、access token 只放内存""TanStack Router""fetch 读取 SSE"，没有写到以下细节，它们影响 T22 至 T25b 的每个页面与 T28 的部署：

- **刷新页面后的登录。** 令牌只在内存，刷新页面就丢了；"静默续期"要在不把令牌写进浏览器存储的前提下重新取得令牌。
- **身份提供方的地址从哪里来。** 控制台是静态资源，企业部署时 IdP、客户端随环境变化。
- **地址结构。** 项目放在哪里（路径、查询参数还是本地状态），回调地址是什么。
- **搜索参数的格式。** TanStack Router 默认把搜索参数编码为 JSON（`?status=%5B%22running%22%5D`），与 FilterBar 的取值、可分享的地址不一致。
- **接口按路径路由到三个服务。** 控制台同源调用公开 API 与管理 API；架构设计「容器视图」的路由清单只列了 `/v1/sessions*`、`/v1/files*` 与模型直通进 runtime，遗漏了同样由 runtime 提供的 `/v1/session-stats`、`/v1/pending-actions`（ADR-0053）与 `/v1/webhook-deliveries`（ADR-0049）。
- **页面模板放在哪一层。** T20c 的四种模板在 `prototypes/`，正式页面（`features/`）不能依赖原型。
- **截图基线怎样在 CI 上稳定。** 截图随字体渲染与操作系统变化，原型夹具的时间相对"现在"生成。

## 候选方案

**刷新页面后的登录**

- A：refresh token 存 sessionStorage，刷新后用它换新令牌。令牌落进浏览器存储，可被同源脚本读出，违背"只放内存"。
- B：后端为前端（BFF）持有令牌、浏览器只拿会话 Cookie。新增一个部署单元，改变架构设计「认证」的做法，属于变更型。
- C（采纳）：令牌（含 refresh token）只放内存；运行中由 refresh token 在后台续期；刷新页面后用隐藏的 iframe 以 `prompt=none` 向身份提供方取新令牌，依赖它的登录会话 Cookie；没有会话（`login_required` 等）时整页跳转登录，身份提供方不可达时不跳转、说明原因。
- 客户端库：keycloak-js 绑定 Keycloak，违背 ADR-0043"只认标准 OIDC"；采纳 oidc-client-ts 3.5.0（PKCE、iframe 静默登录、内存存储都有现成实现）。

**身份提供方的配置**

- A：构建时的环境变量（`VITE_*`）。每个环境要重新构建。
- B（采纳）：运行时读同源的 `/config.json`（`oidc.authority`、`oidc.clientId`、可选的 `oidc.scope`），同一份构建产物用于所有环境；开发环境的默认值在 `console/public/config.json`。

**地址结构**

- A：当前项目放在本地状态，地址只有页面。链接不能分享给同项目的同事，多个标签页各自的项目会互相覆盖。
- B（采纳）：`/projects/$projectId/<一级导航>`，项目 ID 在路径中；租户由用户能进入的项目推出（项目 ID 全局唯一）。`/` 跳到上次使用的项目（本地记录）或第一个项目。

**搜索参数**

- A：沿用默认的 JSON 编码。
- B（采纳）：替换路由的 `parseSearch`、`stringifySearch` 为标准的 `key=value` 与重复键（`console/src/lib/search.ts`），值只有字符串与字符串数组，类型由各路由校验。

**模板的位置**

- A：放进 `components/domain/`。模板是版式，不是领域组件，自研组件表会混入四个布局组件。
- B（采纳）：新的一层 `components/templates/`：可以依赖 domain、ui、lib；features、app、原型可以依赖它（`meridian/import-boundaries` 检查）。

**截图基线**

- A：在 CI 机器上直接运行 Playwright，基线在开发机生成。macOS 与 Linux 的字体渲染不同，基线永远对不上。
- B（采纳）：基线按平台分开（`-darwin`、`-linux`），Linux 基线与 CI 都在 Playwright 官方镜像（版本与 `@playwright/test` 一致）中运行；截图前固定页面时钟。

## 决策

1. **登录。** oidc-client-ts，`userStore` 为内存，交互状态（PKCE 的 `code_verifier`）在 sessionStorage 并在回调后删除。回调地址 `/auth/callback`（整页）与 `/auth/silent-callback`（iframe，只把授权响应交给父页面，不加载应用）。access token 剩余不到 30 秒时先续期再发请求；服务端返回 401 时续期一次，10 秒内再次 401 就重新登录；并发的续期合并为一次。退出走 `end_session_endpoint`，回到控制台后因为没有会话而跳转登录。
2. **运行时配置。** 控制台启动时读 `/config.json`；缺失或格式不对时整页说明原因，不跳转。
3. **地址。** 一级导航都在 `/projects/$projectId/` 之下，每项一个路由模块（`console/src/features/<领域>`），路由树在 `console/src/app/router.tsx`；项目不存在与没有权限进入同样处理（与 ADR-0044 的 403 一致）。筛选条件放搜索参数，格式见上。
4. **接口路由。** 控制台按同源调用，入口按路径转发：`/v1/sessions*`、`/v1/session-stats`、`/v1/pending-actions*`、`/v1/webhook-deliveries*`、`/v1/files*`、`/v1/chat/completions`、`/v1/responses`、`/v1/embeddings` 进 runtime；`/v1/knowledge-bases*` 进 knowledge；其余 `/v1/*` 与 `/admin/v1/*` 进 control-plane。开发与预览的代理表在 `console/vite.config.ts`，与它相同。
5. **请求。** openapi-fetch 按生成的类型调用（公开 API 与管理 API 各一份类型，`pnpm gen:api` 由 `redocly.yaml` 生成，`dev`、`build` 先生成，lint 检查是否过期）；每个请求带 `Authorization`，公开 API 另带 `Meridian-Project`；失败映射为带 problem+json 与 `request_id` 的 `ApiError`。TanStack Query 的查询键以 `['admin', …]` 或 `['v1', 项目 ID, …]` 开头；查询只重试网络错误、429 与 5xx（最多 2 次）；变更不重试，失败默认发错误通知，`meta.notifyError: false` 时由界面就地显示。
6. **分层。** `app`（入口、路由、外壳）不依赖原型与 MSW；原型借用 `app` 的外壳，随原型一起删除。
7. **截图基线。** 外壳与四种模板的基线以 Storybook 的原型故事为对象（亮暗、1280 与 1920），固定时钟；之后的页面任务改外壳或模板时更新基线并说明。

## 影响

- 架构设计：「容器视图」的外部路由补上三个 runtime 接口；「认证」控制台用户一行补充刷新页面后的静默登录；「控制台·技术约定」补充地址结构、运行时配置与搜索参数格式。
- 部署（T28）：控制台的静态资源服务要对未知路径回退到 `index.html`（含两个回调地址），提供 `/config.json`；身份提供方的控制台客户端登记这两个回调地址与退出后的回跳地址。
- 风险：iframe 静默登录依赖身份提供方的会话 Cookie 能在 iframe 中读到。控制台与身份提供方同站（本地开发是 `localhost` 的不同端口）时可用；跨站部署且浏览器拦截第三方 Cookie 时静默登录失败，退化为整页跳转（身份提供方仍有会话，用户不必再输入口令，只多一次跳转）。验证：`console/e2e/app/auth.spec.ts` 断言刷新后主页面不经过登录页。
- 依赖追加到 ADR-0021：`@tanstack/react-router` 1.170.46、`@tanstack/react-query` 5.105.0、`openapi-fetch` 0.17.0、`oidc-client-ts` 3.5.0。
