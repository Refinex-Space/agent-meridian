# ADR-0056 控制台能力、模型与凭据页的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-13 |
| 决策人 | T23 |
| 影响的架构设计章节 | 控制台（信息架构、技术约定）、安全架构「凭据」；`console-api-map.md`「6 能力」「8 模型」「11 设置」 |

## 背景

T23 做控制台的能力（技能、MCP 服务、自定义工具）、模型（供应商账号、模型目录、价格表）与凭据页。按 `console-api-map.md` 接口时有四处空白：

1. 技能页要展示"被哪些智能体引用"，管理 API 的 `Skill` 没有引用方；引用记录在 `cp.agent_version_refs`，只在删除被拒绝（409 `skill.in_use`）时才返回。
2. 任务要求模型的连通性测试"调用一次最小请求并展示延迟与用量"，而 T19b 的 `provider-accounts/{id}:test` 只列一次模型清单、不产生用量（ADR-0053），也测不到某个具体模型（上游模型名、覆盖的端点）。
3. 凭据"只写不读"：明文要在提交后从页面、网络响应、浏览器存储与查询缓存中消失。TanStack Query 的变更会把 `variables` 留在 `MutationCache` 里，直到垃圾回收（默认 5 分钟）。
4. 信息架构把凭据放在「设置」，设置的其余页面在 T25b。

## 候选方案

1. 技能的引用方
   - A：`Skill` 增加必有字段 `references`（`ResourceReference` 数组，与 `Secret.references` 同一结构），查看与列表都带，列表按一页的技能一次查询。
   - B：控制台读全部智能体的当前版本，自己找引用。要读 N 个版本，草稿与已发布的口径和删除检查不一致，属于前端拼凑。
2. 模型测试
   - A：供应商账号保留免费的连通性测试；模型另加"测试"，经公开的直通接口发一次最小请求（对话模型 `POST /v1/chat/completions`，`max_tokens` 16；Embedding 模型 `POST /v1/embeddings`），展示浏览器测得的延迟、回复与响应里的 `usage`。走与业务调用相同的路由、限流、预算与计量，费用计入当前项目。
   - B：control-plane 新增 `models/{id}:test`，经内部接口让 runtime 调模型。多一个管理接口、一个内部接口与 runtime 的处理器，结果与 A 相同。
3. 凭据明文
   - A：写入与轮换不经 `useMutation`，由页面的局部状态记录"提交中"与错误；输入框是非受控的密码框，提交成功或失败后都清空 DOM 中的值；不提供显示明文的开关。
   - B：用 `useMutation` 并把 `gcTime` 设为 0。提交中的那段时间明文仍在缓存里，失败时留到下一次提交。
4. 凭据页的位置
   - A：`/projects/$projectId/settings/secrets`，面包屑"设置 / 凭据"；`/settings` 暂时直接进入凭据，T25b 加其余设置页时改成设置的首页。
   - B：凭据单独作为一级导航。与架构设计的信息架构不符。

## 决策

1. 选 A。`Skill.references` 是"引用这个技能的、未删除智能体的已发布版本"，与删除检查同一查询（`AgentVersionRefRepository.referencingAll`），名称为"智能体名 v版本号"；草稿不算。新增必有的响应字段，对 v1 兼容。
2. 选 A。直通接口已有、已计量，控制台用 OIDC 令牌加 `Meridian-Project` 调用，需要 `models:invoke`（ADR-0044：所有者与项目开发者有，租户管理员没有，没有时按钮说明原因）。rerank 没有公开的直通接口，重排模型不提供测试，经知识库的检索测试验证。按钮旁的提示写明会产生少量费用、计入当前项目；供应商账号的连通性测试写明不产生用量。没有项目预算时直通接口按预算规则拒绝，结果就地显示原因。
3. 选 A。明文只存在于密码框的 DOM 值与那一次请求体中；`Idempotency-Key` 不用（凭据写入不需要重放，失败就让用户重新输入）。由 Vitest 断言提交后查询缓存与变更缓存中没有明文，Playwright 断言 DOM、网络响应与浏览器存储中没有。
4. 选 A。

另外两条页面约定：能力与模型是列表页模板加标签页，标签页对应子路由（`capabilities/skills|mcp-servers|custom-tools`、`models/providers|catalog|price-books`），刷新与分享链接停在同一个标签；技能与价格表有详情页，MCP 服务的工具清单与副作用标注在详情页。技能包在浏览器中按服务端相同的规则解析与预览（frontmatter 用 `yaml` 2.9.1 解析，ADR-0021），不支持 zip，选择文件夹或多个文本文件，忽略以 `.` 开头的路径。

## 影响

- 管理 API：`Skill` 增加 `references`；control-plane 的 `SkillService.get`/`list` 返回 `SkillView`，`AgentVersionIT` 覆盖查看、列表与智能体删除后清空。
- 控制台：`features/capabilities`、`features/models`、`features/settings` 的凭据页；新依赖 `yaml`。`console-api-map.md` 的「6 能力」「8 模型」「11 设置·凭据」随之更新，「8 模型」加上直通接口。
- 风险：模型测试会产生真实费用（每次至多十几个 token），只在用户点击时发生；租户管理员不能测试模型（没有 `models:invoke`），需要时由所有者授予项目开发者角色或自己测试。
