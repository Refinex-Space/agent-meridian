## 背景

T12a 把 T11 的沙箱驱动变成会话级能力：`SandboxService` 获取、空闲回收、产物同步、技能投影，`bash` 工具，计量与审计，并在本机 kind 集群上验证 P4（`sandbox` 档）、P6（bash 规则）、P9。架构设计规定了这些行为，落地时遇到以下没有写到的细节（AgentScope 2.0.4 已核实）：

- **沙箱文件系统的路径。** `BaseSandboxFilesystem` 把路径原样拼进 shell 命令；平台工具用以 `/` 开头、相对工作区根的路径（`/reports/q3.md`），原样执行会落到容器根目录（只读）。`CompositeFilesystem` 列工作区根时向主文件系统传 `/`，在沙箱里列出的是容器根。沙箱的 `glob` 是 `find -name`，只比较文件名，与 `none` 档 `RemoteFilesystem` 的路径 glob 不同。
- **共享实例上的沙箱绑定。** `SandboxBackedFilesystem` 在调用上下文没有本次绑定的沙箱（`SandboxAcquireResult`）时，退回到同一智能体实例上最后绑定的沙箱，而实例被多个会话共享；直接调用工具（恢复确认的重试）不经过 harness 的沙箱生命周期，上下文里没有绑定。
- **缺少外部沙箱时 harness 会自建沙箱。** `HarnessAgent` 在 `RuntimeContext` 没有 `SandboxContext` 时退回装配时的默认上下文，`SandboxManager` 用规范里的客户端认领新沙箱（不打会话标签、不落库、每次调用后删除）。
- **超时。** 2.0.4 的扩展不把命令超时传给执行服务（ADR-0036）。
- **复合命令的规则。** 权限引擎对 allow、ask、deny 三类规则都调用同一个 `matchRule`，只能表达"一条规则匹配所有段"；`true && rm -rf x` 不会命中 `bash(rm:*)` 拒绝规则，`git status && git diff` 也不会被两条放行规则共同放行。
- **沙箱命令的审计。** 账本的 `tool.executed` 只有工具名，没有命令与退出码。
- **快照的保留。** 登记事项 D35：快照对象没有清除。
- **回收与新轮次的竞争、回收时的失败顺序。**
- **"记住此决定"。** T08 记整工具规则；对 `bash` 意味着批准一条命令就放行之后的全部命令（登记事项 D21）。

## 决策

1. **获取与注入。** runtime 的 `SandboxService.prepare` 在调用内核之前、`sandbox` 档每一轮执行：在会话行锁（`FOR UPDATE`）内，已有沙箱用 `resume` 重新连接，已不存在或没有沙箱时从 `sandbox_snapshot_key` 恢复（快照对象也不在时新建），否则从预热池认领；状态与 Pod IP 落库、`sandbox_last_used_at` 记为当时，同一事务提交。事务失败时删除刚认领的沙箱。内核经 `SandboxStatePort.find` 读出它（`TurnSandboxes`），用驱动的 `attach` 取得 `SingleStartSandbox`，以 `SandboxContext.builder().externalSandbox(...)` 放进本轮的 `RuntimeContext`。基础设施暂时不可用时 runtime 不调用内核，本轮以 `session.error(retryable)` 加 `status_rescheduled(retryable_error)` 置回队列；内核读不到或连不上沙箱时抛 `SandboxUnavailableException`，结果相同。没有配置沙箱集群时 `sandbox` 档的轮次以错误结束。
2. **装配。** `filesystem(KubernetesFilesystemSpec)` 的客户端是 `PlatformManagedSandboxClient`，一律拒绝创建与恢复，缺少外部沙箱时以异常结束而不是多出沙箱；工作区投影关闭；路由为受保护路径与 `large_tool_results/`。平台工具使用的文件系统由装配器以同一组路由重建 `RoutedSandboxFilesystem`，主文件系统外包 `SandboxWorkspaceFilesystem`：平台路径翻译为 `/workspace/…`（结果翻译回来），`glob` 按 `RemoteFilesystem` 的语义在列出的文件上过滤，调用上下文没有本次绑定的沙箱时拒绝。恢复确认的重试直接调用工具，内核把会话沙箱作为 `SandboxAcquireResult.userManaged` 放进上下文。工作区根由镜像固定为 `/workspace`。路由会剥离目录前缀，`large_tool_results/` 之下的文件在会话命名空间的平台存储中以剥离后的键保存。
3. **`bash`。** 只在 `sandbox` 档注册（工厂对 `none` 档返回 null）。命令前缀规则：复合命令（`&&`、`||`、`;`、`|`、`|&`、`&`、换行）在引号外分段，`matchRule` 要求每一段都匹配；含命令替换、进程替换、反引号、子 shell 括号或未闭合引号的命令不匹配任何内容级规则。`checkPermissions` 补上复合命令的语义：任一段命中拒绝规则即拒绝、命中询问规则即询问（剥离开头的环境变量赋值与 `env`、`nice`、`nohup`、`time`、`timeout`、`command`、`exec`、`xargs`、`sudo` 及其选项后再比较），每一段被某条放行规则覆盖即放行；看不出会执行什么的命令在存在内容级拒绝规则时询问；`DONT_ASK` 下询问改为拒绝。询问的理由带 `safety`，2.0.4 的权限引擎对这类工具判定不再查放行规则。机制参考 Claude Code（只学机制）。命令以 `timeout -k 5 <秒> bash -c '<命令>'` 执行，默认 120 秒、最多 600 秒，超时退出码 124；输出上限 30000 字符，超出时保留头尾；只有空白的输出显示 `(no output)`；非零退出码附在结尾，是正常结果而不是工具错误。
4. **审计。** `ToolLedgerPort` 增加 `recordSandboxCommand`：每条 `bash` 命令执行后写审计 `sandbox.command`（命令原文至多 4096 字符、是否截断、退出码、是否超时、耗时、会话、线程、轮次、工具调用），不受租约约束（命令已经执行），写入失败只记 ERROR，不让模型误以为没有执行。文件工具在沙箱内执行的辅助命令不单独审计（写类调用已有 `tool.executed`）。
5. **技能资源。** `SandboxDriver.syncSkills`：把智能体版本引用的技能除 `SKILL.md` 之外的文件写到 `/workspace/.meridian/skills/{技能名}/`（正文仍经 `load_skill_through_path`）。每轮开始时比较摘要，一致就不写；摘要与沙箱内 `find . -type f -print0 | LC_ALL=C sort -z | xargs -0 -r sha256sum | sha256sum` 的输出逐字节一致，平台按同一算法计算，所以被改动、被删除、多出文件或换成符号链接都判为不一致，此时 `rm -rf` 后用 tar（commons-compress，随 `agentscope-core` 引入）经 `hydrateWorkspace` 写入。没有技能时期望目录不存在。
6. **产物。** `SandboxDriver.listOutputs` 用沙箱镜像中的 Python 列出 `outputs/` 下的普通文件（不跟随符号链接）与 SHA-256，`readOutput` 经文件接口读取。每轮以 `status_idle` 或 `status_requires_action` 结束之前，`SandboxService` 按 `rt.sandbox_outputs` 的清单镜像同步到 `rt/outputs/{tenant}/{project}/{session}/{path}`：新增或变化的上传、沙箱里删除的副本也删除；单文件超过 64 MB（`output-max-file-size`）不同步并删除旧副本（驱动把文件整个读进内存）。置回队列的轮次不同步。同步失败只记日志，下一轮重试。同一会话两个线程同时结束时后写者生效。
7. **空闲回收。** `IdleSandboxReaper` 每 60 秒扫描 `sandbox_last_used_at` 早于"当前减 10 分钟"的会话（`infra.system`，`@CrossTenant`），逐个交给 `SandboxService.reclaim`：`FOR UPDATE SKIP LOCKED` 锁住会话行（锁不到就跳过），重新判定空闲与"没有 `queued`、`running`、`awaiting_action` 的轮次"，然后快照、删除沙箱、清空沙箱与 Pod IP、记下快照键，同一事务提交；行锁一直持有到提交，单个沙箱操作的等待上限是 `operation-timeout`。获取沙箱也要这把行锁，所以回收先拿到锁时新轮次等它提交后从快照恢复，新轮次先拿到锁时回收跳过。删除在提交之前：删除失败时事务回滚，沙箱仍在、状态一致，下次再回收；先提交再删除则删除失败会留下无人管理的沙箱。快照时发现沙箱已不存在则清空状态、保留原快照。
8. **快照的保留（D35 的回收部分）。** 每个会话至多保留一个快照：新快照提交后删除被取代的旧快照。恢复之后不立即删除用过的快照，它是沙箱在下一次回收之前意外消失时的恢复来源。删除会话时（`deleteSessionSandbox`，T17a 调用）删除沙箱并按前缀清除快照与产物。
9. **表结构。** `sessions.sandbox_state` 存 `{"sandbox_id", "size", "state"}`（`state` 为驱动序列化的状态，规格用于计量）；新增 `sandbox_snapshot_key`、`sandbox_metered_at`；新表 `sandbox_outputs`（主键 `(session_id, path)`）。
10. **计量。** vCPU 秒 = 沙箱存活时间 × 规格的 vCPU 数（1、2、4），按"已计量到的时间"分段记录：每轮结束时计到当时（带线程与轮次），回收、沙箱意外消失、删除会话时计最后一段。用量写 outbox `usage`，种类 `sandbox_vcpu_seconds`，字段见 `SandboxUsageMessage`（`vcpu_seconds` 保留三位小数）。
11. **指标。** `meridian_sandbox_claim_seconds`（Micrometer `meridian.sandbox.claim`，直方图）只计从预热池认领；从快照恢复含归档传输，不计入。
12. **"记住此决定"（D21 的 bash 部分）。** `bash` 的确认结论记住这一条命令：规则内容为命令原文（不带 `:*`，整条命令相同才匹配），不再记整工具规则；复合命令按原文记下也不会匹配，等于不放行。其他工具仍记整工具规则；内核随待处理动作带出工具建议（命令前缀、路径）要改事件载荷与 `pending_actions`，留在登记事项 D21。
13. **配置。** 前缀 `meridian.runtime.sandbox`：`enabled`（默认关闭）、`kube-context`、`connection`（`port-forward`、`direct` 加 `router-url`、`gateway`）、`idle-timeout`、`reap-interval`、`reap-batch-size`、`operation-timeout`、`bash-default-timeout`、`bash-max-timeout`、`exec-timeout`、`output-max-file-size`。

## 候选方案

**回收与新轮次的串行方式**

- A（采纳）：回收在会话行锁内完成判定、快照与删除。正确性只依赖一把锁；代价是持锁期间同一会话的事件写入等待，只发生在空闲会话被回收时。
- B：两阶段（先标记"回收中"再在锁外快照），新轮次遇到标记时等待或置回。少持锁，但要多一个状态与等待协议，崩溃后还要清理标记。

**每轮的沙箱如何交给内核**

- A（采纳）：runtime 落库，内核经 `SandboxStatePort.find` 读。沿用架构设计已定义的端口，`TurnContext` 不变。
- B：`TurnContext` 带沙箱句柄。少一次查询，但改变既有契约的构造参数。

**bash 的复合命令语义**

- A（采纳）：`matchRule` 逐段全匹配，拒绝、询问与多规则放行在 `checkPermissions` 中补上。
- B：只用 `matchRule`。拒绝规则可以被 `true &&` 绕过。

**"记住此决定"**

- A（采纳）：runtime 对 `bash` 记命令原文。不改事件与表，立即消除"批准一条放行全部"。
- B：内核随动作带出建议规则（D21 的完整做法）。要改 `session.status_requires_action` 的载荷与 `pending_actions`，超出本任务。

## 影响

- 架构设计：「端口」表 `ToolLedgerPort` 与 `SandboxDriver` 的用途、「核心表」的 `sessions` 与 `sandbox_outputs`、「引擎装配」文件系统行、「平台工具」bash、「会话沙箱」、「计量与预算」补充；版本升至 v1.13。
- 新增：engine-agentscope 的 `BashTool`、`ShellCommands`、`fs.SandboxWorkspaceFilesystem`、`sandbox.TurnSandboxes`、`SandboxAttachment`、`PlatformManagedSandboxClient`、`SkillProjection`；runtime 的 `sandbox` 上下文（`SandboxService`、`DatabaseSandboxStates`、`IdleSandboxReaper`、`SandboxProperties`、仓储与领域类型）、`config.SandboxConfiguration`、迁移 `V0006`；内置技能 `skills/builtin/docx`。
- 风险：回收与获取在行锁内执行远程操作，大工作区的快照或恢复期间同一会话的事件写入等待（P5：100 MB 约 3 至 5 秒）；产物同步与快照都把文件读进内存，runtime 的堆按 `output-max-file-size` 与工作区上限估算（D36）；`sandbox.command` 审计写入失败只记日志。
