# ADR-0053 控制台所需后端接口的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-13 |
| 决策人 | T19b |
| 影响的架构设计章节 | API 设计（资源）、消息投递与待处理动作（"记住此决定"）、安全架构（认证、授权）、计量与预算、知识库架构（对外形态）、控制台、数据架构（核心表） |

## 背景

T19b 按控制台的十一个一级导航倒推接口（对照表 `docs/engineering/console-api-map.md`），发现以下缺口，架构设计没有写到：

- **概览与智能体页的聚合。** 运行中的会话数、待处理动作数、按智能体的失败率（时间窗）、最近错误、"删除后该智能体的 N 个会话将无法继续"的 N。会话只记了智能体版本，没有智能体 ID；轮次表没有按结束时间的索引。
- **项目级的待处理动作。** 只有按会话列出的接口；历史里看不到结论与处理人。
- **审批人不能审批。** 角色矩阵给审批人 `PENDING_ACTION_DECIDE`，但公开 API 上它没有对应的作用域，回应事件要 `sessions:write`，审批人只有 `sessions:read`。
- **OIDC 下添加成员。** 成员按用户标识（`sub` 等）识别，管理员通常只知道同事的邮箱，不知道 IdP 中的用户 ID。
- **控制台怎么知道当前用户能做什么。** 角色矩阵只在服务端，`PermissionGate` 需要它。
- **预算消耗。** 预算与告警是租户级的 `BUDGET_READ`，项目开发者与观察者在概览上看不到本项目的预算状态。
- **登记事项。** D21（建议规则）、D68（用量明细与 CSV）、D72（Webhook 签名密钥轮换、投递记录的时间范围）、D81（知识库的修改与删除）。
- **连接状态。** 供应商账号没有连通性测试，MCP 服务的探测失败不留痕迹。

## 候选方案

**概览的聚合**

- A：每次请求从 `rt.turns` 现算。7 天的时间窗在繁忙的项目上要扫十万级的行。
- B：轮次结束时在同一事务里累加计数。同一智能体的轮次结束会争用同一行，拖慢主路径。
- C（采纳）：计数类（执行中、等待回应的会话，待处理动作，使用中的会话）走新的部分索引现读；失败率读小时汇总表 `rt.agent_turn_stats`，由后台作业 `TurnStatsRollup` 每分钟按水位累加（跨租户的 `SystemRepository`，多节点经水位行锁串行，汇总到"当前时间减 10 秒"以覆盖结束事务的提交延迟）；最近错误读只收录失败轮次的部分索引，错误码与信息取该轮的 `session.error` 事件。

**审批人的回应**

- A：新增 `POST /v1/pending-actions/{id}:respond`。回应就有两条路径，事件不再是唯一入口。
- B（采纳）：新增 API Key 作用域 `actions:respond`，对应 `PENDING_ACTION_DECIDE`（审批人与所有者）。`POST /v1/sessions/{id}/events` 接受 `sessions:write` 或 `actions:respond`；只有后者时，一批事件必须全是回应事件（`user.tool_confirmation`、`user.custom_tool_result`、`user.recovery_confirmation`），否则 403 `auth.insufficient_scope`。业务系统也可以为独立的审批系统签发只带这个作用域的 Key。

**OIDC 下的成员**

- A：经 IdP 的管理接口按邮箱查用户 ID。要为每家 IdP 写专有接口，违背"只认标准 OIDC"（ADR-0043）。
- B（采纳）：成员可以只给邮箱（`subject` 为空，状态 `invited`），角色照常授予。用户带 OIDC 令牌访问任一管理接口时（控制台启动时先调 `GET /admin/v1/me`），`DatabaseGrantSource` 先用令牌中经过验证的邮箱（`email` 声明，默认要求 `email_verified` 为真，声明名与是否要求验证可配置）找各租户未绑定的邀请并写入用户标识；该用户在这个租户中已是成员时，邀请的角色合并过去、邀请删除。审计 `member.bound`。邮箱比较不区分大小写，同一租户同一邮箱只有一条未绑定的邀请（cp `V0008` 的部分唯一索引）。创建租户时首个所有者同样可以只给邮箱。未验证的邮箱不绑定：否则用户把邮箱改成别人的就能拿到别人的邀请。

**当前用户的权限**

- A：前端复刻角色矩阵。两处定义会漂移。
- B（采纳）：`GET /admin/v1/me`（身份、平台管理员、成员身份与角色绑定）与 `GET /admin/v1/me/access?tenant_id=&project_id=`（按同一套 `AccessContext` 算出的操作类别与公开 API 作用域）。任何已认证的用户都可以调用，没有角色时返回空列表；操作类别的取值在规范中是枚举，`PermissionNamesTest` 守住它与 `security.rbac.Permission` 一一对应。

**项目的预算消耗**

- 采纳：`GET …/projects/{id}/budget-status`（`USAGE_READ`）只给本项目：生效的项目级阈值（本项目的设置 → 项目级默认值 → 都没有时硬阈值 0）、来源、本月已用（`cp.budget_usage`）与状态（`ok`、`soft_exceeded`、`hard_exceeded`）。租户级的消耗仍只对租户所有者与管理员可见。

**建议规则（D21）**

- 2.0.4 的 `PermissionEngine` 在 ask 时调用 `generateSuggestions` 并附在 `PermissionDecision` 上，但 `ReActAgent` 只保留结论的行为、丢掉了建议，事件里拿不到。
- 采纳：内核在产生 `tool_confirmation` 动作时按工具名在本实例的 Toolkit 中找到工具，再调用一次 `generateSuggestions`，只取针对该工具、有内容的规则，放进 `PendingAction.suggestedRules`（随 `session.status_requires_action` 与 `pending_actions.payload` 保存，公开 API 带出 `suggested_rules`）。`user.tool_confirmation` 新增可选的 `remember_rule`，必须是该动作的建议之一（否则 400），记住时用它代替原来的规则（一般工具记整工具，`bash` 记整条命令）；不给时行为不变。

**其他**

- 会话记下 `agent_id`（rt `V0012`，创建时取自解析出的版本）；之前的会话为空，按智能体的筛选与统计不含它们。
- 用量明细 `…/usage-records` 与 CSV 导出 `…/usage-records:export`（租户级 `BUDGET_READ`，项目级 `USAGE_READ`），时间范围规则与报表相同（`UsageRange`），导出至多 100000 行，超过 400 `usage.export_too_large`。
- 供应商账号的连通性测试 `POST …/provider-accounts/{id}:test`（`MODEL_WRITE`）：按类型列一次模型清单，不产生用量；连不上、凭据无效是结果（`unreachable`、`auth_failed`）而不是错误响应。结果与 MCP 服务的探测结果都记在各自的 `last_check`（cp `V0009`），MCP 的重新探测失败时清单不变、`last_check` 为 `error`。
- Webhook 签名密钥轮换 `POST …/webhooks/{id}:rotate-secret`（`API_KEY_WRITE`）：立即替换，ID 不变，新密钥只在响应中出现一次；不保留旧密钥的过渡期，接收方要先接受新密钥。
- 知识库的修改与删除（`knowledge:write`）：删除级联文档、切片、作业与存储计量记录，提交后按前缀删除原文件。不检查引用：知识库在 knowledge，引用在 control-plane 的已发布版本里，检查要跨服务同步调用；引用它的智能体之后检索得到"知识库不存在"的工具错误。
- 生成的 DTO 枚举作为查询参数时按规范取值转换（`ApiEnumConverterFactory`）：从 runtime 移到 `meridian-security`，MVC 服务同样注册（`kind=model_tokens`、`level=project` 之前按 Java 常量名转换会 400）。

## 决策

按上面各项的"采纳"执行。都是新增的接口、字段、表与作用域，没有改变已有接口的语义；"记住此决定"在不给 `remember_rule` 时与之前相同。

## 影响

- 架构设计 v1.27：「API 设计」资源表补会话筛选与 `session-stats`、项目级待处理动作、知识库的修改与删除、管理类资源的新接口；「待处理动作」补建议规则；「认证」「授权」补邮箱邀请、`actions:respond`；「计量与预算」补明细与项目预算消耗；「控制台」指向对照表；「核心表」补 `agent_turn_stats`。
- 迁移：rt `V0012`（`sessions.agent_id`、部分索引、`agent_turn_stats`、`stats_watermarks`），cp `V0008`（成员邀请）、`V0009`（`last_check`）。
- 主路径的额外开销：会话行与轮次行更新时多几个索引的维护（部分索引只收录少量行）；后台作业每分钟一次、按水位只读新结束的轮次。
- 风险：按邮箱绑定依赖 IdP 对邮箱的验证；不发 `email_verified` 的 IdP 关闭验证要求前要确认邮箱由企业目录保证。删除知识库不检查引用（见上）。验证：`ConsoleQueriesIT`、`MemberInvitationIT`、`UsageReportIT`、`BudgetIT`、`ConnectivityIT`、`WebhookAdminIT`、`KnowledgeApiIT`、引擎的 `BashToolScenarioTest`、`FileToolScenarioTest` 与角色矩阵 `RoleMatrixIT`。
