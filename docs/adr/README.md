# 架构决策记录

ADR（Architecture Decision Record）记录一项架构决策：当时面对什么问题、考虑过哪些方案、最终选了什么、要付出什么代价。它让一年后接手的人能看懂代码为什么是现在这个样子。

## 什么时候必须写 ADR

以下变更必须先提 ADR，评审通过后修改[架构设计](../architecture/architecture.md)，再改代码：

- 新增或替换技术基线中的组件，或升级其大版本。
- 新增部署单元。
- 修改模块依赖规则或端口。
- API 的破坏性变更。
- 修改架构设计中任何"必须"或"禁止"条目。
- M0 验证项不通过，需要调整方案。

## 流程

1. 复制 [template.md](template.md) 为 `NNNN-短标题.md`，编号取下表最大值加一，状态写"提议"。
2. 提交 PR，PR 只包含这一个 ADR 文件，至少一位架构负责人评审。
3. 通过后状态改为"已采纳"，在同一个 PR 里修改架构设计的相关章节和"架构决策记录"表，并递增架构设计的版本号。
4. 被新决策取代的 ADR 不删除，状态改为"已被 ADR-NNNN 取代"。
