## 背景

`frontend-design.md`「组件与依赖选型」定了每类能力用什么库，版本留给 T20a 与 T21 确认：取最新稳定版，且发布至少两周。T20a 在 2026-11-13 建立 `console/` 工程，截止日期取 2026-10-30：只采用这一天及以前发布的版本，之后的补丁版本（例如 Vite 8.3.8、Prettier 3.10.1）等下一次升级。

查询方法：`npm view <包> time dist-tags`，在发布时间不晚于截止日期的正式版本（`x.y.z`，不含预发布）中取最高版本，再核对相互之间的 peer 范围。

## 候选方案与取舍

有六处没有直接取"最新稳定版"，或在两种做法之间做了选择：

**TypeScript：7.0.2 还是 6.0.3。** 7.0 是 Go 实现的原生编译器，最新稳定版。typescript-eslint 8.72.1（最新稳定版）的 peer 范围是 `typescript >=4.8.4 <6.1.0`，类型感知的 lint（`recommendedTypeChecked`、`no-floating-promises` 等）在 7.0 上不受支持。采纳 6.0.3（6.x 的最新版）；typescript-eslint 支持 7.x 后再升级。

**ESLint：10.14.0 还是 9.39.5。** ESLint 9 已标为"不再支持"（npm 的 deprecated 说明）。eslint-plugin-jsx-a11y 6.10.2（最新版，2024 年发布）的 peer 范围只写到 ESLint 9，但它没有使用 ESLint 10 移除的 API（`context.getSourceCode` 等）；在 ESLint 10 下逐条写入 `<img>` 缺 `alt`、带点击的 `<div>` 等违规代码，`jsx-a11y/alt-text`、`click-events-have-key-events`、`no-static-element-interactions` 都正常报错。采纳 10.14.0，在 `pnpm-workspace.yaml` 的 `peerDependencyRules.allowedVersions` 中显式放行这一处 peer。

**pnpm：12.17.0 还是 10.34.9。** pnpm 11 起以原生可执行文件分发，`pnpm` 入口是一个 sh 垫片。本机全局的 pnpm 10 按 `packageManager` 字段切换版本时直接 `spawn` 这个垫片，macOS 上得到 `ENOEXEC`（垫片自己的注释写明了这一点），`pnpm -C console …` 无法运行。采纳 10.x 的最新版 10.34.9；各机器与 CI 的全局 pnpm 升级到 11 以上后再改 `packageManager`。

**IBM Plex Sans SC 的切片：cn-font-split 还是官方切片。** `frontend-design.md` 以 cn-font-split 为例。它的 postinstall 从 GitHub 下载原生库，版本取"最新发布"而不锁定，离线与内网构建会失败。`@ibm/plex-sans-sc` 本身带按字频切好的 216 片 woff2 与每个字重的 `unicode-range` 样式表：常用字集中在少数切片里，一段 136 个常用汉字的控制台文案只命中 11 片。采纳官方切片：`src/styles/fonts.css` 只引用 400、500、600 三个字重的样式表，构建产物只含这三个字重，浏览器按 `unicode-range` 只下载用到的切片。代价是样式表较大（三个字重共 648 条 `@font-face`，构建后的 CSS 压缩前 516 KB、gzip 163 KB），这是按字频切片的 `unicode-range` 列表决定的，与 Google Fonts 的中文字体相当。另外，`@ibm/plex-sans-sc` 的 postinstall 是 IBM 的遥测上报，`pnpm-workspace.yaml` 的 `ignoredBuiltDependencies` 不允许它执行。

**导入边界：eslint-plugin-boundaries 还是自写规则。** boundaries 7 改为基于"策略"的配置，"跨领域只能经对方的 `index.ts`"需要它的捕获选择器。自写的 `meridian/import-boundaries`（`console/eslint-rules/meridian.js`）约 80 行：按路径判断分层，跨领域只允许导入 `features/<领域>` 或其 `index`，有 RuleTester 测试。采纳自写规则，少两个依赖（boundaries 与 import 解析器）。

**UI 基元：shadcn CLI 还是取上游源码。** T20a 只需要按钮、徽标、标签页、提示、滚动区域、骨架六个基元；`shadcn init` 会改写 `index.css` 并加入 lucide-react 与 tw-animate-css。T20a 从 shadcn/ui 的注册表（new-york-v4）取这六个组件的源码，按令牌重塑，文件头写明与上游的差异；T20b 生成其余基元时用 CLI，生成后同样重塑并检查 `index.css` 没有被改写。

其余两点：`@types/node` 取与运行时一致的 24.x 的最新版（不是 26.x）；openapi-typescript 7.13.0 的 peer 写的是 `typescript ^5.x`，在 6.0.3 下生成的类型与预期一致（`gen:api --check` 守住），同样在 `allowedVersions` 中放行。

## 影响

- 架构设计不改：技术基线中控制台一行列的是组件，不含版本。
- `frontend-design.md`「字体」中"例如用 cn-font-split"改为官方切片的做法，见「设计定稿」。
- 升级时按同一规则重新查询并改本表；依赖只在 `console/package.json` 声明并锁定版本。
- 风险：jsx-a11y 与 openapi-typescript 的 peer 放行依赖人工核对，升级 ESLint 或 TypeScript 时重新验证（RuleTester 测试、`gen:api --check`、写入违规代码看 lint 是否报错）。
