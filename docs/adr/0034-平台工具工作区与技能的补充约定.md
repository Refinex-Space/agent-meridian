# ADR-0034 平台工具、工作区与技能的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-08 |
| 决策人 | T10a 执行会话 |
| 影响的架构设计章节 | 「身份映射」、「引擎装配」中的 `messageBus` 与 `skillRepository` 两行、「平台中间件」中的 `PolicyMiddleware`、「平台工具」、「文件系统装配」、「端口」（只补充，不改既有条款） |

## 背景

T10a 实现平台工具基类、六个文件工具、`none` 档工作区与技能仓库。架构设计规定了工具必须继承 `ToolBase` 并实现 `matchRule`、文件系统的装配方式、受保护路径只读、命名空间从 `PlatformContext` 取、`PolicyMiddleware` 的职责，落地时遇到以下没有写到或与 2.0.4 实际行为有出入的细节：

- **命名空间的终端用户。** 命名空间 `[tenant_id, project_id, end_user_id, session_id]` 的四个值必须从 `PlatformContext` 取，但 `PlatformContext` 没有终端用户字段（「身份映射」的类型键一行没有它）。
- **`wait_async_results` 是 `ToolBase`。** 「引擎装配」写"它不是 `ToolBase`，不进权限引擎，由 `PolicyMiddleware` 直接拦截"。2.0.4 中它是 `@Tool` 注解的方法，`Toolkit` 把它包装为 `ReflectiveFunctionTool`（继承 `ToolBase`），会进权限引擎：`DEFAULT` 模式下没有 allow 时默认 ask，`BYPASS` 下放行。
- **`onActing` 中间件的事件不发布。** 2.0.4 的 `acting()` 只从中间件链返回的流里找 `RequestStopEvent`，事件经 `actingStream` 内部的 `publishEvent` 发出；中间件自己合成的 `ToolResult*Event` 不进入事件流，也就没有 `agent.tool_result` 与 `permission.decided` 审计。2.0.4 没有公开的事件发送接口。
- **技能资源会写本机磁盘。** harness 的 `MarketplaceStager` 每次构建系统提示词都把非 `WorkspaceSkillRepository` 仓库的技能资源写到本机工作区的 `.skills-cache/<用户>/` 下（登记事项 D05）；只有 `WorkspaceSkillRepository` 被视为"工作区原生"而不暂存。
- **先读后改的状态放在哪里。** Claude Code 把读取状态放在进程内存；平台的一轮可能在任意节点执行，下一轮也可能换节点。
- **记账、指标与审计的落点。** 每个平台工具调用都要记账、计数、审计；engine-agentscope 没有 Micrometer，审计走 runtime 的 outbox。
- **生产装配之后的 API 测试。** T10a 补齐了内核的四个生产提供者，runtime 在任何环境都会装配内核并认领轮次；原来"只入队、不执行"的 API 集成测试与只提供 API 的节点需要关闭 Worker 的办法。

## 候选方案

**终端用户**

- A：命名空间从 `RuntimeContext.userId`（`{project}:{end_user}`）解析终端用户。违反"四个值必须从 `PlatformContext` 取"。
- B（采纳）：`PlatformContext` 增加可选的 `endUserId`，Worker 构造轮次上下文时从会话填入。

**`wait_async_results` 与工具集外的工具**

- A：`PolicyMiddleware` 在 `onActing` 中合成 DENIED 结果。结果能写进状态，但没有事件与审计（见背景）；依赖 `ReActAgent` 私有的 Reactor Context 键发事件过于脆弱。
- B（采纳）：工具策略生成整工具的拒绝规则（`wait_async_results`，以及注册了但不在智能体工具集内的平台工具与 MCP 工具），引擎每轮安装权限时并入合成结果，由权限引擎给出标准的 DENIED 结果（有事件、有审计，模型看到拒绝）。`PolicyMiddleware` 保留为非 `ToolBase` 工具的守卫：只放行 `load_skill_through_path`，否则本轮以错误结束（失败关闭）。装配自检保证 Toolkit 中没有别的非 `ToolBase` 工具。

**技能仓库**

- A：`MeridianSkillRepository` 直接实现 `RuntimeContextSkillRepository`。技能资源每轮写本机磁盘。
- B（采纳）：继承 2.0.4 的 `WorkspaceSkillRepository`（它实现 `RuntimeContextSkillRepository`），读取受保护路径 `skills/` 的只读视图；视图内容在装配时经 `AgentConfigPort.skill` 按智能体版本引用的技能版本生成。技能文件同时可以用 `read_file` 读取，`MarketplaceStager` 不暂存。

**先读后改**

- A：进程内存。换节点后必须重读，跨轮的常见用法（上一轮读、这一轮改）多一次失败。
- B：单独的表。新增数据与写入路径，只为一个检查。
- C（采纳）：读取状态随工具结果保存。`read_file`、`write_file`、`edit_file` 的结果元数据带 `meridian_file`（路径与整文件内容的 SHA-256），元数据不发给模型，随 `AgentState` 受租约约束地持久化；修改前在本线程上下文中从新到旧查找，与文件当前内容比较。压缩之后记录消失、需要重读——此时模型确实已看不到内容。

## 决策

采纳以上各项的 B 或 C，另有以下约定：

1. **工具基类。** `PlatformTool` 的子类声明名称、英文描述、入参 schema、副作用等级与规则内容语法（`RuleSyntax`：路径 glob、命令前缀 `prefix:*`、域名 `domain:<host>`（含子域名）、资源 ID、无）。`matchRule` 在规则内容为空时匹配全部调用；`generateSuggestions` 给出内容级的建议规则（路径、命令前缀等）。基类经 `HarnessAgent.getWorkspaceManager().getFilesystem()` 取文件系统（装配后 `attach`），调用时传入 `ToolCallParam.getRuntimeContext()`。
2. **路径。** 规则与工具的路径一律相对工作区根，不带开头的 `/` 与 `./`，不含 `..`；`**/x` 也匹配根下的 `x`，`dir/**` 也匹配 `dir` 本身。`grep_files` 按搜索目录做权限判定，命中的文件再按它自己的拒绝规则过滤（平台安全规则因此对目录级搜索有效）。
3. **账本。** 幂等键对所有平台工具都是 `session_id:tool_use_id`（恢复确认重试时为 `ToolRetryContext` 中的原键）；`non_idempotent` 工具把它传给下游，结果写入对象存储、引用进账本（登记事项 D14）。调用被取消时尽力把账本记为 `interrupted`。指标 `meridian_tool_calls_total`（`tool`、`state`）与审计 `tool.executed`（只对 `idempotent`、`non_idempotent`）由 runtime 的账本实现在记录结束时写出，审计与账本同一事务。
4. **策略拒绝规则只在策略非平凡时并入。** 2.0.4 对平凡的权限上下文（`DEFAULT`、没有规则）一律放行；runtime 合成的策略总带平台安全规则（ADR-0031），从不平凡，所以生产中拒绝规则总会并入；平凡策略只出现在内核测试中。
5. **工作区存储。** `WorkspaceStorePort` 的值序列化为 JSON，不超过 64 KB 内联在 `rt.workspace_entries`，否则写进对象存储（`rt/{tenant}/{session}/workspace/{ulid}`，与会话的其他大对象同一前缀），表中存键；对象先写、行后更新，版本不匹配时删除新对象，成功后删除被替换的对象。租户与项目取自命名空间前两段，实现继承 `SystemRepository`（「租户隔离」列出的端口实现豁免）。`search` 含子命名空间、按键分页，迁移 `V0005` 为会话前缀建索引。
6. **覆盖写入。** `RemoteFilesystem.write` 只在文件不存在时成功；`write_file` 覆盖已有文件时先做先读后改的检查，再经 `uploadFiles`（最后写入者胜）写入，不是原子的比较并交换。`edit_file` 经 `RemoteFilesystem.edit`，以版本号做乐观并发。
7. **受保护路径的内容。** `AGENTS.md` 为智能体层的系统提示词；`skills/<name>/` 为技能文件；`subagents/<name>.md` 为子智能体（frontmatter 为名字、说明、工具、轮数，正文为提示词）；`tools.json` 为启用的平台工具与 MCP 服务（只是说明，`disableToolsConfig` 下 harness 不读）；`MEMORY.md` 一期为空。
8. **本机工作区根（D05）。** 装配时 `workspace(...)` 设为平台控制的目录（`meridian.runtime.workspace.local-root`，默认在系统临时目录下），平台不在其中写入；`none` 档的 P4 测试断言会话之后它仍不存在、`${user.dir}/.agentscope` 没有新文件。
9. **技能来源。** `AgentConfigPort.skill(SkillRef)` 返回 `SkillDefinition`（`SKILL.md` 与资源）；开发实现读 `dev-config/skills/<skill_id>/v<version>/`，技能名取 `SKILL.md` frontmatter 的 `name`，必须与智能体版本的引用一致。T15b 起由 control-plane 下发。
10. **启动自检（D02）。** 每次装配后检查 Toolkit：白名单外的非 `ToolBase` 工具让装配失败；runtime 启动时用探测对象（全部平台工具、计划模式、`none` 档、占位模型）装配一次，失败则启动失败。白名单只有 `load_skill_through_path`。"平台工具继承 `PlatformTool`"由 ArchUnit 规则 13 检查生产代码。
11. **Worker 开关。** `meridian.runtime.worker.enabled`（默认 `true`）为 `false` 时不装配内核与 Worker，节点只提供 API；只测 API 的集成测试用它保持"只入队、不执行"。

## 影响

- 架构设计：「身份映射」的类型键一行加终端用户；「引擎装配」的 `messageBus` 与 `skillRepository` 两行改为 2.0.4 的实际情况；「平台中间件」的 `PolicyMiddleware` 一行写明两处落地；「平台工具」补路径约定、账本、指标与审计；「文件系统装配」补受保护路径内容、本机工作区根与存储细则；「端口」表补 `AgentConfigPort.skill`；版本升至 v1.10。
- 代码：common 的 `PlatformContext.endUserId`；engine-spi 的 `SkillDefinition`、`AgentConfigPort.skill`、`ResolvedAgentSpec.grants`；engine-agentscope 新增 `tools`（`PlatformTool`、`RuleSyntax`、六个文件工具、`PlatformToolProvider`）与 `fs`（`MeridianBaseStore`、`ReadOnlyFilesystem`、`ProtectedContent`、`MeridianSkillRepository`、`PlatformWorkspace`、`WorkspaceNamespaces`）、`assembly.ToolPolicy`、`middleware.PolicyMiddleware`；runtime 新增 `workspace` 上下文、`PlatformToolsAutoConfiguration`，账本写指标与审计；迁移 `V0005`。
- 风险：`write_file` 覆盖不是原子的，同一会话中两个线程（主智能体与子智能体）并发覆盖同一文件时后写者胜；`RemoteFilesystem` 的 `ls`、`glob`、`grep` 逐页读出整个会话命名空间（含对象存储中的大文件），会话文件很多时延迟上升；"记住此决定"带内容级规则还需要内核随待处理动作带出建议、runtime 按它保存（登记事项 D21，T12a 与 `bash` 一起做）；`AGENTS.md` 被 harness 的 `WorkspaceContextMiddleware` 注入系统提示词，与装配时的 `sysPrompt` 重复，T10b 的提示词分层处理。
