## 背景

T09b 把 `RoutedModel` 的受控通道开放给业务方（`/v1/chat/completions`、`/v1/embeddings`），给知识库提供内部的 Embedding 与 rerank 接口，并提供可独立运行的脚本化模型服务。架构设计规定了这些端点存在、与智能体共用限流预算计量、内部接口用服务 JWT（T14b），没有写到以下细节：

- **一个操作两种响应。** OpenAI 的 `/v1/chat/completions` 按请求体的 `stream` 返回 JSON 或 SSE。openapi-generator 7.26.0 只按第一种响应生成签名（`Mono<ResponseEntity<ChatCompletion>>`），流式无法返回；OpenAI 的 `input`（文本或数组）与 `embedding`（数组或 Base64）是 3.1 的多类型，生成器报"Type array not yet supported"。
- **首包之前的错误与状态码。** SSE 一旦提交响应头，状态码就定了；预算不足、限流超时、供应商不可用都发生在首包之前，应当以对应状态码返回。
- **非对话模型的计量。** `ModelGateway.CallPurpose` 只有推理与压缩；模型目录没有"种类"，对话接口可能被传入 Embedding 模型；DashScope 的兼容 rerank 端点在 `compatible-api/v1` 下，不在账号的 `compatible-mode/v1` 下；`qwen3.7-text-embedding` 单次最多 20 条（2026-11-08 实测，超过时返回 400），知识库按 64 条一批调用。
- **内部接口的租户。** 内部调用由 knowledge 代表某个租户发起，没有 API Key，`PlatformContext` 的租户与项目要从别处来；T14b 之前没有服务凭据。
- **脚本化模型服务的"首包后断流"。** JDK `HttpServer` 的分块响应在关闭时总会写结束块，客户端读到的是正常结束。

## 候选方案

**一个操作两种响应**

- A：直通接口不进规范，手写处理器。违反"契约优先"，SDK 拿不到定义。
- B：拆成两个操作（例如 `:stream` 后缀）。与 OpenAI 不兼容，业务方的 OpenAI SDK 不能直接用。
- C（采纳）：规范按 OpenAI 写一个操作、两种响应；runtime 的生成配置用 `schemaMappings` 把 `ChatCompletion` 映射为 `Object`，处理器按 `stream` 返回 DTO 或 `Flux<ServerSentEvent<String>>`。多类型字段写成命名的 `oneOf`（`EmbeddingInput`、`EmbeddingVector`），meridian-api 的生成配置把它们映射为 `Object`，runtime 按类型分派并校验。

**首包之前的错误**

- A：先提交 200 与 SSE 头，所有错误都以流中的错误块表示。业务方要解析流才知道预算不足，状态码失去意义。
- B（采纳）：先等第一个信号（`switchOnFirst`，`cancelSourceOnComplete=false`，再 `single()`）：第一个信号是错误时以 problem+json 返回对应状态码；否则提交 200 开始推送，之后的错误以一条 `data: {"error": {...}}` 结束流（OpenAI 兼容服务的做法），不发 `[DONE]`。

**非对话模型的计量**

- A：Embedding 与 rerank 另写一套限流、预扣与用量记录。违反任务"不另写一套"，对账多一种来源。
- B（采纳）：`CallPurpose` 增加 `EMBEDDING`、`RERANK`；每次供应商请求经 `RoutingModelGateway` 的同一条路径（种类相符的解析、令牌桶、按输入估算预扣、按供应商报告的输入 token 结算并写用量记录）；用量记录的 `kind` 分别为 `embedding_tokens`、`rerank_tokens`。模型目录增加 `kind`、模型级 `base_url`（覆盖账号的端点）与 `max_batch_size`（Embedding 按它拆批，每批是一次独立计量的供应商请求）。

**内部接口的租户与凭据**

- A：内部接口也用 API Key。API Key 属于业务方项目，knowledge 不该持有业务方的 Key。
- B（采纳）：请求体带 `tenant_id`（必填）与 `project_id`，处理器据此建立 `PlatformContext`；`/internal/` 下的请求由 `meridian-security` 的 `servicejwt` 包校验服务凭据：`ServiceCredentialResolver` 端口（T14b 的服务 JWT 实现它），T09b 提供只在 `dev`、`test` profile 生效的静态凭据（摘要比较），其他 profile 启用直接启动失败，没有来源时一律拒绝。

**首包后断流**

- A：引入 Netty 或 MockWebServer 写脚本服务。`meridian-test-support` 不依赖平台模块，多一个 HTTP 框架只为一种故障。
- B（采纳）：断流的步骤以固定长度（远大于实际）发出响应头，写到指定块数后关闭连接，客户端读到不完整的响应（`IOException`），与真实的连接中断一致。

## 决策

采纳以上各项的 B 或 C，另有以下约定：

1. **请求严格。** 直通接口只接受规范列出的 OpenAI 字段子集（文本消息与函数工具；`max_tokens` 与 `max_completion_tokens`，后者优先；`temperature`；`stream` 与 `stream_options.include_usage`），未列出的字段返回 400，与平台"不静默忽略"的约定一致；错误一律是 problem+json，不改为 OpenAI 的错误格式（状态码与 OpenAI 相同，SDK 按状态码抛出）。
2. **用量块。** 流式只在 `stream_options.include_usage` 为真时在 `[DONE]` 之前多一个 `choices` 为空、带 `usage` 的块；非流式总带 `usage`（供应商没有报告时为空，平台按估算计量）。流式块中没有值的字段不输出，`finish_reason` 例外（每个增量都给出，可为 null）。
3. **幂等。** 非流式对话补全与 Embedding 支持 `Idempotency-Key`（重放首次结果）；流式请求带 `Idempotency-Key` 返回 400，结果无法重放。
4. **`ModelInvoker` 的增量。** 结束原因与用量在供应商给出它们的块中出现（用量可能单独成块），不承诺都在最后一块。2.0.4 的流式工具调用参数片段不带序号（工具名为 `__fragment__`），按"供应商逐个输出工具调用"归到最近一个调用的序号上。
5. **重试。** Embedding 与 rerank 的连接失败、429、5xx 重试 2 次，指数退避从 500 毫秒起，遵循不超过 10 秒的 `Retry-After`，每次重试前重新等待限流，与 `RoutedModel` 首包之前的规则相同。
6. **内部规范。** 内部接口写在 `meridian-internal-v1.yaml`（不随公开 API 发布，不做兼容性检查），DTO 生成到 `cn.refinex.meridian.api.internal.model`，runtime 的接口生成到 `cn.refinex.meridian.runtime.openapi.internal`。
7. **脚本化模型服务。** `ScriptedOpenAiServer` 放在 `meridian-test-support`（JDK `HttpServer`、Jackson 3、SnakeYAML），无状态：最近一条以 `#script:<名称>` 开头的用户消息选中脚本，其后的 assistant 消息数决定步骤；工具调用 ID 由脚本名、选中消息的位置与步骤确定地生成。开发配置 `dev-config/providers/scripted.yaml` 带 `profiles: [dev, test]`，`FileModelCatalog` 只在这两个 profile 加载它。

## 影响

- 架构设计：「模型调用」增加直通接口、Embedding 与 rerank 一段；「认证」"服务之间"一行注明开发期静态凭据；「API 设计」资源表注明内部接口规范；「计量与预算」的计量项与用量记录注明 `embedding_tokens`、`rerank_tokens`；「测试策略」增加脚本化模型服务；版本升至 v1.9。
- 代码：engine-spi 的 `CallPurpose` 增加两个值、`ModelInvoker` 的增量说明；engine-agentscope 新增 `RoutedModelInvoker`；runtime 新增 `modelrouting.api`（两个处理器）、`VectorModelService`、`ProviderVectorClient`、`ModelKind`、`TextTokens`，`RoutingModelGateway.resolve(modelId, kind)`；security 新增 `servicejwt` 包；test-support 新增 `model` 包与内置脚本；两份规范与生成配置。没有数据库迁移。
- 风险：用量记录多了两种 `kind`，T16 的消费者要按 `kind` 计价；流式工具调用的序号归并假设供应商不交错输出多个调用的参数（OpenAI 与 DashScope 的实际行为）；脚本化模型服务的"首包后断流"依赖固定长度响应被提前关闭，`ScriptedOpenAiServerTest` 与 `ScriptedProviderContractIT` 覆盖。
