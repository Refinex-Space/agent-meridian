# ADR-0022 构建门禁与依赖规则的落地方式

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-07 |
| 决策人 | T01 执行会话 |
| 影响的架构设计章节 | 「代码仓库与模块」「防漂移机制」（只补充落地方式，不改条款） |

## 背景

架构设计「防漂移机制」规定模块依赖方向由 ArchUnit 与 maven-enforcer 共同检查、依赖版本只在 `meridian-bom` 声明，但没有规定 Maven 层面怎么组织。T01 搭建骨架时遇到四个需要定下来的细节，它们影响之后每个任务添加依赖的方式：

1. 根 POM 在 `dependencyManagement` 中导入 `meridian-bom`。如果 `meridian-bom` 继承根 POM，Maven 报导入循环（`The dependencies of type=pom and with scope=import form a cycle`，已实测）。
2. enforcer 的禁用清单怎么区分模块：任务要求"除 engine-agentscope、engine-agentscope-test、runtime、arch-tests 外禁止 `io.agentscope:*`"，「防漂移机制」还要求 enforcer 检查模块依赖方向。
3. 测试库版本：Spring Boot 4.1.2 管理的 JUnit（6.0.3）、Mockito（5.23.0）不是最新稳定版。
4. Checkstyle 要求 public 方法有 Javadoc，但 record 访问器除外；Checkstyle 的 XPath 不能比较两个属性值（属性节点不支持取值，只支持 `[@text='字面量']`，已实测会抛 `UnsupportedOperationException`），无法精确识别"与组件同名的方法"。

## 候选方案

**BOM 结构**

- A：`meridian-bom` 不继承任何父 POM，根 POM 从同一 reactor 导入它。Maven 3.9 能从 reactor 解析导入的 BOM（已实测），代价是 `-N` 与在子模块目录单独运行 Maven 会解析失败。
- B：另建 `meridian-build-parent` 承载插件配置，根 POM 只做聚合。多一个模块，与任务给定的模块清单不符。

**enforcer 的模块差异**

- A：默认允许，10 个模块各自追加 `io.agentscope` 的排除项。新模块（例如 T26 的 `meridian-sdk-java`）忘记追加时不报错。
- B：默认拒绝。根 POM 排除 `io.agentscope` 与 `cn.refinex.meridian` 全部构件，各模块在自己 POM 的同一个 execution（`enforce-rules`）里用 `includes`（`combine.children="append"`）放行「模块依赖规则」允许的平台模块（含传递依赖）与具体的 AgentScope 构件。`includes` 会覆盖 `excludes`，所以放行项只写具体构件，不写通配的 `io.agentscope`，全局禁用的 starter、RAG 扩展、Service 在放行模块中仍然被拦截（已实测）。

**测试库版本**

- A：全部沿用 Boot 管理的版本。
- B：JUnit、AssertJ、Mockito、Testcontainers 的 BOM 放在 Boot 之前导入，取发布满两周的最新稳定版；Reactor（含 reactor-test）沿用 Boot 的版本，因为 reactor-core 是运行时依赖，与 Spring Framework 绑定。

**record 访问器豁免**

- A：不豁免，访问器也写 Javadoc。与任务要求不符。
- B：按结构近似：record 中非 static、无参数、方法体只有一条 `return` 的方法视为访问器。同形态的派生方法也会被放过。
- C：写自定义 Checkstyle 检查。需要单独的构建模块供插件依赖，成本与收益不相称。

## 决策

- BOM 选 A。`meridian-bom` 中声明一个跳过执行的 Spotless 插件，只为让命令行的 `spotless:` 前缀在该模块可解析；它的 POM 格式由根模块的 Spotless 配置代为检查。
- enforcer 选 B。默认拒绝能让新模块自动受约束，并顺带落实「防漂移机制」中"模块依赖方向由 enforcer 检查"。`meridian-test-support` 与 `meridian-engine-agentscope-test` 在根 POM 中放行为只能以 test 作用域依赖。
- 测试库版本选 B。
- record 访问器选 B，局限写在 `build/checkstyle/checkstyle.xml` 的注释中，由代码评审兜底。
- 另外：`junit-jupiter`（test 作用域）声明在根 POM 的 `dependencies` 中。Surefire 与 Failsafe 按标签排除 `live`，类路径上没有 JUnit Platform 时，一个空的 `target/test-classes` 就会让构建失败。

## 影响

- 架构设计无需修改：以上都是「防漂移机制」已规定约束的落地方式。
- 之后的任务新增模块间依赖或 AgentScope 构件时，要同时在该模块 POM 的 `enforce-rules` 中放行；修改「模块依赖规则」本身仍需变更型 ADR，并同步 `meridian-arch-tests` 的 `MeridianModule`。
- Maven 命令必须在根目录用 `-pl <模块> -am` 运行，已写入根 `CLAUDE.md`。
- 升级测试库时注意与 Spring Boot 测试支持的兼容性；出现冲突时退回 Boot 管理的版本。
