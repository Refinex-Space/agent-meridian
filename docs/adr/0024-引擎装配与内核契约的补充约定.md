# ADR-0024 引擎装配与内核契约的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-07 |
| 决策人 | T03 执行会话 |
| 影响的架构设计章节 | 「引擎装配」「端口」（只补充，不改既有条款） |

## 背景

T03 定义 `meridian-engine-spi` 的全部契约并实现 `AgentAssembler`。逐项核对 AgentScope 2.0.4 源码后，有几处架构设计没有写到、但为了落实它已规定的行为必须定下来的细节。它们影响 runtime、engine-agentscope 与之后多个任务，所以记录在这里。

## 决策

**1. `asyncToolRegistry(NoopAsyncToolRegistry)`。** 架构设计用 `NoopMessageBus` 避免"每次推理都读一次工作区"。但 2.0.4 的 `HarnessAgent.Builder.build()` 在没有显式设置时会创建 `WorkspaceAsyncToolRegistry(filesystem, ".agentscope/bus/async-tools")`，`InboxMiddleware` 每次推理前调用它的 `findStale`，仍然读工作区。平台不启用 harness 的异步工具，所以同时注入空实现。`AgentAssemblerTest` 用对照实验证明：不设置时推理前会访问 `.agentscope/bus`，设置后不会。

**2. `enableAgentTracingLog(false)`。** 2.0.4 默认安装 `AgentTraceMiddleware`，它以 INFO 级别记录模型回复正文（截断到 120 字符），违反编码规范「日志」中"禁止记录提示词正文、模型输出正文"。轮次的可观测性由 `OtelTracingMiddleware` 与平台事件承担。

**3. 实例缓存键包含子智能体名。** 架构设计规定缓存键为 `(agent_version_id, environment_id, environment_revision)`，又规定子智能体"由 `AgentAssembler` 按子智能体配置单独装配和缓存"。缓存键因此加上可空的子智能体名，主智能体为空。

**4. 缓存基于 Caffeine。** 容量与空闲淘汰交给 Caffeine（Spring Boot 管理版本 3.2.4，Apache-2.0）；引用计数与"归零才关闭"在缓存条目上实现：淘汰只把条目标记为退役，引用归零时才关闭实例，关闭在执行器上进行，不占用归还实例的线程（可能是 Reactor 线程）。同一个键的装配在条目自己的锁内进行，不阻塞其他键。

**5. 新增端口 `AgentConfigPort`。** `TurnContext` 只带 `agent_version_id`、`environment_id`、`environment_revision`；缓存未命中时内核经这个端口读取已解析的配置，由 runtime 的 `config` 包实现（配置缓存）。已同步到架构设计「端口」表。

**6. 平台资源随实例关闭。** `Toolkit.copy()` 不转移 MCP 客户端的所有权：经 `Builder.toolkit(...)` 传入的工具包上注册的 MCP 客户端，`HarnessAgent.close()` 不会关闭。平台工具的提供者把需要关闭的资源（例如 MCP 客户端）随工具一起返回，`AssembledAgent.close()` 先关闭 `HarnessAgent` 再关闭这些资源。

**7. 技能清单在装配时冻结。** `disableDynamicSkills()` 使 `HarnessSkillMiddleware` 在构建时用 `RuntimeContext.empty()` 枚举一次技能并冻结清单。智能体实例本来就按智能体版本缓存，所以 `MeridianSkillRepository`（T10a）按装配时的智能体版本解析技能清单即可，不依赖调用时的上下文；技能资源的读取仍按调用时的上下文。

**8. 事件模型包含 user 域。** `EngineEvent` 的封闭层级与架构设计「事件」清单逐一对应，包括由 API 写入的 `user.*` 事件，使 `session_events` 只有一种数据模型。事件只有类型与 `data`，信封字段由 runtime 在持久化时分配。

## 候选方案

第 1、2 条的替代方案是"不设置，沿用默认"，分别违反架构设计的意图与日志规范，没有采纳。第 3 条的替代方案是子智能体不缓存、每次拉起都装配，会让并行子智能体重复构建并反复关闭 MCP 客户端。第 4 条的替代方案是手写 LRU 与定时清理，重复实现成熟能力。第 5 条的替代方案是让 `TurnContext` 直接携带完整配置，每轮都要传递与校验一份不变的大对象。

## 影响

- 架构设计「引擎装配」表增加 `asyncToolRegistry(...)` 与 `enableAgentTracingLog(false)` 两行；「端口」表增加 `AgentConfigPort`。不改变既有条款。
- `meridian-engine-agentscope` 新增 Caffeine 依赖（版本由 Spring Boot 管理）。
- T10a 实现技能仓库与 MCP 注册时遵循第 6、7 条。
