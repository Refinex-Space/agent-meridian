# ADR-0045 凭据库、供应商与模型目录的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-11 |
| 决策人 | T15a；Q3 与端点策略由用户在 T15a 会话中确认 |
| 影响的架构设计章节 | 领域模型（ID 规则）、数据架构（control-plane 核心表、跨服务数据流）、模型调用、安全架构（授权、凭据）、计量与预算、待决问题（Q3） |

## 背景

T15a 在 control-plane 中建立凭据库、供应商账号、模型目录与价格表，并让 runtime 的模型调用改从 control-plane 解析。架构设计规定了信封加密、`/internal/v1/secrets:resolve`、明文在 runtime 只缓存 5 分钟、价格表有版本，没有规定：

- 凭据挂在哪一级：领域模型写"凭据挂在项目下"，但供应商账号与租户设置（联网搜索后端的 `secret_id`）都是租户级资源，引用的凭据也只能是租户级的；角色矩阵中管理凭据的是租户管理员。
- 模型"授权给项目"的含义（登记事项 D23）；数据密钥、密文与密钥加密服务的格式；内部接口的形状、审计与租户校验。
- 供应商端点的 SSRF 校验（登记事项 D52）：企业内的私有化推理服务在内网地址上，一律拒绝内网会让它们无法接入。
- 价格表的版本怎样生效、用量记录怎样指向版本；删除被引用的资源时怎样告诉调用方引用方。
- 待决问题 Q3（首批供应商）：用户在 T15a 开工时决定为 OpenAI 兼容、Anthropic、Gemini（接入方式见 ADR-0046）。

## 候选方案

1. **凭据的归属**：(a) 只挂项目——租户级的供应商账号无处引用；(b) 只挂租户——与领域模型"凭据挂在项目下"不符，T15b 的项目级 MCP 服务也无法只给本项目用；(c) 凭据属于租户，可选地属于其中一个项目：租户级凭据供租户级资源与全部项目使用，项目级凭据只供本项目的资源使用。
2. **供应商端点的地址策略**：(a) 拒绝一切非公网地址（与 `web_fetch` 相同）——私有化推理服务无法接入；(b) 只拒绝回环、链路本地与元数据地址，私有网段全部放行——租户管理员可以让 runtime 访问内网任意 HTTP 服务；(c) 合并：危险地址始终拒绝，私有网段默认放行，平台可以收窄到指定网段。
3. **价格表版本的生效**：(a) 版本可以预约未来的生效时间——runtime 要按调用时间挑版本，缓存要感知生效时刻；(b) 新版本发布即生效，旧版本不可修改，用量记录带结算时的版本号。

## 决策

1. **归属与授权（1c）。** 供应商账号、模型、价格表是租户级资源；模型可被该租户的全部项目使用，"未授权给该项目"即模型不属于调用方租户（D23），按项目限制可用模型不在 M1 范围。凭据带 `tenant_id` 与可空的 `project_id`；解析时租户必须一致，凭据带项目时项目也必须一致，否则与不存在相同（404）。管理接口在租户下（`/admin/v1/tenants/{tenant_id}/secrets`，请求体可带 `project_id`），新增操作类别 `SECRET_READ`、`SECRET_WRITE`、`MODEL_READ`、`MODEL_WRITE`，都是租户级：凭据只有所有者与租户管理员可以管理与查看；模型目录（供应商账号、模型、价格表）由所有者与租户管理员管理，项目开发者与观察者可以查看（选择智能体的模型）。
2. **信封加密。**
   - 主密钥（KEK）只在密钥管理系统中，经 `KeyEncryptionService` 包装与解包数据密钥：`local`（开发与测试：配置给出的文件中的 AES-256 密钥，文件不存在时生成并以 0600 写入，不提交）与 `vault`（HashiCorp Vault Transit 的 `encrypt`/`decrypt`，令牌认证，可选命名空间）。配置 `meridian.control-plane.secrets.key-encryption` 没有默认值，部署必须显式选择。
   - 数据密钥（DEK）按租户一把 AES-256，在租户第一次写入凭据时生成，包装后存 `cp.secret_data_keys`（带包装它的 KEK 标识）；解包后的数据密钥在 control-plane 内存中最多缓存 5 分钟。
   - 凭据值用 AES-256-GCM 加密：12 字节随机 nonce，附加认证数据为 `tenant_id`、`secret_id` 与版本号（密文搬到别的行或租户无法解密），`cp.secrets.ciphertext` 存 nonce 加密文与标签。轮换是写入新值、版本号加一，旧密文被覆盖。
   - 管理接口只能写入、轮换、删除，任何响应都不含明文；列表与详情给出名称、所属项目、版本、创建与轮换时间、最后使用时间、引用方（供应商账号、租户设置的联网搜索后端，T15b 起另有 MCP 服务）。幂等记录不保存请求体中的凭据值。
3. **内部接口（只接受 `runtime` 的服务 JWT）。**
   - `POST /internal/v1/secrets:resolve`（`{tenant_id, project_id, secret_id}` → `{secret_id, version, value}`，`Cache-Control: no-store`）：按上面的规则校验租户与项目；每次成功的解析在同一事务中写审计 `secret.resolved`（操作者为调用方服务）并更新 `last_used_at`。
   - `GET /internal/v1/models/{model_id}`：模型、所属供应商账号（只有凭据 ID）、当前价格表版本，不带明文；runtime 自己校验模型的租户与调用方一致。`describe`（装配时读上下文窗口）不需要 `PlatformContext`，所以接口不按租户过滤。
4. **失效通知。** 供应商账号、模型、凭据、价格表变更提交后在 `config.invalidate` 发布 `{"type":"provider_account"|"model"|"secret"|"price_book","tenant_id":…,"id":…}`。runtime 收到后立即淘汰对应缓存（凭据按 ID，供应商账号淘汰其下全部模型，价格表淘汰引用它的模型）；兜底过期时间：模型目录 60 秒，凭据明文 5 分钟（即明文在 runtime 内存中的上限）。缓存键包含租户与项目，命中不会跨租户。
5. **供应商端点的地址策略（2c，D52）。** `meridian-common` 的 `common.net`：`AddressPolicy` 从 runtime 移入并按类别判定地址；`EndpointPolicy` 校验端点 URL：只允许 `http`、`https`，不允许用户信息；主机按字面量或 DNS 解析，每个地址都要通过。始终拒绝：链路本地（含 `169.254.169.254`）、云元数据（`100.100.100.200`、`fd00:ec2::254`、`192.0.0.192`）、未指定、组播、广播与保留、文档、基准测试段，以及按内嵌 IPv4 判定后属于这些的 IPv6 地址。回环地址只在 `allow-loopback` 为真时放行（开发与测试的脚本化模型服务）。私有网段（`10/8`、`172.16/12`、`192.168/16`、`100.64/10`、`fc00::/7`）落在 `private-networks` 中才放行，默认是这五段，生产部署按私有化推理服务所在网段收窄（T28 写进部署文档）。control-plane 在写入供应商账号与模型时校验，runtime 在每次读取目录（缓存刷新）时按当前 DNS 结果再校验一次；两次校验之间的 DNS 重绑定以网络策略为最终边界（T37）。
6. **图片地址（D52）。** `user.message` 等内容块的 `image.url` 只接受带主机的 `http`、`https` 绝对地址，入口返回 400；Gemini 不接受 URL 图片（ADR-0046）。
7. **模型目录。** 模型的种类 `chat`、`embedding`、`rerank`；Embedding 与 rerank 只能挂在 OpenAI 兼容的供应商账号下（其他格式的向量接口按需再接，D27）。能力 `tool_calls`、`vision`、`reasoning` 只作展示与校验依据。备用模型必须同租户、同种类、不是自己；智能体配置给了备用模型时以它为准，否则用目录中的备用模型（`ModelGateway.ModelDescriptor` 增加 `fallbackModelId`）。限流参数在账号上，模型可以覆盖。
8. **价格表（3b）。** 前缀 `prb`；价格表属于租户，带币种；版本从 1 递增，发布即生效、不可修改，价格按每百万 token 分输入、输出、缓存读、缓存写、推理五项（`numeric`，API 中是十进制字符串）。模型引用价格表；runtime 的用量消息在结算时带上目录中当前的 `price_book_id` 与 `price_book_version`，T16 按记录中的版本计价，调价不影响已有记录。价格表没有删除接口，版本是历史记录的计价依据。
9. **引用冲突。** 删除被引用的资源返回 409，problem+json 扩展字段 `references` 列出引用方 `[{type, id, name}]`（`common.error.ReferencedException`）：供应商账号被模型引用、模型被其他模型作为备用、凭据被供应商账号或租户设置引用、价格表被模型引用（换绑时检查）。T15b 起智能体版本对模型的引用同样计入。

## 影响

- 架构设计：ID 规则加 `prb`；control-plane 核心表补列（`secret_data_keys`、`price_book_versions`）；领域模型的凭据归属；「模型调用」第 1 步补目录来源与端点校验；「凭据」补存储与取用的细则；「授权」补四个操作类别；「计量与预算」补用量记录中的价格表版本；Q3 已决。版本号递增。
- 代码：`meridian-common`（`common.net`、`ReferencedException`、`IdPrefix.PRICE_BOOK`）、`meridian-security`（`Permission`、`RoleMatrix`、`ProblemMapper` 输出 `references`）、`meridian-engine-spi`（`ModelDescriptor.fallbackModelId`）、control-plane（`secret`、`provider` 上下文，迁移 `V0002`）、runtime（`ControlPlaneSecretResolver`、`ControlPlaneModelCatalog`、失效订阅、用量消息字段；文件实现只在 `dev`、`test` profile）、`meridian-admin-v1.yaml`、`meridian-internal-v1.yaml`。
- 依赖：control-plane 的测试依赖 Testcontainers 的 Vault 模块（版本由 Testcontainers BOM 管理）。Vault Transit 经 Spring `RestClient` 调用，不引入 Spring Vault。
- 风险：control-plane 在解析请求期间持有明文与解包后的数据密钥（内存中，不落盘、不记日志）；本地主密钥文件只适合开发，生产必须用 Vault（T28 写进部署文档）。
