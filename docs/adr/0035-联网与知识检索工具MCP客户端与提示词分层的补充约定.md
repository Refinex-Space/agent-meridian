# ADR-0035 联网与知识检索工具、MCP 客户端与提示词分层的补充约定

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（补充） |
| 日期 | 2026-11-08 |
| 决策人 | T10b 执行会话 |
| 影响的架构设计章节 | 「引擎装配」（新增 `sysPrompt` 与 `disableWorkspaceContext()` 两行）、「端口」中的 `AgentConfigPort`、「平台工具」、「上下文管理」中的提示词分层、「智能体安全」（只补充，不改既有条款） |

## 背景

T10b 实现 `web_fetch`、`web_search`、`knowledge_search`、MCP 客户端、平台基础提示词与系统提示词分层。架构设计规定了四层顺序、动态内容以消息注入、来源标签、`web_fetch` 的 SSRF 防护与 5 MB 上限、MCP 凭据经请求定制器注入，落地时遇到以下没有写到或与 2.0.4 实际行为有出入的细节：

- **2.0.4 自己往系统提示词里加内容。** harness 的 `WorkspaceContextMiddleware` 在每次推理的 `onSystemPrompt` 追加一节：当天日期、操作系统、本机工作区路径，以及再读一遍的 `AGENTS.md`（登记事项 D29：与装配时的 `sysPrompt` 重复）。日期每天变化，同一智能体的请求前缀跨天就不同，命中不了供应商的提示词缓存。`HarnessSkillMiddleware` 把技能清单追加在系统提示词最后。
- **租户层从哪里来。** 租户提示词属于 `cp.tenant_settings`（T15b），本任务从 `AgentConfigProvider` 的文件实现读取；智能体实例按智能体版本缓存，`HarnessAgent` 的系统提示词是构建期配置。
- **工具定义的键顺序。** 平台工具的入参 schema 用 `Map.of` 写成，`Map.of` 的迭代顺序每个 JVM 随机。工具定义随请求发给模型，不同节点上同一智能体的请求前缀因此不同。
- **`web_fetch` 的 SSRF。** JDK `HttpClient` 无法替换单个客户端的 DNS 解析；"解析后校验"再交给客户端自己解析，中间有重绑定的窗口。`java.net.URI` 对 `127.1`、`0x7f.1` 这类主机给不出 `getHost()`，而 `inet_aton` 风格的写法（十进制、八进制、十六进制、省略段）在不同组件里解释不同。
- **`web_search` 的后端。** 架构设计列出博查、Tavily、Brave、SearXNG，任务要求实现 SearXNG 与一个商业 API。
- **`knowledge_search` 的入参。** 规则内容是知识库 ID，入参必须带出要检索的知识库；工具工厂原来只拿到平台服务，拿不到智能体绑定的知识库。
- **MCP 客户端与凭据。** 2.0.4 的 `McpClientBuilder.httpRequestCustomizer` 只接受同步定制器，MCP SDK 0.17.2 把它包成 `Mono.fromSupplier`，在发请求的线程上执行；同步客户端（`buildSync`）在内部另起订阅，调用方 Reactor Context 中的内容传不到传输层。`Toolkit.registerMcpClient` 注册的 `McpTool` 不经平台记账，也拿不到幂等键；工具名没有前缀。
- **MCP 服务连不上。** 装配时工具发现失败，实例缺一组工具会被缓存复用。
- **MCP 的 SSRF。** 「智能体安全」要求 MCP 的 HTTP 调用经过 SSRF 防护，而企业 MCP 服务（包括 knowledge 的 `/mcp/knowledge`）通常在内网。

## 候选方案

**提示词分层**

- A：保留 `WorkspaceContextMiddleware`，在它之后加一个中间件删掉日期。依赖 2.0.4 的模板文本，`AGENTS.md` 仍重复。
- B（采纳）：装配时 `disableWorkspaceContext()`；`sysPrompt` 为「平台基础提示词 → 租户 → 智能体」（`PlatformPrompt.compose`，空的层不出现），技能清单仍由 `HarnessSkillMiddleware` 追加在最后。当前时间以 `<platform_context>` 用户消息注入：只在 `NewMessages` 轮次、放在用户消息之前（审批结果与自定义工具结果不能与普通消息同轮，恢复轮没有新输入）；消息随输入写进状态，元数据标记 `meridian_platform_context`，上下文构成算作平台注入。`AGENTS.md` 仍是受保护路径，可以 `read_file`。

**租户层**

- A：把租户提示词放进 `ResolvedAgentSpec`。租户提示词不随智能体版本变化，放进版本配置语义不对。
- B（采纳）：`AgentConfigPort` 增加 `tenantPrompt(tenantId)`；装配器经 `TenantPromptProvider` 在装配时读取一次（装配在 `Blocking` 的虚拟线程上，`PlatformContext` 经 `PlatformContexts.find()` 取得；没有时直接失败，避免缓存一个缺租户层的实例），结果随实例缓存。智能体版本属于一个项目，同一缓存键下的会话都属于同一租户。T15b 的配置失效要连同该租户的实例一起淘汰。runtime 的 `AgentConfigProvider` 增加 `tenantSettings`，开发期文件实现读 `kind: tenant_settings`（`system_prompt`、`web_search`）。

**工具定义的顺序**

- 采纳：`PlatformTool` 构造时把入参 schema 规整为按键排序的不可变结构；MCP 工具在发现后按名字排序。

**来源标签**

- 采纳：`<external_content source="web_fetch|web_search|knowledge_search|mcp" 其他属性>` 包住内容；内容中形如 `<external_content`、`</external_content` 的片段（不区分大小写，`<`、`/` 与标签名之间允许空白）把开头的 `<` 换成 `&lt;`，伪造的闭合标签与冒充其他来源的开标签都失效；属性值按 XML 转义。平台基础提示词（英文）声明标签内一律是数据。知识库每个切片各包一个标签，带文档名与分数便于引用；MCP 的错误结果同样包标签。

**`web_fetch`**

- A：JDK `HttpClient` 先 `InetAddress` 解析校验再请求。客户端会重新解析，有重绑定窗口；DNS 解析在 Netty 线程上阻塞。
- B（采纳）：Reactor Netty `HttpClient` 配 `GuardedResolverGroup`：委托 Netty 的非阻塞 DNS 解析，结果中只要有一个地址被拒绝就不建立连接，通过时连接的正是校验过的地址。不复用连接（每次抓取、每一跳都重新解析校验），不跟随重定向而自己逐跳处理（至多 5 跳），不走代理（代理会替客户端解析）。IP 字面量不经过解析器，由平台在请求之前按 `AddressPolicy` 判定：`inet_aton` 全部写法与 IPv6 字面量都由平台解析，只由数字与点组成却不合法的主机名直接拒绝，合法的非标准写法改写为规范形式再请求；`getHost()` 为空时从 authority 取主机。被拒绝的段：IPv4 私有、CGNAT（含阿里云元数据 `100.100.100.200`）、回环、链路本地（含 `169.254.169.254`）、未指定、文档、基准测试、保留、组播、广播；IPv6 回环、未指定、唯一本地（含 AWS `fd00:ec2::254`）、链路本地、站点本地、组播、文档、Teredo、本地 NAT64；IPv4 映射、IPv4 兼容、NAT64、6to4 按内嵌 IPv4 判定。响应体读满 5 MB 即停止并标记截断。HTML 先用 jsoup 去掉脚本、样式等不可见元素、链接改为绝对地址，再用 flexmark-html2md-converter 转 Markdown（参考 spring-ai-agent-utils 的 `SmartWebFetchTool`）；纯文本、JSON、XML 原样；其他类型拒绝。被拒绝时抛 `ForbiddenException`，工具给模型固定的英文说明；其他失败的异常消息是英文，工具原样交给模型。工具一次输出至多 50000 字符，`offset` 续读。

**`web_search`**

- 采纳：`WebSearchPort` 的实现 `TenantWebSearch` 按调用方租户的设置选择适配器，API 密钥经 `SecretResolver` 每次解析。适配器：SearXNG（可自建、内网部署、不需要密钥）与博查。商业 API 选博查而不是 Tavily：企业部署在国内，博查可直连、按国内合规提供服务，Tavily 需要跨境访问。租户没有配置时返回"未配置"的错误结果。

**`knowledge_search`**

- 采纳：`PlatformToolProvider` 的工厂可以读取装配对象（`with(name, (services, profile) -> …)`），`knowledge_search` 按实例创建：`knowledge_base_ids` 必填，schema 的 `enum` 只列智能体绑定的知识库（2.0.4 的参数校验先拦下未绑定的 ID），执行时再校验一次。T19 之前 runtime 提供 `UnconfiguredKnowledgeSearch`，检索以"未配置"的错误结果交给模型，不中断本轮。

**MCP**

- A：`Toolkit.registerMcpClient`。工具名没有 `mcp__` 前缀、不进平台账本、拿不到幂等键，凭据只能写成静态请求头。
- B（采纳）：`McpConnector` 用 `McpClientBuilder` 按固定顺序构建：先选传输（Streamable HTTP 或 SSE），再设置 HTTP 客户端（不跟随重定向、连接超时）、请求定制器 `McpCredentialInjector`、协议版本（Streamable HTTP 声明 `2025-03-26`、`2025-06-18`，SSE 只有 `2024-11-05`），用 `buildAsync()` 得到异步客户端。每个 MCP 工具包成 `McpPlatformTool`（继承 `PlatformTool`）：名字 `mcp__{server}__{tool}`（不符合 `^[a-zA-Z0-9_-]{1,64}$` 的不注册），进权限引擎与账本，副作用等级取服务配置的标注，未标注按 `non_idempotent`（`McpServerSpec` 的 `sideEffect` 缺省时取该值），`non_idempotent` 的调用把幂等键放进请求的 `_meta`（`meridian/idempotency_key`）。凭据：每次调用（以及装配时的初始化与工具发现）之前经 `SecretResolver` 解析，作为 `McpCredentials` 放进这一次调用的 Reactor Context（`McpTransportContext`），定制器只从中读取写入请求头；客户端配置、工具定义、提示词、日志里都没有明文，结果与错误说明中出现的凭据明文替换为 `***`。客户端作为 `ToolBundle.resources` 随实例关闭。
- 装配时连不上服务（初始化或工具发现失败、主机名无法解析）抛 `McpUnavailableException`（`tool.mcp_unavailable`，可重试）：本轮以 `session.error(retryable)` 结束、重新排队，下次认领时重新装配；凭据不可用或端点指向元数据地址属于配置错误，以终止错误结束。单次工具调用失败（服务返回 `isError`、调用超时）是出错的工具结果，不结束本轮。
- MCP 的 SSRF：端点由管理员登记（控制面登记时校验，T15b），允许内网地址；客户端不跟随重定向，拒绝解析到链路本地地址或已知云元数据地址的端点。

## 决策

采纳以上各项的 B 方案或"采纳"项。都是对架构设计已规定行为的落实：四层顺序、动态内容以消息注入、来源标签、SSRF 防护与 5 MB 上限、凭据经请求定制器注入、`mcp__` 前缀与副作用标注都不变；新增端口方法 `AgentConfigPort.tenantPrompt`、错误码 `tool.mcp_unavailable`，不改变既有端口的语义。

## 影响

- 架构设计：「引擎装配」表新增 `sysPrompt` 与 `disableWorkspaceContext()` 两行；「端口」表 `AgentConfigPort` 一行补充租户提示词；「平台工具」补充联网、知识检索与 MCP 的实现约定；「上下文管理」的提示词分层补充落点；「智能体安全」补充来源标签格式；版本升至 v1.11。
- 代码：engine-spi（`AgentConfigPort.tenantPrompt`、`ToolErrorCode`、`McpUnavailableException`、`McpServerSpec` 副作用缺省值）；engine-agentscope（`PlatformPrompt`、`PlatformContextMessage`、`TenantPromptProvider`、`SourceTags`、三个工具、`tools.mcp`、`PlatformToolProvider` 的工厂与 MCP、`PlatformTool` 的 schema 规整、`AgentScopeEngine` 注入时钟）；runtime（`tooling` 的 SSRF 抓取、搜索适配器、未配置的知识检索、`TenantSettings`）。
- 依赖：BOM 新增 flexmark-html2md-converter 0.64.8、jsoup 1.22.2（覆盖 flexmark 传递的 1.15.4，它解析不可信的网页）、wiremock-standalone 3.13.2（测试）；engine-agentscope-test 的测试作用域加 `spring-boot-starter-webmvc`（P8 的进程内 MCP 服务）。
- 既有行为的变化：每个新消息轮次多一条平台上下文消息，压缩前的消息数随之增加（既有测试已按新的构成调整）；`AGENTS.md` 不再被注入系统提示词。
- 风险：平台上下文消息每轮约 20 个 token；租户提示词变更在实例淘汰前不生效（T15b 处理失效）；MCP 服务短时不可用会让挂载它的智能体整轮重试。验证：`PromptLayeringScenarioTest`、`ScriptedModelSessionIT`（前缀逐字节相同）、`SourceTagsTest`、`AddressPolicyTest`、`GuardedWebFetcherTest`、`WebSearchAdaptersTest`、`ExternalContentToolScenarioTest`、`McpToolsIT`。
