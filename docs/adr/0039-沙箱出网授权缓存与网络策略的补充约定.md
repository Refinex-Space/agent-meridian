## 背景

T12b 实现沙箱出网控制并在本机 kind 集群上验证 P14。架构设计「沙箱出网」规定了四条（NetworkPolicy 只放行代理、模板固定代理地址、代理按源 IP 回调 runtime 并缓存 30 秒、不终止 TLS），回调方式由 ADR-0038 改为 Lua 过滤器。落地时遇到以下没有写到的细节：

- **按 IP 找会话。** `sandbox_pod_ip` 没有唯一约束；沙箱在平台之外被重建（Pod 被驱逐后 agent-sandbox 重建，IP 变了）而会话行还没更新时，旧 IP 可能被另一个会话的新 Pod 复用，两行记录同一 IP。会话归档、删除后沙箱可能还在（删除会话的沙箱清理在 T17a）。
- **白名单的语法。** `EnvironmentSpec.egressAllowlist` 只说"例如 `pypi.org`、`*.example.com`"，没有规定通配的层级、大小写、端口与非法条目。
- **缓存的失效。** "Pod IP 被清空后授权立即失效"要求跨节点：代理的回调经 Service 负载均衡到任一 runtime 节点，清空 Pod IP 的是另一个节点。缓存的加载与失效还有竞争：提交之前开始的加载读到旧数据。
- **接口的形态。** 内部接口的错误一律是 problem+json（`InternalOpenApiSpecTest` 检查），拒绝出网是常态结果。
- **沙箱的 DNS。** 沙箱要解析代理的服务名；CoreDNS 会把外部域名的查询转发出去。
- **白名单域名解析到内网。** 代理按域名放行后自己解析并连接，域名可能被解析到集群内或元数据地址（DNS 重绑定）。
- **本机拓扑。** kind 集群用 Calico 默认 IP 池 `192.168.0.0/16`，覆盖 Docker Desktop 的 `host.docker.internal`（`192.168.65.254`）；Calico 对池内目的地址不做出向 NAT，Pod 访问不到宿主上的 runtime。
- **回调凭据。** `/internal/` 要求服务凭据；Envoy 不能签发服务 JWT（T14b）。

## 决策

1. **按 IP 找会话**：`egress.infra.system.SandboxAddressRepository`（`SystemRepository`，`@CrossTenant`）查 `sandbox_pod_ip` 相等、`deleted_at` 为空、状态不是 `terminated` 的会话，最多取两行。一行时按会话的 `(environment_id, environment_revision)` 读环境（在该会话的 `PlatformContext` 中读，T15b 换成按项目解析的实现也成立）；零行或两行一律拒绝（`unknown_source`），两行时记告警。不加唯一约束：唯一约束会让新会话认领到被复用的 IP 时落库失败。迁移 `V0007` 加部分索引 `sessions (sandbox_pod_ip) WHERE sandbox_pod_ip IS NOT NULL`。
2. **白名单语法**（`egress.domain.EgressAllowlist`）：条目是主机名或 IP 字面量（逐字匹配），或 `*.` 加域名（匹配任意层级的子域名，不匹配域名本身，需要时两条都写）；不区分大小写，忽略末尾的 `.`；不限定端口。非法条目（单独的 `*`、中间带 `*`、带端口、路径或协议）被忽略并记告警，不会放宽匹配。目标（`:authority`）按同一套规则规整：只接受字母、数字、`-`、`_` 组成的 DNS 名与 IPv4、IPv6 字面量，带 `@`、`%`、空白、控制字符的一律 `invalid_target`；十进制整数等非常规 IPv4 写法按 DNS 名处理，不会与正常条目相等。
3. **缓存与失效**：每个节点用 Caffeine 按源 IP 缓存解析出的授权（会话与白名单）30 秒，上限 1 万条；找不到会话不缓存。加载在缓存的按键计算中执行，淘汰会等正在进行的加载结束再删除，所以改动 Pod IP 的事务提交之前开始的加载写入的条目一定会被提交之后的淘汰删掉。`SandboxService` 在获取（新认领、恢复、重新连接时 IP 变了）、回收、删除会话的沙箱时把旧 IP 与新 IP 交给 `EgressRevocations`：本节点立即淘汰，提交后再淘汰并经 Redis Pub/Sub 频道 `egress:revoke` 广播。新 IP 即使与旧的相同也要广播：错过上一次广播的节点在新会话认领到这个 IP 时还会再收到一次。残余风险：一个节点在两次广播期间都断开订阅时，它的旧条目最长保留到 30 秒过期。
4. **接口**：`POST /internal/v1/egress:authorize`，请求体 `{source_ip, target}`；放行 200 `{session_id}`；拒绝 403 problem+json，`code` 为 `egress.not_allowlisted`、`egress.unknown_source`、`egress.invalid_target`。代理只认 200。判定耗时计入 `meridian_egress_authorize_seconds`（标签 `result`、`reason`），缓存命中率为 `cache_gets_total{cache="egress_grants",result="hit|miss"}`。
5. **网络策略**（chart `meridian-sandbox`）：沙箱 Pod 的出网只到代理的 10000 端口与集群 DNS（53/UDP、TCP）。代理的入网只接受沙箱 Pod 与 kubelet 的健康检查；出网只到 DNS、授权回调的 runtime（按拓扑）、`0.0.0.0/0` 排除私网、链路本地（含云元数据）、CGNAT 与回环，以及 values 中列出的集群内命名空间（本机 kind 的 P14 目标）。白名单域名被解析到内网地址时代理也连不上。
6. **两种拓扑**由 `egressProxy.authz.topology` 切换：`cluster`（Service 地址，网络策略按命名空间与 Pod 标签放行 runtime）与 `host`（`host.docker.internal`，只取 IPv4，网络策略按宿主 IP 放行）。本机 kind 用 `host`、端口 18080（`run-runtime.sh --server.port=18080`）。
7. **Envoy 的配置**：动态转发代理加 CONNECT（路由 `connect_config`），不终止 TLS；路由不限总时长（长下载），`stream_idle_timeout` 300 秒、`request_headers_timeout` 10 秒；下游连接上限 1 万（overload manager）、动态转发集群的熔断阈值 4096；不生成请求 ID、不加 `x-envoy-*` 头；管理接口只绑定 127.0.0.1，另起健康检查监听；访问日志为 JSON（源 IP、方法、目标、状态码）。镜像 `envoyproxy/envoy:distroless-v1.40.2`，非 root、只读根文件系统。
8. **本机 kind**：`kind-gvisor.sh` 的 Pod 网段改为 `10.244.0.0/16`（Calico IP 池同步设置），与 Docker Desktop 的宿主地址不重叠。P14 的白名单内外目标是 `deploy/kind/egress-echo.yaml` 的 `allowed-echo`、`denied-echo`（同一个 Envoy 以 `direct_response` 应答），由 `deploy-sandbox.sh` 部署；开发配置增加 sandbox 档环境 `env_dev_sandbox`（白名单只有 `allowed-echo`）。
9. **回调凭据**：Lua 脚本从环境变量读取凭据（来自 Secret `meridian-egress-proxy-credential`，chart 不创建它）。开发期与 knowledge 共用 `MERIDIAN_DEV_SERVICE_CREDENTIAL`，由 `deploy-sandbox.sh` 写进 Secret；T14b 换成服务 JWT 时要为代理另定凭据方式（登记事项 D38）。

## 候选方案

- 缓存放 Redis（每次回调查一次 Redis，清空 Pod IP 时删除键）：失效不依赖订阅，但每个出网请求多一次网络往返；与架构设计「认证」中 API Key 校验"本地缓存加 Pub/Sub 立即失效"的做法不一致。未采用。
- `sandbox_pod_ip` 加唯一约束：被复用的 IP 让新会话的认领落库失败，可用性更差；未采用，改为两行即拒绝。
- 沙箱不放行 DNS、代理地址写成 Service 的固定 ClusterIP：避免 DNS 隧道，但要固定 IP 段且与任务要求的"只能访问代理与 DNS"不一致；登记事项 D39，T37 评估。

## 影响

- 架构设计：「沙箱出网」补充以上细则；「可观测性」指标表增加 `meridian_egress_authorize_seconds`；「本地开发」写明 kind 的 Pod 网段；版本仍为 v1.14（与 ADR-0038 同一任务）。
- 新增：runtime 的 `egress` 上下文、迁移 `V0007`、内部接口、chart 的出网代理与网络策略、`deploy/kind/egress-echo.yaml`、`dev-config/agents/environment-sandbox.yaml`。
- 风险与验证：DNS 隧道（沙箱可以向任意域名发 DNS 查询），登记事项 D39（T37）；代理的指标采集、下线排空与节点池容忍，登记事项 D40；订阅中断的残余窗口见第 3 条；P14 由 `EgressProxyKindIT` 在 kind 中验证，缓存失效由 `SandboxEgressRevocationIT` 验证。
