# P11 状态缓存清理后的内存

| 项 | 内容 |
|---|---|
| 状态 | 通过（R1） |
| 通过标准 | 10 万个线程轮转后，堆内存稳定（架构设计「M0 技术验证」）；不稳定时按待决问题 Q6 定期重建引擎实例 |
| 环境 | MacBook Pro M1 Max；runtime 是宿主上的单个 JVM（Temurin 25.0.5，G1，`-Xmx6g -XX:ActiveProcessorCount=4`，`dev` profile，默认配置）；PostgreSQL 17.11、Redis 7.4.11、MinIO 在 Docker Desktop 的 compose 中 |
| 版本 | AgentScope 2.0.4、Spring Boot 4.1.2；测量于 2026-11-09 |

## 结论

通过，不需要 Q6 的缓解措施。经公开 API 创建 10 万个会话、每个会话执行一轮短对话（并发 50），全程由同一个共享的 `HarnessAgent` 实例执行。每 1 万个线程做一次 Full GC 后的存活对象统计：从第 1 万个线程起稳定在 59.1 至 60.1 MB，没有随线程数增长；全部结束后为 54.0 MB，空闲 30 秒后 53.8 MB。AgentScope 的状态缓存只在轮次执行期间持有本线程的槽：执行中的 `AgentState` 实例数始终不超过并发数（2 至 7 个），结束并空闲后为 0。

## 源码核对（2.0.4）

`ReActAgent` 按 `(userId, sessionId)` 在三个 `ConcurrentHashMap` 中缓存每个会话的数据：`stateCache`（`AgentState`）、`permissionEngineCache`（`PermissionEngine`）、`slotVersions`（乐观并发的版本号）。没有容量上限与过期，只有 `clearStateCache()`、`clearStateCache(ctx)`、`clearStateCache(userId, sessionId)` 释放（`ReActAgent.clearStateCache`，约 4476 至 4512 行）。平台的 `sessionId` 是线程 ID，每个线程一个槽：不清理时，共享实例每执行一个新线程就多留一份状态。

`AgentScopeEngine` 在每轮开始前（`begin`）与结束时（`finally`，含异常与取消）调用 `clearStateCache(userId, threadId)`；`SubagentRunner` 对子线程同样处理（架构设计「内核适配层」）。harness 层另有几个按键的 Map（`WorkspaceManager` 的锁、`HarnessSkillMiddleware` 的仓库缓存等），键是工作区路径或技能仓库，不随线程增长；本次的直方图也没有看到它们增长。

## 方法

- **驱动**：`scripts/perf/capacity.sh rotate --threads=100000 --concurrency=50 --checkpoint=10000 --runtime-pid=<PID>`（`scripts/perf/CapacityDriver.java`）。每个"线程"是一个新会话：创建会话 → 打开事件流 → 发一条 `#script:chat` 消息（脚本化模型服务的固定回答，流式 6 字符一块）→ 等 `session.status_idle` → 关闭事件流，之后不再使用这个会话。
- **测量**：开始前、每完成 1 万个、结束后、空闲 30 秒后，对 runtime 进程执行 `jcmd <PID> GC.class_histogram`（只统计存活对象，执行前做一次 Full GC），记录总量与 AgentScope 相关类的实例数。
- **规模**：10 万个会话、10 万轮，用时 1481 秒；结束后 `rt.sessions` 中留下 10 万行，事件与状态都在数据库中，不在 JVM 堆里。

## `clearStateCache` 前后的缓存大小

`StateCacheReleaseTest`（`meridian-engine-agentscope-test`）直接读取共享实例中三个缓存的大小，作为本项的回归测试：

| 时刻 | `stateCache` | `permissionEngineCache` | `slotVersions` |
|---|---|---|---|
| 一轮执行中（工具调用被闸门卡住） | 1 | 1 | 1 |
| 这一轮结束后（`finally` 中的 `clearStateCache`） | 0 | 0 | 0 |
| 200 个线程轮转之后 | 0 | 0 | 0 |

不调用 `clearStateCache` 时，这三个 Map 每执行一个新线程各多一项（2.0.4 的代码路径中没有其他移除），10 万个线程即 10 万份 `AgentState` 留在共享实例里，这正是本项要排除的情况。

## 发现

- 一轮内批次 checkpoint 之后，结束时的保存会遇到乐观并发冲突并以覆盖处理（AgentScope 打一条 `agent_state CAS conflict — OVERWRITE applied` 的 WARN）；数据正确、受租约约束，只是每轮多一次写入与一条日志（AgentScope 集成审查 A-F3，登记 D47）。

## 遗留

无。Q6 的结论写入架构设计「待决问题」：状态缓存清理后内存稳定，不需要定期重建引擎实例。
