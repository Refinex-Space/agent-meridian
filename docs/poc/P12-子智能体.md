# P12 子智能体：并行拉起同一子智能体与中断传递

| 项 | 内容 |
|---|---|
| 状态 | 通过（T13） |
| 通过标准 | 并行拉起同一子智能体时两条子线程的事件互不混淆；中断父线程时子线程同时停止（架构设计「M0 技术验证」） |
| 环境 | macOS arm64，Temurin 25.0.5+8；Testcontainers 中的 PostgreSQL 17、Redis、MinIO |
| 版本 | AgentScope 2.0.4、Spring Boot 4.1.2；验证于 2026-11-09 |

## 结论

通过。父智能体在一次推理中两次调用 `spawn_subagent` 拉起同名子智能体，Toolkit 并行执行两个调用（两次拉起相隔 4 毫秒），平台为每次拉起生成自己的子线程 ID，子线程的事件经 `EventSinkPort` 写入时带各自的 `thread_id`，两条线程的事件、流式增量与工具结果没有交叉。经公开 API 发送 `user.interrupt` 后，内核先中断本轮登记的两条子线程，再中断父线程：两条子线程在发出中断后 138 毫秒内都以 `interrupted` 结束（模型流的块间隔是 200 毫秒），父线程不再推理，以 `session.status_idle(interrupted)` 结束。

## 源码核对（2.0.4）

- `AgentSpawnTool`（不使用它的原因）：子会话 ID 由工具自己生成（`"sub-" + UUID` 或按标签哈希）；`agentsByKey`、`labelToKey` 是工具实例上的并发映射，被所有会话共享；子智能体的事件经父智能体的转发发射器带 `source` 进入父线程的事件流。
- `RuntimeContext.builder(source)` 即 `new Builder().from(source)`：复制 `sessionId`、`userId`、`agentState`、`toolExecutionContext`、`toolRequestConfig` 与全部字符串与类型化属性。`HarnessAgent.ensureSessionDefaults` 只在上下文中没有 `AbstractFilesystem` 时放入本实例的文件系统，所以复制父上下文会让子智能体沿用父线程的文件系统、状态与自定义工具。子线程的上下文必须从 `RuntimeContext.builder()` 空白构建。
- `ReActAgent.buildAgentStream`：每次 `streamEvents` 用自己的 `FluxSink`，并在 Reactor Context 中放入自己的 `EVENT_SINK_KEY` 与 `AgentEventEmitter.CONTEXT_KEY`，覆盖从调用方继承的同名键；只有存在 `FORWARDING_CONTEXT_KEY`（`agent_spawn` 安装）时才把事件转发给父线程。所以在父线程的工具调用里启动子智能体，子智能体的事件只出现在它自己的流上。
- `HarnessAgent.interrupt(userId, sessionId)` 委托 `AgentBase.interruptRunning`，只中断该 `(userId, sessionId)` 已受理的调用；中断父线程不影响另一个实例上的子智能体，所以平台要自己先中断子线程（架构设计「消息投递」）。受理之前的中断被丢弃，平台在受理后补发（`InterruptRelay`）。

## 做法

两层验证，都用真实装配的 `AgentScopeEngine`：

- 内核场景 `turn.SubagentScenarioTest.parallelSameNameSubagentsKeepEventsApartAndStopOnInterrupt`：父智能体与子智能体各用一个 `ScriptedModel`（按模型 ID 选择），子智能体的回应按请求内容生成（第一次调用探针工具回显自己的任务），两个子智能体同时卡在探针工具里时调用 `AgentEngine.interrupt`，再放行工具。
- 端到端 `config.SubagentSessionIT.parallelSameNameSubagentsAreIsolatedAndStopWhenTheParentIsInterrupted`：经 HTTP 启动的 runtime 用生产装配（`spawn_subagent`、`RoutedModelFactory`、线程登记与事件写入），供应商是脚本化模型服务；父智能体的脚本在一次推理中拉起两个同名子智能体，任务分别以 `#script:child-slow-a`、`#script:child-slow-b` 开头，两个子智能体逐字慢速输出"甲""乙"（80 字，块间隔 200 毫秒）；会话流带 `event_deltas=true`，看到两条子线程都已输出后经 `POST /v1/sessions/{id}/events` 发送 `user.interrupt`（节点频道触发立即续租，Worker 调用 `AgentEngine.interrupt`）。

```bash
./mvnw -pl meridian-engine-agentscope-test -am test -Dtest=SubagentScenarioTest -Dsurefire.failIfNoSpecifiedTests=false
./mvnw -pl meridian-runtime -am verify -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false \
  -Dit.test=SubagentSessionIT -Dfailsafe.failIfNoSpecifiedTests=false
```

## 结果

| 检查 | 内核场景 | 端到端 |
|---|---|---|
| 子线程 | 两条，ID 不同，`parent_tool_use_id` 分别对应两次调用 | `GET /v1/sessions/{id}/threads` 返回主线程与两条子线程，`parent_tool_use_id` 各不相同 |
| 事件互不混淆 | 每条子线程的事件只含自己任务的工具调用与结果（`probe:alpha` 与 `probe:beta` 不交叉） | 每条子线程的流式增量全是同一个字（一条只有"甲"，一条只有"乙"），持久化事件以 `session.thread_created` 开始 |
| 中断后子线程 | 两条都以 `session.thread_status_idle(interrupted)` 结束；子智能体的模型只被调用 2 次（各 1 次），放行工具后没有再推理 | 两条都以 `session.thread_status_idle(interrupted)` 结束，各自输出不到 80 字；发出中断到两条子线程结束 138 毫秒 |
| 父线程 | 以 `session.status_idle(interrupted)` 结束，模型只被调用 1 次；两个 `spawn_subagent` 的结果都是"was interrupted before it finished" | 同左；父线程的脚本只被请求 1 次 |
| 终态唯一 | 主线程恰好一个终态；子线程没有 `session.status_*` 事件 | 会话状态没有被子线程推进 |

同一批验证中的相关行为（T13 其他验收项）：超时 1 秒的子智能体在 1.02 秒时被取消，子线程以 `interrupted` 结束、父智能体收到超时结果并继续；每轮拉起上限配置为 2 时同一批的第 3 个调用被拒绝、不创建子线程。

## 遗留

- 子线程的事件逐条在各自的事务中写入（与主线程由 Worker 逐条写入相同）。事件量大的子智能体会增加数据库写入，容量在 P7（R1）中一并评估。
- 取消子智能体的订阅（超时、父线程失去租约）后，AgentScope 把内部的 `CancellationException` 交给 Reactor 的 `onErrorDropped`，日志中有一条 ERROR，不影响结果。
