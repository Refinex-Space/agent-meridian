# P4 两个档位的文件系统装配

| 项 | 内容 |
|---|---|
| 状态 | 进行中：`none` 档通过（T10a）；`sandbox` 档待 T12a |
| 通过标准 | runtime 节点本地磁盘上没有会话文件；沙箱档 `bash` 可用，受保护路径只读（架构设计「M0 技术验证」） |
| 环境 | macOS arm64，Temurin 25.0.5+8；Testcontainers 中的 PostgreSQL 17、Redis、MinIO |
| 版本 | AgentScope 2.0.4、Spring Boot 4.1.2；验证于 2026-11-08 |

## 结论（`none` 档）

`none` 档按架构设计「文件系统装配」工作：`abstractFilesystem(CompositeFilesystem(default = RemoteFilesystem(MeridianBaseStore), routes = 受保护路径 → ReadOnlyFilesystem))`。一轮读写文件的会话之后，小文件内联在 `rt.workspace_entries`、大文件在对象存储，平台控制的本机工作区根目录没有被创建，`${user.dir}/.agentscope` 没有新文件；受保护路径只读，写入被平台安全规则拒绝，即使绕过规则也被只读文件系统拒绝。

## 做法

真实装配的节点（`WorkerFixture` 的平台模式：生产的 `PlatformToolProvider`、`PlatformWorkspace`、`DatabaseWorkspaceStore`、工具账本与每轮的权限合成），`ScriptedModel` 驱动：

- `config.FileToolsWorkerIT#aTurnThatReadsAndWritesFilesLeavesNothingOnTheLocalDisk`：一轮中写一个 50 字节的周报与一个约 100 KB 的 CSV、编辑周报、分段读取 CSV、列目录。断言：
  - `rt.workspace_entries` 两行，命名空间都是 `[tenant_id, project_id, end_user_id, session_id]`（终端用户来自会话，经 `PlatformContext.endUserId`）；周报内联、版本 2（创建一次、编辑一次）；CSV 的 `object_key` 为 `rt/{tenant}/{session}/workspace/{ulid}`，对象在 MinIO 中，`size` 大于 64 KB。
  - 本机工作区根目录（装配时的 `workspace(...)`）不存在；`${user.dir}/.agentscope` 下没有测试开始之后修改的文件。
- `config.FileToolsWorkerIT#pathRulesAllowMatchingPathsDenyProtectedPathsAndAskForTheRest`：写 `AGENTS.md`、`skills/x/SKILL.md` 得到 DENIED，工作区中没有这两个键。
- `workspace.app.DatabaseWorkspaceStoreIT`：`putIfVersion` 的"不存在才创建"与版本匹配、64 KB 以上进对象存储且被替换或删除的对象随之删除、按命名空间前缀分页（含子命名空间，不跨会话与租户）。
- 内核层 `turn.FileToolScenarioTest`、`turn.SkillScenarioTest`（内存的 `WorkspaceStorePort`）：受保护路径的内容（`AGENTS.md` 为系统提示词、`skills/` 为技能文件）、列目录时的受保护条目、技能资源不暂存到本机工作区。

```bash
./mvnw -pl meridian-runtime -am verify -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false \
  -Dit.test='FileToolsWorkerIT,DatabaseWorkspaceStoreIT' -Dfailsafe.failIfNoSpecifiedTests=false
./mvnw -pl meridian-engine-agentscope-test -am test -Dtest='FileToolScenarioTest,SkillScenarioTest' \
  -Dsurefire.failIfNoSpecifiedTests=false
```

## 发现

- 不设 `workspace(...)` 时 harness 的本机工作区根是 `${user.dir}/.agentscope/workspace`：`WorkspaceManager` 读 `AGENTS.md`、`MEMORY.md` 时文件系统返回空就回退到本机文件；`MarketplaceStager` 每次构建系统提示词都把非 `WorkspaceSkillRepository` 仓库的技能资源写到 `.skills-cache/<用户>/`。平台把 `workspace(...)` 设为平台控制的目录，技能仓库继承 `WorkspaceSkillRepository`（被视为工作区原生，不暂存），本机因此没有写入（登记事项 D05，ADR-0034 第 8 条）。
- `CompositeFilesystem` 对单文件路由（`/AGENTS.md`）查存在性时传 `//AGENTS.md`，列目录时报告大小为 0；`ReadOnlyFilesystem` 合并开头的斜杠，`list_files` 对大小为 0 的条目不显示大小。
- `RemoteFilesystem.write` 只在键不存在时成功（`putIfVersion(…, 0)`），覆盖已有文件要走 `uploadFiles`；`ls`、`glob`、`grep` 都经 `search` 逐页读出整个会话命名空间，大文件也从对象存储读出（ADR-0034 的风险一条）。
- PostgreSQL 的数组切片 `namespace[1:4]` 中的 `:4` 会被 Spring 的命名参数解析当成参数，SQL 中写作 `namespace[1 : 4]`；`String[]` 参数绑定为 `varchar[]`，与 `text[]` 列比较时要显式 `CAST(... AS text[])`。
