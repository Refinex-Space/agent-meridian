# P15 权限改写：无人审批的执行不停在等待审批

| 项 | 内容 |
|---|---|
| 状态 | 通过（T08） |
| 通过标准 | `unattended` 会话和子线程在存在显式 ask 规则时都不会停在等待审批（架构设计「M0 技术验证」） |
| 环境 | macOS arm64，Temurin 25.0.5+8；Testcontainers 中的 PostgreSQL 17、Redis、MinIO |
| 版本 | AgentScope 2.0.4、Spring Boot 4.1.2；验证于 2026-11-08 |

## 结论

通过。2.0.4 的 `PermissionEngine` 在 `DONT_ASK` 下仍对显式 ask 规则返回 ask（只有最后一步的默认 ask 变成 deny），所以只换模式不够；平台在合成时把 ask 规则改写为 deny 之后，`unattended` 会话与子线程遇到显式 ask 规则时得到 DENIED 结果、智能体继续推理，没有待处理动作。`unattended` 会话无法进入计划模式。工具自检返回的安全类 ask 不受规则改写影响，由平台自动拒绝并立即运行恢复轮兜底。

## 源码核对（2.0.4）

- `PermissionEngine.checkPermission`：deny 规则 → ask 规则（命中即返回 ask，不看模式）→ 工具自检（`decisionReason` 含 `safety` 的 ask 直接返回）→ allow 规则 → BYPASS → 默认 ask（`DONT_ASK` 下为 deny）。
- `ReActAgent.applyConfirmResults`：批准时把 `ConfirmResult.rules` 加进本次调用缓存的 `PermissionEngine`，不写回 `PermissionContextState`，所以不会被持久化；平台每轮清理状态缓存后它就消失，"记住此决定"必须由平台保存（ADR-0031 第 5 条）。
- `ReActAgent.evaluatePermissions`：权限上下文"平凡"（`DEFAULT`、没有规则、没有工作目录）时不走 `PermissionEngine`，除工具自检的 ask 外一律放行。平台每轮注入平台安全规则，上下文永远不平凡（ADR-0031 第 3 条）。
- `PlanModeTools.PlanExitTool.checkPermissions` 恒为 ask（不带 `safety`），`DONT_ASK` 下落到默认 deny；`plan_enter` 没有自检，`unattended` 会话靠合成时追加的 deny 规则禁止。

## 做法

合成逻辑是 runtime 的纯函数 `approval.domain.PermissionSynthesizer`（单测 `PermissionSynthesizerTest`：五层优先级冲突、模式收紧、两种改写、子智能体 allow 子集、自定义工具放行）。判定用真实装配的 `AgentScopeEngine` 与 `ScriptedModel`：集成测试 `config.PermissionRewriteIT`，智能体对 `edit_doc(reports/**)` 显式 ask、对 `edit_doc` 整工具 allow，测试工具 `PathRuleTool`（testkit）实现 `matchRule`，规则内容是路径 glob。

```bash
./mvnw -pl meridian-runtime -am verify -Dtest=PermissionSynthesizerTest -Dsurefire.failIfNoSpecifiedTests=false \
  -Dit.test=PermissionRewriteIT -Dfailsafe.failIfNoSpecifiedTests=false
```

## 结果

| 场景 | 结果 |
|---|---|
| 有人值守，`edit_doc(reports/q3.md)` | 停在等待审批：一个 `tool_confirmation` 待处理动作，工具没有执行（对照组） |
| `unattended`，同一批调用 `reports/q3.md` 与 `drafts/notes.md` | 模式 `DONT_ASK`，ask 改写为 deny：`reports/q3.md` 得到 DENIED 结果，`drafts/notes.md` 照常执行；智能体继续推理，以 `end_turn` 结束；没有待处理动作，事件中没有 `session.status_requires_action` |
| 子线程（用 `PermissionSynthesizer.subagents` 为子智能体合成的策略直接驱动内核，T13 的 `spawn_subagent` 之前验证改写本身） | 策略为 `DONT_ASK`，父智能体的 ask 改写为 deny；`reports/q3.md` 得到 DENIED，事件流以 `session.status_idle(end_turn)` 结束，没有 `session.status_requires_action` |
| `unattended`，智能体开启计划模式，模型调用 `plan_enter` | DENIED，没有待处理动作，以 `end_turn` 结束 |
| `unattended`，工具自检对 `secrets.txt` 返回安全类 ask | 内核以 `PERMISSION_ASKING` 结束；平台不产生待处理动作，本轮以 `session.status_idle(tools_denied)` 结束并入队 `confirmations` 恢复轮；恢复轮把拒绝结果（"无人值守的会话无法审批，平台已自动拒绝"）交给智能体，以 `end_turn` 结束；审计记录 `permission.decided(denied, source=unattended)` |
| 平台安全规则（智能体 `BYPASS` 且对 `write_file` 整工具 allow） | `write_file(AGENTS.md)`、`write_file(skills/x/SKILL.md)`、`read_file(.env)`、`read_file(config/id_rsa)` 全部 DENIED；`write_file(reports/q3.md)`、`read_file(docs/readme.md)` 执行 |

## 遗留

- 子线程的端到端（`spawn_subagent` 使用 `TurnContext.subagentPolicies`、子智能体以 `PERMISSION_ASKING` 结束时转成拒绝结果）由 T13 验证。
- 平台文件工具的 `matchRule` 必须按 `**` 匹配零或多级目录解释规则内容（T10a）；bash 对受保护路径的保护在 T12a。
