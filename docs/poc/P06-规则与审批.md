## 结论（T08 部分）

审批流程按架构设计「待处理动作」工作：权限判为 ask 产生 `tool_confirmation`，批准后工具按原入参（或审批人修改后的入参）执行，拒绝后智能体收到 DENIED 结果并继续，超时视为拒绝；内容级规则经工具自己的 `matchRule` 生效。`bash(git status:*)` 本身要等 T12a 的 bash 工具实现 `matchRule` 后验证。

## 做法

真实装配的 `AgentScopeEngine` 与 `ScriptedModel`，回应经与 API 相同的发送事件用例（`EventIntake`）：

- `config.ApprovalFlowIT`：ask → `tool_confirmation`（动作带工具名与入参）；批准后执行、工具结果 `permission=approved`；批准时修改入参；拒绝（带理由）后模型收到 DENIED 结果与理由、继续推理；超时（时钟推进 30 分钟、超时扫描）视为拒绝；"记住此决定"的会话级与项目级规则在后续轮次生效；审计 outbox 记录 `permission.decided` 与 `pending_action.concluded`。
- `config.PermissionRewriteIT`：测试工具 `PathRuleTool` 实现 `matchRule`（路径 glob），智能体对 `edit_doc(reports/**)` ask、对 `edit_doc` allow：有人值守时 `reports/q3.md` 触发审批，`drafts/notes.md` 直接执行；平台安全规则对 `AGENTS.md`、`skills/**`、`.env`、`id_rsa*` 的 deny 优先于智能体的 allow。

```bash
./mvnw -pl meridian-runtime -am verify -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false \
  -Dit.test='ApprovalFlowIT,PermissionRewriteIT' -Dfailsafe.failIfNoSpecifiedTests=false
```

## 发现

- 2.0.4 对"平凡"的权限上下文（`DEFAULT`、没有规则）不走权限引擎、一律放行；平台每轮注入平台安全规则，上下文因此永远不平凡，`DEFAULT` 模式下没有命中 allow 的调用都需要确认。智能体版本必须显式放行它的工具；会话声明的自定义工具在会话层默认放行（ADR-0031 第 3 条）。
- 一批工具中只要有一个需要确认，2.0.4 整批都不执行（包括已放行的与自定义工具），确认之后整批一起执行；所以"同批既有待确认调用又有自定义工具"实际表现为先确认、确认轮执行后自定义工具再挂起。
