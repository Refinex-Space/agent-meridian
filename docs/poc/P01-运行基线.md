## 依赖解析（T01）

### 做法

`meridian-bom` 导入 `spring-boot-dependencies:4.1.2`，单独声明三个 AgentScope 构件，不导入 `agentscope-dependencies-bom`（它锁定 Boot 4.0.4）。`meridian-common` 依赖 Jackson 3，`meridian-engine-agentscope` 依赖 common 与三个 AgentScope 构件。

```bash
./mvnw -pl meridian-engine-agentscope -am dependency:tree -Dverbose
```

### 结论

依赖解析通过。补丁级与小版本的提升风险低；需要运行验证的是 **Netty 4.1 → 4.2**：Vert.x 4.5 基于 Netty 4.1 构建，fabric8 的 Vert.x HTTP 客户端在 Netty 4.2 下能否正常工作要在真实调用中确认。已在 `docs/plan/PLAN.md`「登记事项」登记，由 T03（运行基线）与 T11（沙箱驱动）验证。

## 运行验证（T03）

### 做法

`meridian-runtime` 的 `config` 包下的集成测试 `AgentScopeRuntimeBaselineIT`，在一个 JVM 里同时做三件事：

1. 启动最小的 WebFlux 应用上下文：只导入 Netty 服务器、WebFlux、编解码与 Jackson 的自动配置，不连数据库与 Redis；`JsonMapper` Bean 用平台的 `JsonMappers.strict()`（Jackson 3，snake_case，RFC 3339）。
2. HTTP 入口 `POST /p1/agent-runs` 在 `boundedElastic` 上经 `AgentInstanceCache` 装配 `HarnessAgent`（`AgentAssembler` 加测试夹具），由 `ScriptedModel` 驱动一次 `streamEvents`：第一次模型调用发起 `echo` 工具调用，第二次根据工具结果作答；`doFinally` 中归还实例。响应体由 Jackson 3 序列化。
3. 用 AgentScope Kubernetes 扩展所用的 fabric8 Vert.x HTTP 客户端（`VertxHttpClientFactory`）请求同一个服务，回应登记事项 D03。

全程安装 BlockHound（架构设计「测试策略」要求 runtime 测试开启）。

```bash
./mvnw -pl meridian-runtime -am verify -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false \
  -Dit.test=AgentScopeRuntimeBaselineIT -Dfailsafe.failIfNoSpecifiedTests=false
```

### 与架构设计不符或架构设计未写到的 AgentScope 行为

| 发现 | 处理 |
|---|---|
| `maxRetries(int)` 是含首次在内的总尝试次数，`<=0` 抛 `IllegalArgumentException`；重试只在供应商模型类中按 `GenerateOptions.executionConfig.maxAttempts` 执行，默认 3 | 变更型，ADR-0023（已采纳）：装配改为 `maxRetries(1)` |
| 只设置 `messageBus(NoopMessageBus)` 时，`build()` 仍创建基于工作区的 `WorkspaceAsyncToolRegistry`，`InboxMiddleware` 每次推理前读工作区 | 补充型，ADR-0024：同时注入 `NoopAsyncToolRegistry`，测试带对照实验 |
| 默认安装的 `AgentTraceMiddleware` 以 INFO 记录模型回复正文 | 补充型，ADR-0024：`enableAgentTracingLog(false)` |
| `Toolkit.copy()` 不转移 MCP 客户端所有权，经 `Builder.toolkit(...)` 传入的工具包上的 MCP 客户端不会被 `HarnessAgent.close()` 关闭 | 补充型，ADR-0024：平台资源随 `AssembledAgent.close()` 关闭 |
| `disableDynamicSkills()` 在构建时用 `RuntimeContext.empty()` 枚举并冻结技能清单 | 补充型，ADR-0024：技能仓库按装配时的智能体版本解析（T10a） |
| 全部源码中没有给 `GenerateReason.STRUCTURED_OUTPUT` 赋值，结构化输出完成时结果为 `MODEL_STOP` | 不影响架构：两者在「状态机」的停止原因映射中都是 `end_turn`；T04 的穷举映射保留该值 |
| `generate_response` 工具的入参形如 `{"response": {...}}` | `ScriptedResponse.structuredOutput` 按此构造 |
| 不设置 `workspace(...)` 时工作区根取 `${user.dir}/.agentscope/workspace`；harness 会读取其中的 `skills/`（第 3 层技能）并在其中暂存技能资源 | 登记事项 D05，由 T10a 在装配文件系统与技能时确定本机工作区根目录 |
| JDK 25 把 `System.loadLibrary` 列为受限方法，reactor-netty 加载 Netty 本地传输库时告警"将来会被阻止" | runtime 的 Failsafe 加 `--enable-native-access=ALL-UNNAMED`；生产 JVM 参数同样需要，由 T28（部署）写入 |

### 结论

通过。Spring Boot 4.1.2、JDK 25 下，同一 JVM 中 Jackson 3 的 Web 序列化与 AgentScope 2.0.4 的智能体调用都正常，Jackson 2 与 3 互不干扰。Netty 4.1 → 4.2 的提升在本地真实 HTTP 调用中未见问题；对 Kubernetes API 的调用由 T11 在 kind 集群中再验证。
