## 依赖解析（T01）

### 做法

`meridian-bom` 导入 `spring-boot-dependencies:4.1.2`，单独声明三个 AgentScope 构件，不导入 `agentscope-dependencies-bom`（它锁定 Boot 4.0.4）。`meridian-common` 依赖 Jackson 3，`meridian-engine-agentscope` 依赖 common 与三个 AgentScope 构件。

```bash
./mvnw -pl meridian-engine-agentscope -am dependency:tree -Dverbose
```

### 结果

依赖树中的关键行：

```text
cn.refinex.meridian:meridian-engine-agentscope:jar:0.1.0-SNAPSHOT
|  \- tools.jackson.core:jackson-databind:jar:3.1.7:compile
+- io.agentscope:agentscope-core:jar:2.0.4:compile
|  +- io.projectreactor:reactor-core:jar:3.8.8:compile (version managed from 3.8.2)
|  +- com.fasterxml.jackson.core:jackson-databind:jar:2.21.7:compile (version managed from 2.21.1)
|  +- io.modelcontextprotocol.sdk:mcp:jar:0.17.2:compile
+- io.agentscope:agentscope-harness:jar:2.0.4:compile
+- io.agentscope:agentscope-extensions-sandbox-kubernetes:jar:2.0.4:compile
```

- Jackson 2（`com.fasterxml.jackson`，2.21.7）与 Jackson 3（`tools.jackson`，3.1.7）共存，包名不同，不冲突。两者共用 `com.fasterxml.jackson.core:jackson-annotations:2.21`。
- MCP Java SDK 解析为 0.17.2，Boot 不管理它。
- 有效 POM 中 `org.springframework.boot:spring-boot` 的管理版本为 4.1.2；临时给 runtime 加 `spring-boot-starter-webflux` 后，同一棵树中同时出现 `spring-boot:4.1.2`、Jackson 3.1.7、Jackson 2.21.7 与 AgentScope 2.0.4（验证后已撤销）。

Boot BOM 覆盖了 AgentScope 的以下传递依赖版本（`-Dverbose` 的 `version managed from`）：

| 构件 | AgentScope 声明 | 实际 |
|---|---|---|
| `com.fasterxml.jackson.*`（databind、jsr310、yaml） | 2.21.1 | 2.21.7 |
| `io.projectreactor:reactor-core` | 3.8.2 | 3.8.8 |
| `io.netty:*`（经 fabric8 `kubernetes-httpclient-vertx` → `vertx-core` 4.5.28） | 4.1.135.Final | 4.2.19.Final |
| `io.opentelemetry:opentelemetry-api` | 1.61.0 | 1.62.0 |
| `org.slf4j:slf4j-api` | 2.0.17 | 2.0.20 |
| `org.xerial:sqlite-jdbc` | 3.47.1.0 | 3.53.4.0 |
| `org.apache.commons:commons-lang3` | 3.16.0 | 3.20.0 |
| `commons-codec:commons-codec` | 1.17.1 | 1.21.0 |
| `org.jetbrains.kotlin:kotlin-stdlib` | 2.2.21 | 2.3.21 |

### 结论

依赖解析通过。补丁级与小版本的提升风险低；需要运行验证的是 **Netty 4.1 → 4.2**：Vert.x 4.5 基于 Netty 4.1 构建，fabric8 的 Vert.x HTTP 客户端在 Netty 4.2 下能否正常工作要在真实调用中确认。已在 `docs/plan/PLAN.md`「登记事项」登记，由 T03（运行基线）与 T11（沙箱驱动）验证。
