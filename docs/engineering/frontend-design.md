# 控制台设计系统与前端工程规范

本规范规定 AgentMeridian 控制台的设计语言、设计令牌、组件与依赖选型、交互与状态模式，以及前端工程的组织方式。控制台相关的任务（T20a 至 T25b、R3）都以它为准。架构设计"控制台"一节给出了页面范围和技术栈，本规范把它们落到可执行的标准。

文中给出的颜色、字体、尺寸是**设计方向的起点**。T20a 在 Storybook 中把它们实现为令牌，经用户确认视觉方向、T20c 截图评审后定稿；定稿值写回本文件，此后修改走 ADR。

## 控制台是给谁用的

| 用户 | 在控制台里做什么 | 最在意 |
|---|---|---|
| 平台管理员 | 管理租户、成员、模型供应商、凭据、预算 | 配置正确、改动可追溯、危险操作有后果提示 |
| 智能体开发者 | 定义和发布智能体、调试会话、查看事件轨迹 | 信息完整、定位问题快、能看清每一步发生了什么 |
| 审批人 | 处理待审批的工具调用 | 一眼看懂"要批准的是什么、会产生什么影响" |
| 运营与财务 | 看用量、成本、预算 | 数字准确、口径清楚 |

主要工作是**观察和治理智能体的执行**。控制台的气质应该像一台精密仪器：安静、准确、信息密集但有秩序。它不是营销页面，也不是聊天应用。

## 设计方向

### 概念

Meridian 是子午线：导航、测绘、天文观测共同的基准线。控制台借用这个领域的视觉语汇，比如海图的冷白纸面、测绘仪器的刻度、黄铜指针、精确的细线，但只取其精神，不做拟物装饰。

**大胆只用在一处：会话时间轴。** 它是控制台最有辨识度的元素：一条竖直的"子午线"贯穿事件序列，刻度标出时间，子线程从主线分叉，运行中的"此刻"位置用黄铜色标记。其余界面都保持克制，为它让路。

### 色彩

起点色板（亮色主题）：

| 名称 | 值 | 用途 |
|---|---|---|
| 海图白 Chart White | `#F5F7F6` | 应用背景，带一点冷绿灰，像海图纸 |
| 纸面 Surface | `#FFFFFF` | 内容区、面板、表格 |
| 墨 Ink | `#1B2420` | 正文与标题；墨绿黑，不用 `#111`、`#0B0B0B` 这类近黑 |
| 石墨 Graphite | `#5B6560` | 次要文字、图标 |
| 刻线 Rule | `#D8DDDA` | 边框、分隔线 |
| 海图蓝 Chart Blue | `#2456A3` | 主操作、链接、焦点环、选中态 |
| 黄铜 Brass | `#B3862C` | 只用于时间轴的"此刻"标记、需要人工处理的状态 |

暗色主题以深海图夜色 `#121A1F` 为背景、`#1A242B` 为面板，文字 `#E3E9EC`，刻线 `#2B3740`，海图蓝提亮到 `#6E9FE6`，黄铜提亮到 `#D4A64E`。

语义色与状态映射（全控制台统一，任何页面不得另起一套）：

| 语义 | 色 | 用于 |
|---|---|---|
| 运行中 | 海图蓝 | `session.status_running`、进行中的轮次 |
| 等待处理 | 黄铜 | `requires_action`、待审批 |
| 空闲 / 已结束 | 石墨 | `idle`、`completed` |
| 重新调度 | 海图蓝的浅色 | `rescheduled` |
| 成功 | 海绿 `#2E7A58` | 工具成功、健康 |
| 失败 / 危险 | 信号红 `#BE3A31` | `error`、拒绝、删除类操作 |
| 已终止 | 石墨的浅色 | `terminated` |

规则：

- 令牌用 OKLCH 定义在 CSS 变量中，亮暗两套。组件里**禁止**出现十六进制颜色、`rgb()`，以及 Tailwind 的任意色值写法（`bg-[#...]`），由 lint 检查。
- 正文与背景对比度至少 4.5:1，大字和图标至少 3:1（WCAG 2.2 AA）。
- 状态不能只靠颜色区分：同时有图标或文字。
- 图表配色按 dataviz 技能的方法生成并校验，类别色不超过 8 种。

### 字体

| 用途 | 字体 | 理由 |
|---|---|---|
| 界面中文 | IBM Plex Sans SC | 与西文同一家族，中西混排的笔画粗细与字面高度一致；工程气质与"仪器"方向吻合；SIL OFL 许可 |
| 界面西文与数字 | IBM Plex Sans | 同上；有等宽数字（`tabular-nums`），表格中的数字对齐 |
| ID、代码、JSON、日志 | IBM Plex Mono | 只用于真正的机器文本，**不**用来装饰标签 |

- 自托管，离线环境同样可用。IBM Plex Sans 与 IBM Plex Mono 用 `@fontsource` 的包；IBM Plex Sans SC 在 `@fontsource` 上不存在，使用 IBM 官方包 `@ibm/plex-sans-sc`（解压约 124 MB），在构建期按 `unicode-range` 切片（例如用 cn-font-split），只打包 400、500、600 三个字重，浏览器按需加载用到的切片。
- 字号阶梯（以 14px 正文为基准，适配高密度控制台）：12、13、14、16、18、22、28。行高：正文 1.5，标题 1.3，表格 1.4。
- 字重只用 400、500、600。层级靠字号、字重和颜色，不靠全大写和字距。
- 中文排版：中西文之间留空（由文案保证，不用 CSS 自动加）；标点用全角；一行不超过约 40 个汉字（长文本区域）。

### 形状、间距与层级

- 间距以 4px 为单位：4、8、12、16、24、32、48。
- 圆角按层级区分，不是一个值用到底：控件 4px，卡片和面板 6px，浮层 8px；标签、徽标用 4px。**禁止**全局的胶囊按钮。
- 层级靠背景层次和 1px 刻线表达。阴影只给浮层（下拉、对话框、提示），而且只有一种柔和阴影。
- 布局默认左对齐。数字列右对齐。

### 图标

- **图标库：Phosphor Icons**（MIT）。选择理由：有 6 种字重，可以用 regular 表示默认、fill 表示激活或选中，而不用换一套图标；覆盖面广，按需引入可摇树。弃选 Lucide：功能没问题，但它是 shadcn 的默认图标，和默认主题一起构成了最常见的"模板脸"。
- 全控制台只用一个图标库，**禁止**混用其他库的图标。shadcn/ui 生成的组件默认引用 `lucide-react`，生成后必须全部替换为 Phosphor 的封装；ESLint 用 `no-restricted-imports` 禁止 `lucide-react` 与 `@radix-ui/react-icons`。
- 尺寸只有 16、20、24 三档，颜色一律 `currentColor`。
- **自研 SVG**：品牌标识（子午线弧加刻度的标记）、领域图标（智能体、线程、轮次、沙箱、待处理动作、技能、知识库）、空态插画。规则：
  - 按 Phosphor 的 256 网格和 regular 字重的线宽绘制，与库内图标并排时看不出差别。
  - 用 SVGO 优化，以 SVGR 生成 React 组件，放在 `src/assets/icons/`，每个图标在 Storybook 中展示。
  - 空态插画只用线条和最多一种强调色，不用渐变、3D、卡通形象。

### 动效

- **唯一的编排时刻：会话时间轴。** 运行中，新事件沿子午线依次落位（200ms，ease-out），"此刻"标记以 2 秒周期轻微呼吸。
- 其余动效只回应用户的操作：面板展开收起、对话框出现、行内编辑切换，150 至 250ms，进入用 ease-out，退出用 ease-in。
- 不动的东西：表格行、数字（不做滚动计数）、页面切换（不做整页淡入）、卡片悬停（不做上浮和放大）。
- 尊重 `prefers-reduced-motion`：关闭位移动画，只保留不透明度变化。

## 禁用清单

下面这些是 AI 生成界面最常见的模板化特征。它们本身并非一无是处，但在这个控制台里都是"没有经过选择的默认值"。评审时逐条对照，出现即改。

**视觉**

1. 未经改造的 shadcn 默认主题（zinc 灰、默认圆角、默认阴影）。
2. 紫色、靛蓝到粉色的渐变；任何作为装饰的渐变背景和渐变文字。
3. 玻璃拟态、背景模糊卡片、霓虹光晕、装饰性光斑。
4. 所有内容都切成同样圆角、同样阴影的卡片（"SaaS 卡片套件"）。
5. 首页放四个大数字统计卡片，配假的涨跌箭头和迷你趋势图。
6. 暖奶油色背景配衬线大标题和陶土色强调；近黑背景配单一荧光绿或朱红强调；报纸式细线零圆角密排。
7. 通体胶囊按钮；每个元素都有悬停上浮。
8. emoji、"✨"类 AI 图标、机器人头像作为装饰。

**排版与文案**

9. 标题里只把一个词变色、加粗或改成斜体做强调。
10. 全大写、加宽字距的小标签放在每个标题上方（eyebrow）。
11. 等宽字体用作装饰性标签。
12. 用中点拼接的元信息串（"A · B · C"）、"词 — 片段"式标签、按钮和链接文字后面加"→"。
13. 内容不是序列却加"01 / 02 / 03"编号。
14. 营销腔文案："释放 AI 的力量"、"开启智能新时代"；占位文字（Lorem ipsum、"示例描述"）出现在交付界面中。
15. 每个区块下方都有一段解释性小字。补充信息放进 info 图标的提示里。

**交互**

16. 整页转圈加载；骨架屏和最终布局几何不一致导致跳动。
17. 每个操作都弹成功 toast。
18. 删除等不可逆操作没有后果说明，或者只是"确定吗？"。

**能机检的条目必须机检**：渐变（`bg-gradient-*`、`linear-gradient`）、`backdrop-blur`、`uppercase` 与 `tracking-*` 同时使用、按钮上的 `rounded-full`、JSX 文本中的 emoji 与"→"，都写成 lint 规则或检查脚本，接入控制台的 lint。其余条目在截图评审中人工检查。

## 组件与依赖选型

选型原则：无障碍有保障，源码可控，能被我们的令牌完全重塑，同一类能力只选一个。版本在 T20a 和 T21 中确认（最新稳定版，发布至少两周），记录在 ADR-0021。

| 能力 | 选型 | 理由 | 弃选及原因 |
|---|---|---|---|
| UI 基元 | Radix Primitives，经 shadcn/ui CLI 生成源码进仓库，再按本规范重塑 | 无障碍行为完整；源码在仓库里，样式完全由我们决定，没有运行时主题锁定 | Ant Design、Arco、Semi：视觉语言强烈且难以彻底改造，与 Tailwind 冲突，体积大。MUI：Material 设计语言。Mantine：自带样式体系，与 Tailwind 4 二选一 |
| 样式 | Tailwind CSS 4，令牌以 CSS 变量注入 `@theme` | 架构设计已定；令牌即单一事实来源 | CSS-in-JS：运行时成本，与 RSC 无关但无必要 |
| 路由 | TanStack Router | 类型安全的路由与搜索参数，筛选条件放 URL | React Router：搜索参数类型支持弱 |
| 服务端状态 | TanStack Query | 缓存、重试、失效、乐观更新 | 自写 fetch 状态管理 |
| 客户端状态 | URL 搜索参数加组件局部状态；确需全局时用 Zustand，需写 ADR | 绝大多数状态属于服务端或 URL | Redux：样板代码多 |
| API 客户端 | openapi-typescript 生成类型，openapi-fetch 调用 | 类型从 OpenAPI 生成，运行时极小，禁止手写接口类型 | 手写 axios 封装 |
| 表单 | React Hook Form 加 Zod | 性能好，校验声明式；Zod schema 用 `satisfies` 对齐生成的类型 | Formik：维护不活跃 |
| 表格 | TanStack Table 加 TanStack Virtual | 无头，样式完全自控；万行虚拟滚动 | AG Grid：重且风格固定 |
| 通知 | Sonner，按令牌重塑 | 轻量，堆叠与可访问性好 | — |
| 命令面板 | cmdk | ⌘K 全局搜索与跳转 | — |
| 动效 | motion | 架构设计已定；布局动画与手势 | — |
| 图表 | ECharts，按需引入，主题读取令牌 | 架构设计已定；时序、热力、大数据量表现好 | — |
| 代码与 JSON 编辑 | Monaco，懒加载 | 智能体提示词、技能、JSON 配置编辑 | CodeMirror：可行，但 Monaco 的 JSON Schema 校验更省事 |
| 代码高亮（只读） | Shiki | 与编辑器主题一致的静态高亮，用于事件详情 | Prism：主题生态弱 |
| Markdown 渲染 | react-markdown 加 rehype-sanitize | 渲染智能体消息，必须消毒 | dangerouslySetInnerHTML：XSS 风险 |
| 拓扑图 | xyflow | 子智能体拓扑 | — |
| 终端 | xterm.js | 二期 Web 终端 | — |
| 日期 | date-fns 加 zh-CN 语言包 | 函数式，按需引入 | Moment：已停止开发 |
| 图标 | Phosphor Icons 加自研 SVG | 见"图标" | Lucide：见"图标" |
| 字体 | `@fontsource` 的 IBM Plex Sans 与 Mono；`@ibm/plex-sans-sc` 构建期切片 | 见"字体" | — |
| 组件开发与文档 | Storybook，含 a11y 插件 | 组件状态全覆盖，同时作为可交互原型 | Ladle：生态小 |
| 接口模拟 | MSW | 原型阶段与测试共用同一套接口模拟 | — |
| 测试 | Vitest、Testing Library、Playwright | 见测试规范 | — |
| 代码规范 | ESLint（typescript-eslint、react-hooks、jsx-a11y）加 Prettier | react-hooks 与 jsx-a11y 规则成熟 | Biome：速度快，但无障碍与 Hooks 规则覆盖不如前者 |

## 自研组件

通用基元（来自 shadcn 源码、按令牌重塑）放在 `src/components/ui/`。领域组件放在 `src/components/domain/`，每个都有 Storybook 故事，覆盖全部状态。领域组件清单：

| 组件 | 职责 |
|---|---|
| `StatusBadge` | 会话、轮次、工具调用、待处理动作的状态，颜色与图标按语义映射表 |
| `SessionTimeline` | 子午线时间轴：事件序列、子线程分叉、运行中的"此刻"标记、新事件落位动画 |
| `EventCard` | 单个事件的摘要，按事件类型选择渲染器 |
| `ToolCallView` | 工具调用的入参、结果、权限结论、耗时 |
| `ThreadTree` | 线程树导航 |
| `InspectorPanel` | 右侧详情面板：选中事件的完整内容、原始 JSON、复制 |
| `TokenUsage` | 输入、输出、缓存、推理 token 与成本，数字等宽对齐 |
| `CopyableId` | 带前缀 ID 的等宽显示，中间省略，一键复制并给出反馈 |
| `RelativeTime` | 相对时间，悬停显示绝对时间与时区 |
| `EmptyState` | 首次使用的空态（带主操作）与筛选结果为空（带清除筛选） |
| `ErrorState` | problem+json 错误：原因、下一步、可复制的 `request_id`、重试 |
| `PermissionGate` | 按角色隐藏或禁用操作，并说明原因 |
| `DangerConfirmDialog` | 不可逆操作的确认：写明后果；删除类要求输入名称确认 |
| `PageHeader` | 页面标题、面包屑、主操作 |
| `FilterBar` | 筛选与搜索，状态同步到 URL |
| `DataTable` | 基于 TanStack Table 的表格封装：排序、分页、列显隐、批量操作、虚拟滚动 |
| `KeyValueList` | 详情页的属性列表 |
| `CodeBlock` | 只读代码与 JSON，Shiki 高亮，复制 |
| `StreamIndicator` | SSE 连接状态：已连接、重连中、已断开 |

同一个能力只有一个组件。新增领域组件前先查这张表；表里没有的，先在这里加一行。

## 布局

### 应用外壳

```text
┌──────────┬──────────────────────────────────────────────────────┐
│ ◇ 标识    │ 面包屑                          ⌘K 搜索   用户菜单     │
│ 项目切换  ├──────────────────────────────────────────────────────┤
│          │ 页面标题                                    [主操作]    │
│ 导航      │                                                      │
│  概览     │ 内容区（左对齐，宽表格页满宽，表单页最大 880px）        │
│  会话     │                                                      │
│  ...     │                                                      │
│          │                                                      │
│ 折叠      │                                                      │
└──────────┴──────────────────────────────────────────────────────┘
```

- 左侧导航宽 232px，可折叠为 56px 图标栏，折叠状态记在本地。
- 目标视口：桌面 1280 至 2560px 宽。1024px 时仍可用。移动端不作为目标，但不能横向溢出。

### 会话详情（时间轴页）

```text
┌──────────────┬──────────────────────────────────┬─────────────────┐
│ 线程树        │ 子午线时间轴                        │ 检查器           │
│ ● 主线程      │  │ 10:02:11  用户消息                │ 选中事件的完整   │
│   ├ 子线程 A  │  ├── 10:02:12  调用 knowledge_search │ 内容、原始 JSON、 │
│   └ 子线程 B  │  │   └ 结果 8 条                     │ 权限结论、耗时、  │
│              │  ◆ 此刻（运行中，黄铜色）            │ token 与成本      │
│ 待处理动作 1  │                                    │                 │
└──────────────┴──────────────────────────────────┴─────────────────┘
```

三栏可调宽度，检查器可收起。时间轴支持键盘上下移动选中事件。

### 页面模板

全控制台只有四种页面模板，新页面必须选其一：

| 模板 | 结构 | 例子 |
|---|---|---|
| 列表页 | 页头、筛选栏、数据表格 | 会话列表、智能体列表、API Key |
| 详情页 | 页头（含状态与主操作）、标签页、属性列表与子表格 | 智能体详情、知识库详情 |
| 编辑页 | 左侧表单分组导航，右侧表单；底部固定的保存栏 | 智能体定义、环境 |
| 工作台 | 多栏可调布局 | 会话详情、Playground |

## 状态与反馈

### 加载

- 区域级加载：每个独立的数据区域有自己的 Suspense 边界，**禁止**整页转圈。
- 骨架屏与最终布局的几何一致，包括行高、列宽、头像与图标的位置，加载完成时不跳动。
- 请求在 150ms 内返回时不显示骨架；一旦显示，至少保持 300ms，避免闪烁。
- 骨架使用柔和的不透明度呼吸，不用从左到右的高光扫过；`prefers-reduced-motion` 时为静态。
- 按钮触发的操作：按钮内显示进度，禁止重复提交，不遮挡页面。

### 空态

- **首次使用**：一句话说明这里会出现什么，加一个主操作（"创建智能体"）。
- **筛选后为空**：说明没有匹配项，提供"清除筛选"。
- 不放大幅插画，不写营销文案。

### 错误

- 错误映射自 problem+json：写明发生了什么、用户下一步能做什么，并提供可复制的 `request_id`。
- 表单错误就近显示在字段下方，提交时聚焦到第一个错误字段。
- 区域加载失败时，该区域显示错误与重试，页面其他部分照常可用。
- 权限不足：说明缺少的角色或作用域，不显示一个空白页面。

### 通知策略

| 情况 | 方式 |
|---|---|
| 操作结果就在当前视野里（保存后表单变为已保存状态） | 不额外通知 |
| 异步操作完成、结果不在视野里（知识库文档写入完成） | toast，可跳转 |
| 操作失败且用户需要知道 | toast（错误样式）或就地错误，带 `request_id` |
| 影响整个应用的状态（与服务端断开、预算告警） | 页面顶部横幅，可关闭 |
| 有需要人处理的事项（待处理动作） | 导航上的计数徽标；会话页的黄铜色标记 |

toast 同时最多 3 条，成功类 4 秒消失，错误类需要手动关闭。

### 实时数据

- 会话页通过 SSE 实时更新，顶部 `StreamIndicator` 显示连接状态。断线自动重连，并按 `Last-Event-ID` 补齐事件，与"SSE 协议"一节一致。
- 列表页的实时变化（新会话、状态变化）不打断用户：在表头上方提示"有 N 条更新"，点击后刷新。

## 交互规范

- **键盘**：⌘K 打开命令面板；`/` 聚焦当前页搜索；`Esc` 关闭浮层；时间轴和表格支持方向键。所有可交互元素可 Tab 到达，焦点环清晰可见（海图蓝 2px）。
- **表单**：失焦时校验格式，提交时全量校验；未保存就离开时提示；只读与禁用在视觉上区分。
- **不可逆操作**：确认对话框写明后果（"删除后，该智能体的 12 个会话将无法继续"）；删除租户、吊销 API Key 等最高风险操作要求输入名称确认。
- **乐观更新**：只用于开关类、可撤销的操作。
- **复制**：ID、Key 片段、JSON 都可一键复制，复制后图标短暂变为对勾。
- **时间**：列表中显示相对时间，悬停显示绝对时间（含时区）；详情中显示绝对时间。
- **数字**：千分位；token 用 K、M 缩写并在悬停时给出精确值；金额保留两位小数并标明币种。
- **长内容**：智能体消息、工具结果默认折叠到合理高度，可展开；超大结果显示对象存储引用，按需加载。

## 文案

- 中文，句子式，不用感叹号和 emoji。
- 按用户理解的概念命名，不按系统实现命名：用"通知地址"而不是"Webhook 配置"，必要时在提示里给出技术名。
- 按钮写清动作：用"发布版本"而不是"提交"。同一动作在流程中保持同名，按钮叫"发布"，结果就提示"已发布"。
- 错误不道歉，也不含糊：写原因和下一步。
- 术语与架构设计的术语表保持一致：会话、线程、轮次、待处理动作、环境、档位。

## 设计流程与评审

T20a 至 T20c 按以下顺序完成设计，每一步都有可检查的产物。T20a 完成设计计划、令牌、图标与会话详情原型后，先由用户确认视觉方向，再做其余组件与原型：

1. **设计计划**：基于本规范写出令牌草案、字体、布局概念与 ASCII 线框，并逐条对照"禁用清单"自查；任何一处读起来像"对任何同类产品都会这么做"的默认值，就改掉并写明改了什么、为什么。
2. **令牌与基元**：在 Storybook 中实现令牌页（色板、字号、间距、圆角、阴影、动效）与全部基元组件，亮暗两套。
3. **领域组件**：实现"自研组件"表中的组件，每个状态一个故事。
4. **可交互原型**：用 MSW 模拟接口，在 Storybook 中拼出每个页面模板与关键页面（会话详情、智能体编辑、待处理动作），作为后续开发的验收基准。
5. **截图评审**：用 ego-browser 或 Playwright 在亮暗两种主题、1280 与 1920 两种宽度下截图，对照下面的评审表逐项检查，修正后再截一轮。最后做一次减法：每个页面去掉一样不必要的东西。

评审表：

| 维度 | 检查点 |
|---|---|
| 层级 | 一眼能看出页面主题、主操作、当前状态 |
| 对齐与节奏 | 左边缘对齐；间距只来自 4px 阶梯；没有孤立元素 |

## 前端工程

### 目录结构

```text
console/
├── src/
│   ├── app/                 应用入口、路由树、全局 Provider、错误边界
│   ├── features/<领域>/      按业务领域组织：sessions、agents、environments、knowledge ...
│   │   ├── api/             该领域的查询与变更 Hook（基于生成的客户端）
│   │   ├── components/      只在本领域使用的组件
│   │   ├── routes/          路由组件
│   │   └── index.ts         对外导出
│   ├── components/
│   │   ├── ui/              基元（shadcn 源码重塑）
│   │   └── domain/          跨领域复用的领域组件（上表）
│   ├── lib/                 api 客户端、SSE、格式化、权限、常量
│   ├── styles/              tokens.css、全局样式、字体
│   └── assets/icons/        自研 SVG
├── .storybook/
├── e2e/                     Playwright
└── mocks/                   MSW 处理器
```

### 边界规则

- `features/A` 不能引用 `features/B` 的内部文件，只能通过 `features/B/index.ts`；跨领域复用的东西移到 `components/domain` 或 `lib`。用 ESLint 的导入限制规则检查。
- 组件中不直接调用 `fetch`，统一走 `lib/api` 与各领域的 `api/` Hook。
- 颜色、间距、圆角、阴影、动效时长只能来自令牌。

### 代码规范

- TypeScript 严格模式，禁止 `any`；必要的类型断言要写注释说明理由。
- 组件用函数组件与 Hooks；一个文件一个导出组件；props 类型命名 `XxxProps`。
- 组件与 Hook 写中文 JSDoc，说明用途与关键 props。
- 文案直接写在组件中（只有中文一种语言），但同一术语的写法以本规范"文案"一节为准。

### 性能预算

- 首屏 JavaScript（gzip 后）不超过 300 KB；Monaco、ECharts、xyflow、xterm 一律按路由懒加载。
- 列表超过 200 行启用虚拟滚动。
- 时间轴在 1 万条事件时滚动流畅：Playwright 在固定的 1 万条事件数据上连续滚动 5 秒，帧时间 p95 不超过 16.7 ms，且没有超过 50 ms 的长任务。
- 字体按 `unicode-range` 切片加载，首屏只加载用到的字重。

### 测试

- 每个领域组件、每个复杂 Hook 都有 Vitest 测试。
- 每个页面的关键路径有 Playwright 用例。T21 用 `toHaveScreenshot` 为应用外壳与四种页面模板建立亮暗主题的截图基线，页面任务只允许内容区与基线不同。
- Playwright 默认连接脚本化模型服务（`ScriptedOpenAiServer`，见 T09b），结果确定；只有标注 `live` 的用例才调用真实模型。
- Storybook 的 a11y 检查不得有违规。

状态不只靠颜色：每种状态有自己的形状，形状来自测绘图上的标记。徽标、线程树、时间轴节点用同一套符号。

#### 字体与字号

- 字体栈：`"IBM Plex Sans", "IBM Plex Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；等宽 `"IBM Plex Mono", "IBM Plex Sans SC", ui-monospace, monospace`。西文字体在前，中文字形落到 Plex Sans SC，中西文笔画粗细一致。
- 字号阶梯只有七档，Tailwind 的默认字号全部移除（`--text-*: initial`），类名就是像素值：

| 类名 | 字号 / 行高 | 用途 |
|---|---|---|
| `text-12` | 12 / 16 | 时间刻度、表头、辅助数字 |
| `text-13` | 13 / 20 | 表格单元格、次要信息、按钮 |
| `text-14` | 14 / 21 | 正文 |
| `text-16` | 16 / 24 | 区块标题 |
| `text-18` | 18 / 24 | 面板标题 |
| `text-22` | 22 / 28 | 页面标题 |
| `text-28` | 28 / 36 | 少数需要更大标题的场合（空态的主句） |

- 字重只有 `font-normal`（400）、`font-medium`（500）、`font-semibold`（600），其余移除；字距（`tracking-*`）全部移除。
- 数字默认 `tabular-nums`（表格、时间、token、金额）；时间用 Plex Sans 的等宽数字，不用等宽字体。

#### 间距、圆角、阴影

- 间距：4、8、12、16、24、32、48（Tailwind 的 `1 2 3 4 6 8 12`），lint 拒绝其他档位的内外边距与间隙。宽度、高度不受这条约束。
- 圆角：`rounded-control` 4px（按钮、输入、徽标、标签）、`rounded-panel` 6px（面板、卡片）、`rounded-overlay` 8px（下拉、提示、对话框）。Tailwind 的默认圆角全部移除；`rounded-full` 只用于圆形符号，不用于按钮。
- 阴影只有一种：`shadow-overlay`，只给浮层。阴影色取墨色的色相（亮色 `oklch(0.25 0.02 166 / 0.12)` 与 `/ 0.06` 两层），暗色主题加深不透明度；不用中性灰的 `rgba(0,0,0,.1)`。

#### 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `--duration-fast` | 150ms | 悬停、按下、提示出现 |
| `--duration-base` | 200ms | 事件落位、面板展开 |
| `--duration-slow` | 250ms | 对话框、检查器收起 |
| `--ease-out` | `cubic-bezier(0.2, 0, 0, 1)` | 进入 |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 退出 |
| `--breath` | 2s | "此刻"标记的呼吸周期 |

`prefers-reduced-motion: reduce` 时位移、缩放一律取消，只保留不透明度过渡；呼吸改为静止。

时间轴的构成（全控制台唯一大胆的地方）：

- **子午线**：一条 1px 的竖线贯穿事件序列。每个事件在线上有一个节点，节点形状表示事件种类；线左侧有短刻度，像尺子的分划。
- **主刻度**：每轮开始处是一条横跨时间栏的长刻度，标出"第 N 轮"，一轮就是两条主刻度之间的一段。
- **间隔**：相邻事件相隔超过 1 分钟时，子午线断开并标出间隔时长，空闲时间一眼可见。
- **分叉**：子线程从父线的节点以圆弧分出，在右侧形成一条平行的细线，它的事件落在这条线上；子线程结束时以圆弧并回父线。并行的子智能体占用并排的线。
- **此刻**：会话运行中时，子午线末端以虚线延伸到黄铜色的菱形，旁边是"此刻"和距上一个事件的时长；菱形以 2 秒周期轻微呼吸。新事件落位时，菱形随之沿线下移。
- **节点符号**：调用方输入为空心方块，智能体消息为实心小圆，思考为空心小圆，工具调用为右向三角，工具结果以拐角线挂在调用下方并带结果状态符号，模型请求为短横（测量），压缩为断线符号，状态事件用"状态符号"表。

### 自查

逐条对照"禁用清单"：

| 条目 | 本设计 |
|---|---|
| 1 shadcn 默认主题 | 基元源码进仓库后全部改为本令牌：中性色是冷绿灰而不是 zinc，圆角分三级，阴影只有一种且只给浮层 |
| 2 紫、靛蓝到粉的渐变 | 没有任何渐变；lint 拒绝 `bg-linear-*`、`bg-radial*`、`bg-conic*`、`bg-gradient-*` 与 `*-gradient(` |
| 3 玻璃拟态、模糊、光晕 | 不用；lint 拒绝 `backdrop-blur*` 与 `backdrop-filter` |
| 4 SaaS 卡片套件 | 会话详情没有卡片：时间轴是一条线上的行，检查器是一个面板；层级靠背景层次与 1px 刻线 |

自查中改掉的默认值（读起来像"任何同类产品都会这么做"的地方）：

1. **状态徽标**：默认做法是浅色底的胶囊徽标（绿底"成功"、蓝底"运行中"）。改为"状态符号 + 文字"，不填底色；符号形状与时间轴节点是同一套，状态在色盲和灰度打印下仍可区分。
2. **主色**：起点 `#2456A3` 的方向对，但"蓝色主操作"本身是控制台的默认值。保留蓝色是因为海图的水域就是这种冷蓝，但把色相往青移到 252、彩度降到 0.125，让它和冷绿灰底同一温度，读起来像海图上的墨蓝，而不是 Tailwind `blue-600`（色相 263、彩度 0.215）那种电光蓝。
3. **时间轴**：默认的活动流是"左侧竖线 + 圆点 + 每个事件一张卡片 + 头像"。改为子午线加刻度：时间栏在线的左侧，轮次是主刻度，事件是线上的节点，没有卡片和头像；空闲间隔让子午线断开。
4. **时间戳**：默认用等宽字体，或在详情里也显示"3 分钟前"。改为 Plex Sans 的等宽数字、绝对时间 `10:02:14`，毫秒和时区放在检查器。
5. **元信息串**：默认写成 `qwen-plus · 1.6s · 3.2K tokens`。改为右侧对齐的度量列，每项自带中文单位（"1.6 秒"、"输入 3.2K"）。
6. **标签页**：shadcn 默认是灰底胶囊分段控件。改为与内容左边缘对齐的文字标签页，当前页是墨色文字加 2px 海图蓝下划线，整组下方一条刻线。
7. **焦点环**：默认是 3px 半透明光晕。改为 2px 实线海图蓝、偏移 2px，在亮暗两套底色上都清楚。
8. **暗色主题**：默认是 zinc-950 一类的中性近黑。改为夜间海图的蓝黑 `#121A1F`，面板 `#1A242B`，与亮色共享同一套色相关系。
9. **代码与 JSON**：默认在亮色页面上放一块深色代码卡片。改为 `surface-inset` 底、墨色等宽字，与页面同一明度层级。
10. **阴影**：默认 `rgba(0,0,0,.1)` 的灰阴影用在每张卡片上。改为只给浮层的一种双层阴影，颜色取墨色的色相。
