# CLAUDE.md 分层维护规范

Claude Code 的项目记忆分三层，各自加载时机不同。放对位置，智能体才能在需要的时候看到需要的信息，又不让上下文被无关内容挤满。依据 Claude Code 官方文档（code.claude.com/docs/en/memory），2026-11-07 核对。

## 三层结构

| 层 | 文件 | 加载时机 | 放什么 | 长度 |
|---|---|---|---|---|
| 根 | `CLAUDE.md` | 会话启动时 | 项目阶段、唯一事实来源、全局命令、整体架构、模块边界、最容易写错的约束 | 200 行以内 |
| 模块 | `<模块目录>/CLAUDE.md` | 读写该目录下的文件时按需加载 | 该模块的命令、包地图、不变量、易错点、对外接口 | 120 行以内 |
| 规则 | `.claude/rules/*.md`，frontmatter 中用 `paths` 限定路径 | 读写匹配路径的文件时按需加载 | 某类文件的编码规范精要（Java、SQL、前端、Python、文档） | 80 行以内 |

完整的规范在 `docs/engineering/`，三层文件只放精要，并链接到完整文档。

## 模块 CLAUDE.md

### 何时创建

模块第一次有实际代码的那个任务，在收尾时创建该模块的 `CLAUDE.md`。空模块不建。

### 模板

```markdown
# <模块名>

<一句话：这个模块负责什么，不负责什么。>

## 命令

- 编译与单测：`./mvnw -pl <模块> -am test`
- 单个测试：`./mvnw -pl <模块> -am test -Dtest=<类名> -Dsurefire.failIfNoSpecifiedTests=false`
- 集成测试：`./mvnw -pl <模块> -am verify`

## 包地图

只列读代码不容易看出来的部分，例如"session.app.TurnWorker 是执行一轮的唯一入口"。

## 不变量

必须一直成立的约束，每条注明对应的架构设计章节。

## 易错点

实际踩过的坑，每条一句话加正确做法。

## 对外接口

本模块实现或依赖的端口、HTTP 接口、事件。
```

### 何时更新

- 每个任务收尾时，更新它修改过的模块的 `CLAUDE.md`：命令变了、包结构变了、新增了不变量或易错点。
- 同一个错误第二次出现时，把它写进对应模块的"易错点"或对应的规则文件。
- 只写智能体从代码里读不出来、而且每次都需要知道的东西。能从代码直接看出来的、通用的开发常识，不写。

## 根 CLAUDE.md

- T01 完成后，把构建、测试、单个测试、格式化、架构检查的命令写入"命令"一节。之后命令有变化时同步更新。
- 新增模块、模块职责变化时更新"整体架构"与"模块边界"。
- 保持 200 行以内。内容变多时，把细节下沉到模块 `CLAUDE.md` 或规则文件。

## /init 的使用

- `/init` 分析整个仓库，在已有 `CLAUDE.md` 时只给改进建议，不覆盖文件。
- 适用时机：T01 完成后运行一次，参考它的建议补全根 `CLAUDE.md` 的命令一节；每个阶段评审（R1 至 R6）时运行一次，检查根文件是否过期。采纳建议前逐条核对，不照单全收。
- 模块 `CLAUDE.md` 按上面的模板手写，不用 `/init` 生成。
- 每个阶段评审时运行 `/doctor prompt-audit`，检查指令文件中过期、冲突或引用了不存在文件的内容。

## 确定性约束不靠 CLAUDE.md

CLAUDE.md 是上下文，不是强制配置。必须保证的事情用机制实现：

| 约束 | 机制 |
|---|---|
| 禁止推送、禁止破坏性 git 操作 | `.claude/settings.json` 的 `permissions.deny` |
| 模块依赖、禁用依赖、分层 | ArchUnit 与 maven-enforcer，CI 中运行 |
| 格式 | Spotless 与 Prettier，CI 中检查 |
| API 一致 | 契约测试与 openapi-diff |
