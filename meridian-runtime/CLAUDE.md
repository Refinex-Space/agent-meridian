# meridian-runtime

运行时应用（Spring WebFlux，schema `rt`）：公开 API（会话、事件、线程、待处理动作、模型直通）与 SSE、内部接口（Embedding、rerank、沙箱出网授权）、会话与线程、事件与 seq、轮次调度与租约、带租约的智能体状态存储、Worker 执行智能体与崩溃恢复、消息投递与中断、待处理动作与恢复轮、权限合成、收件箱、工具账本、`none` 档工作区存储、会话沙箱的生命周期、模型路由（限流、预算、计量）。不管理租户、凭据、模型目录（control-plane），不做知识库（knowledge）。

## 命令

- 编译与单测：`./mvnw -pl meridian-runtime -am test`
- 集成测试（Testcontainers：PostgreSQL、Redis、MinIO）：`./mvnw -pl meridian-runtime -am verify -Dtest=NONE -Dsurefire.failIfNoSpecifiedTests=false`；单个再加 `-Dit.test=<类名> -Dfailsafe.failIfNoSpecifiedTests=false`
- IDE 后台编译会把坏的 class 写进本模块的 `target/`（报 `Unresolved compilation problems` 或"无法访问 Interaction"），跑测试前先 `./mvnw -q clean -pl meridian-runtime`。
- 本地启动：`scripts/dev/up.sh`、`scripts/dev/run-control-plane.sh` 后运行 `scripts/dev/run-runtime.sh [--server.port=18080]`（`dev` profile，连 compose 的 PostgreSQL、Redis、MinIO，口令从 env 文件传入；API Key 经 `http://localhost:18081` 的 control-plane 校验，`MERIDIAN_CONTROL_PLANE_URL` 可改）。容器方式：Compose `app` profile（根 `CLAUDE.md`）。健康检查 `GET /actuator/health`，探针 `/actuator/health/liveness`、`/readiness`。
- profile：`dev` 连本地 compose；`test` 由测试的 `@DynamicPropertySource` 注入连接（含 `SpringContainerProperties.minio`，对象存储是必需配置），节点 ID 固定为 `test-node`。
- 迁移：`src/main/resources/db/migration/rt/`（`V0001` 核心表、`V0002` 状态的 `content_turn_id`、`V0003` 会话的 `deleted_at`、`V0004` 动作的结论与权限规则表、`V0005` 工作区的会话前缀索引、`V0006` 会话的快照键与计量起点、`sandbox_outputs`、`V0007` `sandbox_pod_ip` 的部分索引）；已合入的迁移不改，修正写新迁移。
- kind 集成测试（`*KindIT`，标签 `kind`；需要 Docker 与按根 `CLAUDE.md` 建好的 kind 集群）：`./mvnw -Pkind -pl meridian-runtime -am verify`（`config.SandboxSessionKindIT`；`config.EgressProxyKindIT` 是 P14，在 18080 端口启动 runtime 供集群中的出网代理回调、在 18081 端口启动代替 control-plane 的令牌签发方，宿主的这两个端口要空闲）。本地启动连 kind 沙箱：`--server.port=18080 --meridian.runtime.sandbox.enabled=true --meridian.runtime.sandbox.kube-context=kind-meridian`（出网代理按 `values-kind.yaml` 回调 `host.docker.internal:18080`），sandbox 档的开发环境是 `env_dev_sandbox`（白名单只有 kind 的 `allowed-echo`）。
- 公开 API 的接口从 `meridian-api` 的规范生成到 `target/generated-sources/openapi`（`runtime.openapi`），内部接口生成到 `runtime.openapi.internal`，改规范后先编译；契约测试：`-Dit.test='*ContractIT,SessionApiIT,EventStream*IT,ModelEndpointsIT'`。本地调用的 API Key 由 `scripts/dev/dev-api-key.sh` 经管理 API 签发并写入 `.env` 的 `MERIDIAN_DEV_API_KEY`（含 `models:invoke`，不限流）；`DevApiKeyResolver` 只在 `test` profile（A05）。控制台用户：`scripts/dev/console-token.sh` 的令牌加 `Meridian-Project`。调用 control-plane 的服务 JWT 用 `.env` 的 `MERIDIAN_RUNTIME_CLIENT_SECRET` 换取；内部接口的测试令牌由 `support.ApiTestKeys.knowledgeToken()`、`egressProxyToken()` 签发（`TestTokenIssuer`）。
- 不接真实模型跑会话：先 `scripts/dev/scripted-model.sh`，智能体配置引用 `mdl_dev_scripted`，用户消息以 `#script:<名称>` 选择脚本（`meridian-test-support/CLAUDE.md`）。
- 智能体配置的来源 `meridian.runtime.agent-config.source`（ADR-0047）：默认 `control-plane`（经内部接口读取已发布版本、环境修订、技能、租户设置与策略）；`file` 只允许 `dev`、`test` profile，读 `dev-config/agents/*.yaml`（`kind: agent_version | environment | tenant_settings`）与同级的 `dev-config/skills/<skill_id>/v<version>/`，策略读 `rt.permission_rules`（`meridian.runtime.dev-agent-config.directory` 可改）。`dev` 默认 `file`，`MERIDIAN_RUNTIME_AGENT_CONFIG_SOURCE=control-plane` 切换（`scripts/dev/agent-smoke.sh`）；`test` 默认 `file`。供应商目录与凭据按 `meridian.runtime.model-routing.catalog-source`（ADR-0045）：默认 `control-plane`；`file` 只允许 `dev`、`test` profile，读 `dev-config/providers/*.yaml`（`kind: provider_account`，内含 `models`，凭据只写环境变量名 `secret_ref`）。`dev` 默认 `file`（开发智能体引用 `mdl_dev_*`），`MERIDIAN_RUNTIME_CATALOG_SOURCE=control-plane` 切换后只有经管理 API 建的模型可用（`scripts/dev/catalog-smoke.sh`）。预算限额 `dev-config/budgets/*.yaml`（`kind: budget`，`scope_id: "*"` 必须加引号，不存在时不限），T16 起由 control-plane 下发。
- 智能体配置（T15b）：`config.AgentSpecSchemaTest`（Schema 与 `ResolvedAgentSpec` 一致）、`config.AgentConfigSessionIT`（新版本与新修订经通知立即生效、策略与记住此决定在 control-plane、MCP 工具与凭据、租户提示词与联网搜索后端、docx 技能；生产装配，`StubControlPlane`、进程内 MCP 服务）。
- 真实模型测试：`./mvnw -Plive -pl meridian-runtime -am verify`（只跑 `*LiveIT`：`ModelLiveIT` 约 8 次调用，`ModelEndpointsLiveIT` 3 次，`ControlPlaneCatalogLiveIT` 1 次，`AgentConfigLiveIT` 1 次（T15b-A01：配置与目录都来自 control-plane 替身的一轮会话）；需要 Docker 与 `DASHSCOPE_API_KEY`，模型取 `MERIDIAN_LIVE_CHAT_MODEL`、`MERIDIAN_LIVE_EMBEDDING_MODEL`、`MERIDIAN_LIVE_RERANK_MODEL`；没有密钥时跳过）。单个类加 `-Dit.test=<类名>`。

## 包地图

- `session.app.TurnWorker` 认领轮次，`TurnExecution.run()` 是执行一轮的唯一入口：`TurnPreparer`（读输入、恢复判定、写 `status_running`）→ `AgentEngine.runTurn` → 每个事件带租约写库 → 终态交给 `TurnFinisher`（结束轮次、计数、合并收件箱成下一轮、待处理动作、outbox、置回队列）→ `finally` 释放租约条目。`TurnWorkerLifecycle` 是后台循环与优雅下线（`SmartLifecycle`）。
- 恢复判定是纯逻辑：`session.domain.RecoveryPlanner.decide(RecoverySnapshot)`，单测 `RecoveryPlannerTest`；停止原因到轮次状态的映射在 `TurnEnding`。
- `dispatch.app`：`TurnEnqueuer`、`TurnClaimer`（`input(turn)` 读轮次输入）、`LeaseRenewer`、`LeaseReaper`、`TurnTransitions`、`DispatchWakeups`、`NodeLeaseRegistry`、`QueueDepthGauge`。后台任务在 `config.DispatchConfiguration` 中以 `PeriodicJob` 装配。
- `stream.app.SessionEventWriter`：事件写入的唯一入口，提交后 XADD 到 `ev:{session_id}`（`EventStreamPublisher`）；`DatabaseEventSink` 是 `EventSinkPort`；`ObjectStoreBlobStore` 是 `BlobStorePort`（键 `rt/{tenant}/{session}/blobs/…`）。`stream.infra.EngineJson`：事件、轮次输入、自定义工具与开发配置的 JSON 编解码。
- 子智能体（T13，ADR-0040）：`session.app.DatabaseThreadRegistry` 是 `ThreadRegistryPort`（同一事务先以父轮次租约写 `session.thread_created`、再插 `rt.threads` 行；状态更新经 `EventSinkPort` 写 `thread_status_*`，投影推进线程状态）；`DatabaseEventSink` 经 `ApprovalAudit` 写入，子线程的工具结果同样写 `permission.decided`；`config.EngineAutoConfiguration` 装配 `SubagentRunner`，上限 `meridian.runtime.worker.max-subagents-per-turn`（`WorkerProperties`，默认 8）；`SessionService.delete` 删除全部线程的 `agent_states`（`ThreadRepository.deleteAgentStates`）。
- `delivery.app.DatabaseInbox`：`InboxPort`（steer 带租约消费，同事务写 `session.message_consumed`）、`takePending`（合并成下一轮）、`redeliverSteer`。`tooling.app.DatabaseToolLedger`：`ToolLedgerPort`，结束记录时计数 `meridian.tool.calls`、为有副作用的调用在同一事务写审计 `tool.executed`（T10a）。
- `tooling`（T10b，ADR-0035）：SSRF 地址策略在 `common.net.AddressPolicy`（T15a 移入 common，供应商端点另有 `EndpointPolicy`）；`infra.GuardedWebFetcher` 是 `WebFetchPort`（Reactor Netty 加 `GuardedResolverGroup`：DNS 之后校验、不复用连接、不走代理、逐跳重定向、5 MB 截断；`WebContentConverter` 用 jsoup + flexmark 转 Markdown），被拒绝抛 `ForbiddenException`、其他失败抛英文的 `WebFetchException`；`app.TenantWebSearch` 是 `WebSearchPort`（按租户设置选 `app.WebSearchAdapter`：`infra.SearxngSearchAdapter`、`infra.BochaSearchAdapter`）；`app.UnconfiguredKnowledgeSearch` 是 T19 之前的 `KnowledgeSearchPort`。租户设置 `session.app.TenantSettings`（`AgentConfigProvider.tenantSettings`）。
- `sandbox`（T12a，ADR-0037）：`app.SandboxService`（`prepare` 在会话行锁内重新连接、从快照恢复或认领并落库、同步技能；`afterTurn` 镜像同步 `outputs/` 到 `rt/outputs/…` 并计量 vCPU 秒；`reclaim` 以 `SKIP LOCKED` 锁行、判定无活动轮次后快照、删除、提交，被取代的快照提交后删除；`deleteSessionSandbox` 给 T17a）、`app.DatabaseSandboxStates`（`SandboxStatePort`）、`app.IdleSandboxReaper`（`PeriodicJob`）、`app.SandboxProperties`（`meridian.runtime.sandbox`）、`app.ObjectStoreSnapshotStore`（T11）；`domain`（`SandboxRecord`、`SessionSandbox`、`SandboxMetering`、`SandboxUsageMessage`、`OutputSyncPlan`、`SandboxObjectKeys`）；`infra.SessionSandboxRepository`、`SandboxOutputRepository`、`infra.system.IdleSandboxRepository`。`session.app.TurnExecution` 在调用内核前 `prepare`（可重试失败时自己发 `error(retryable)` 加 `rescheduled`）、终态前 `afterTurn`；`config.SandboxConfiguration`（`enabled=true` 时 Kubernetes 客户端、驱动、`TurnSandboxes`、回收任务）。审计 `sandbox.command` 在 `DatabaseToolLedger.recordSandboxCommand`。

- SSE：`stream.app.SessionStreamHub` 是本节点读取 `ev:{session_id}` 的唯一入口（一个不阻塞 `XREAD` 轮询全部被订阅的会话）；`EventStreamService` 按五步算法处理每个连接，范围由 `stream.domain.StreamFilter` 决定（ADR-0030）。
- 身份（T14b，ADR-0044）：`application.yml` 的 `meridian.security.service-jwt.service=runtime`（入站 `aud`、出站客户端 ID）；内部接口按调用方限定：`egress:authorize` 只接受 `egress-proxy`，`embeddings`、`rerank` 只接受 `knowledge`。控制台用户的请求 `PlatformContext.userId` 有值、`apiKeyId` 为空：幂等键作用域与 `decided_by` 用 `PlatformContext.actor()`，预算不计 API Key 层级。
- control-plane 对接（T14a，ADR-0042）：`config.ControlPlaneConfiguration` 装配 `dispatch.app.TenantQuotaPort`（`dispatch.infra.ControlPlaneTenantQuotas`；没有 `meridian.security.service-client.control-plane-url` 时取 `default-tenant-max-running`）、`dispatch.app.TenantQuotaListener`（`config.invalidate` 的 `tenant_quota` → `TurnQueueRepository.updateTenantMaxRunning`）、`web.ApiKeyRevocationListener`（`key.revoked` → `ControlPlaneApiKeyResolver.evict`）。`TurnEnqueuer` 只在 `hasTenantCounter` 为假时读配额，且在入队事务之前。
- 结果类型都是 sealed：`EnqueueResult`、`ClaimResult`、`TransitionResult`、`AppendResult`、`TurnResult`、`RecoveryDecision`；租约条件不满足是结果，不是异常（端口按契约抛 `LeaseLostException`）。

## 不变量

- 时间一律取注入的 `Clock`，SQL 绑定 `:now`（ADR-0027）；数值来自 `DispatchProperties`、`WorkerProperties`。
- 带租约条件的写入先 `SELECT ... FROM rt.turns ... FOR SHARE` 锁住持有租约的轮次再写（「租约与 fencing」）。锁顺序：先 `rt.turns`，再 `rt.tenant_concurrency`，再 `rt.sessions`；同一事务里既入队又写事件时先入队。
- 失去租约（续租 `REVOKED`、写入被拒、内核抛 `LeaseLostException`）只取消订阅，禁止 `interrupt`；放弃的执行不写任何数据。
- 恢复认领按 `epoch > 1` 判断（下线续跑不加 `recovery_attempt`）；恢复方式按"本轮的内容写入"（`content_turn_id`）判定，不只比 `content_epoch`；`recovery_attempt` 达 2 时不再执行（ADR-0028 第 1、2 条）。
- 同节点重新认领：`LeaseHandle.release()` 之前本节点不再认领该线程；`TurnExecution` 在 `doFinally` 中释放。
- 续租每个租约一个 `REQUIRES_NEW` 事务、锁等待上限 2 秒（`LeaseRenewer.RENEW_LOCK_TIMEOUT`）：轮次行可能被等会话行锁的事务长时间锁住，不设上限时单线程的续租循环整体停住、本节点全部租约过期（ADR-0041）。父轮次被置回或取消时，`TurnTransitions` 在同一事务中把仍在运行的子线程写成 `thread_status_idle(interrupted)`。
- seq 只由 `SessionEventWriter` 在会话行锁内分配；状态事件在同一事务中推进会话与线程状态。XADD 失败不回滚，只记 `meridian.event.publish.failures`。
- Redis 命令在调用线程上按顺序发出，不在前一条命令完成的回调（Netty 事件循环）上发下一条（`Mono.zip`、`flatMapSequential`）。
- 模型必须属于调用方租户（`CatalogModel.usableBy`，D23），否则与不存在相同；文件目录的模型不带租户。结算时目录里找不到模型（调用期间被删除）照常记账，只是不带价格表。
- 模型路由的 Redis 用阻塞的 `StringRedisTemplate` 经 `Blocking` 执行，不在 Netty 事件循环上发命令；限流与预算的时间取注入的 `Clock`。预算计数以 token 计，键带租户哈希标签 `budget:{租户}:…`，令牌桶键 `ratelimit:{供应商账号}:{模型}`。
- 本模块的用例与仓储都是阻塞的：响应式代码一律经 `Blocking`；调度与端口实现的跨租户仓储继承 `SystemRepository` 并带 `@CrossTenant`，项目级仓储从 `PlatformContext` 取租户与项目。
- 指标（`session.app.TurnMetrics`、`EventStreamService`）用 Micrometer 点分隔名，导出到 Prometheus 时变成「可观测性」表中的名字。
- `/v1/` 下的请求都经 `ApiKeyWebFilter` 认证，Reactor Context 中有 `PlatformContext`；处理器先 `ApiKeyAuthorization.require` 再调用用例。`/internal/` 下的请求经 `ServiceCredentialWebFilter` 校验服务凭据，没有 `PlatformContext`，处理器先 `ServiceCredentialAuthorization.require` 再按请求体建立（ADR-0041）。会话不属于当前项目与不存在相同（404）：跨租户的仓储（事件、SSE）之前先经 `SessionService.get` 确认归属。
- 结束轮次、发送事件、归档、删除的事务都先取线程咨询锁（`ThreadLockRepository`），锁住之后再读会话状态；漏掉时消息会留在收件箱没有轮次处理（ADR-0028 第 8 条、ADR-0030）。先锁了行再要咨询锁的后台作业（超时扫描）只能 `tryLock`，否则与上面的事务死锁。
- 改动 `rt.sessions.sandbox_pod_ip` 的代码都要在同一事务里调 `EgressRevocations.podIpChanged`/`revoke`（旧 IP 与新 IP），否则同 IP 的新 Pod 会在 30 秒内沿用旧会话的出网授权。
- 会话沙箱的获取与回收在 `rt.sessions` 行锁内执行远程操作（单个操作的上限 `operation-timeout`）：两者靠这把锁串行，回收另要求会话没有 `queued`、`running`、`awaiting_action` 的轮次；不要把沙箱的状态转换挪到锁外。"记住此决定"对 `bash` 记命令原文（`RememberedRules`）。
- 子线程的工具调用与结果事件记在父轮次下：`TurnPreparer` 的恢复快照只取本线程（`thread_id` 等于轮次所在线程）的账本行与结果，子线程不会被恢复（ADR-0040）。
- 恢复轮（回应、超时、中断、无人值守自动拒绝）都经 `PendingActionResolver` 在线程咨询锁下入队：等待回应的轮次先结束为 `completed`，再入队，部分唯一索引才放得下。带中断请求入队的轮次，`TurnContext.interruptRequested` 为真，内核在第一次推理前停止。
- 流式对话补全先等第一个信号再提交响应（`switchOnFirst(…, false)` 加 `single()`；`next()` 会取消供应商的流）：首包之前的错误是 problem+json，之后是一条 `{"error"}` 块；流式块用 NON_NULL 序列化，`finish_reason` 例外（ADR-0033）。
- 与 control-plane 的对接：`config.StubControlPlane` 建在 `TestTokenIssuer` 上（真实的令牌端点与 JWKS，内部接口只认 runtime 的服务 JWT；`issue` 签发 Key、`quotas` 设配额、`grant` 设控制台用户的项目作用域、`revoke`；T15a 起 `model(CatalogStub)`、`secret(...)` 模拟模型目录与凭据解析；T15b 起 `publish(租户, 项目, 规格, 技能…)`、`environment(...)`、`tenantSettings(...)`、`policies(...)` 模拟配置分发，`rememberedRules` 记下记住的决定，签发过 Key 的项目的策略默认为空），测试经 Redis 发布 `key.revoked`、`config.invalidate`（`ControlPlaneIntegrationIT`、`ControlPlaneCatalogIT` 在断言里重复发布，等订阅生效）；控制台用户来自 Keycloak（`KeycloakRealm`，默认 `sub` 声明）。其他 API 测试用 `ApiTestKeys` 的开发期 Key（`test` profile，不限流）。
- 只测 API 的集成测试（`support.ApiTestBase`、`EventStreamRedisOutageIT`）设 `meridian.runtime.worker.enabled=false`：T10a 起生产装配齐全，不关就会有 Worker 认领并执行轮次。起了 Worker 的 Spring 测试结束时要 `stop()` 并 `GracefulShutdownManager.resetForTesting()`（`RuntimeApplicationIT` 的写法）。
- 每轮合成的权限都带平台安全规则，AgentScope 不再走"平凡权限上下文一律放行"的路径：`DEFAULT` 模式下没有命中 allow 的工具调用都要确认，测试智能体要显式放行它的工具（`WorkerFixture.LEDGER_TOOLS_ALLOWED`）；会话声明的自定义工具在会话层自动放行。

## 故障注入测试的写法

- 多节点：`config.WorkerFixture` 共享时钟、`ScriptedModel` 脚本（按调用顺序跨节点消费）、智能体配置（`TestAgents`）与记账工具；`fixture.node("node-a")` 组装完整节点（`WorkerNode`：`TestNode` + 收件箱、账本、对象存储、真实装配的内核、Worker）。引用 `meridian-engine-agentscope` 的测试放在 `config` 包。
- 卡住执行：`LedgerTool` 记账并在执行中途等闸门（`fixture.lookupCalls.close()`/`open()`、`awaitEntered()`）；放行要在 `finally` 中。
- 强杀：`execution.cancel(...)`（不收尾），时钟推进 31 秒，`WorkerFixture.reap(另一节点)` 重试回收直到成功（正在被写入的轮次行会被 `SKIP LOCKED` 跳过）。工具在接管之后再放行，它的结束记录写不进账本。
- 中断：经 `fixture.post(node, session, new UserEvent.Interrupt())` 发送（与 API 相同的 `EventIntake`），再调 `renewer().renewAll()` 模拟续租周期，或 `node.channelListener().start()` 走节点频道。下线：`node.lifecycle().start()`/`stop()`。动用下线的类在 `@AfterEach` 调 `GracefulShutdownManager.getInstance().resetForTesting()`（JVM 单例）。
- 起着的 runtime 跑真实装配的会话：`config.ScriptedModelSessionIT`（不声明 `ModelFactory`，生产的 `RoutedModelFactory` 调内嵌的 `ScriptedOpenAiServer`，临时目录写智能体与供应商配置，属性值用字符串）；模型接口经 HTTP：`modelrouting.api.ModelEndpointsIT`，流式块用 `ContractValidator.validateSchema`，内部接口用 `validateInternal`；契约：`config.ScriptedProviderContractIT`。

## 易错点

- 生成的 DTO 枚举在查询参数中按规范取值转换（`web.ApiEnumConverterFactory`），在 JSON 中由 `@JsonValue` 处理；生成的类名与领域类同名（`Session`、`SessionThread`），映射类里用全限定名区分。
- 公开 API 的集成测试继承 `support.ApiTestBase`（共用一个容器，不加 `@DirtiesContext`），经 `ApiTestClient`、`SseTestClient` 调用，每次交互都按规范校验；需要独占 Redis 的测试（`EventStreamRedisOutageIT`）自起容器。写事件模拟 Worker 用 `support.EventFeeder`（含"提交后不 XADD"）。
- `ON CONFLICT (thread_id) WHERE status IN (...)` 的条件必须与部分唯一索引一字不差，否则推断不到冲突目标。
- `text[]` 参数传 `String[]`（`JdbcValues.textArray`）；`Instant` 参数在 `SystemRepository` 中用 `JdbcValues.timestamptz`。jsonb 写入经 `JdbcValues.jsonb`，NUL 会被替换为 U+FFFD。
- jsonb 会规整键顺序与空白：断言 `data` 原文时按 jsonb 的输出写（`": "` 带空格），或解码后比较。
- 认领在 `REQUIRES_NEW` 事务中执行；入队、置回、结束、事件写入、收件箱、账本是 `REQUIRED`，可以组合进一个事务。
- 内核事件的写入与 AgentScope 的执行是并行的：工具开始执行时 Worker 可能还在写上一个事件，测试要等事件写完再接管。
- `java.net.URI` 对 `127.1`、`0x7f.1` 这类主机给不出 `getHost()`（端口也是 -1），校验要从 authority 取主机；IP 字面量不经过 HTTP 客户端的解析器，必须在发请求之前判定。
- macOS 上 Netty 的 `DnsServerAddressStreamProviders.platformDefault()` 要加载原生库，失败时打 ERROR；`GuardedWebFetcher` 在 macOS 上直接用 `DefaultDnsServerAddressStreamProvider`。
- 批次级 checkpoint 开启时，强杀发生在第一批工具之后会走 `RecoveryOnly`；要测"重放完整输入"，在第一批工具执行中途强杀，或关闭 checkpoint（`WorkerFixture.withoutCheckpoint()`）。
